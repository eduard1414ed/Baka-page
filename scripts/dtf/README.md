# Перенос статей с DTF

Чем собраны шесть постов сайта из статей на DTF — задача 17,
[разбор](../../статус/задача-17-перенос-с-dtf.md).

## Зачем это в репозитории

Скрипты писались как разовые и жили в папке сессии. По факту пригодились
трижды: заказчик попросил переставить картинки и подписать студии; сохранение
из открытой вкладки админки откатило работу, и её пришлось восстанавливать.
Инструмент, которым это делается, обязан пережить сессию — иначе следующая
правка перенесённого текста означает «собрать руками».

## Что тут лежит

| Файл | Что делает |
|---|---|
| `source.mjs` | скачивание статей с api.dtf.ru (кэш в `.tmp-dtf/`), разбор HTML в markdown, шапка поста |
| `captions.mjs` + `studios.json` | подпись «Название, студия X»; студии собраны один раз, в сеть не ходят |
| `titles-2023.mjs` | что изображено на кадрах зимней подборки 2023 — опознано глазами |
| `build-*.mjs` | пересборка постов из первоисточника |
| `verify.mjs` | сверка перенесённых постов с DTF |

## Как пользоваться

```
node scripts/dtf/verify.mjs              # сверить все перенесённые посты
node scripts/dtf/verify.mjs --selftest   # спросить проверки подлогами
node scripts/dtf/build-zima-2022.mjs     # пересобрать пост из первоисточника
```

**Перед пересборкой попросите заказчика закрыть админку.** Открытая вкладка
держит свою копию поста и при сохранении пишет её поверх целиком — так уже
были откачены три правки в зимнем обзоре.

**Сборщики берут шапку и служебные метки из живого файла**, а не сочиняют
заново: заголовок, поле «Тайтлы поста» и метки `::anime-ref` принадлежат
заказчику, и пересборка не имеет права их стирать.

## Чего тут нет

Оригиналов картинок с DTF: это чужие данные, и весят они мегабайты. В постах
стоят уже сжатые копии (webp, качество 85, вписать в 2048 — то же правило,
которым сжимает админка). Понадобится пережать — качайте с
`https://leonardo.osnova.io/<uuid>/` **без хвоста** `-/scale_crop/…`,
он отдаёт уменьшенную копию.
