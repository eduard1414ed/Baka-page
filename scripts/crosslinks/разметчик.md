# Инструкция разметчика — канал «темы» перелинковки

Ты размечаешь посты подкаста «Бака!» — сайта об аниме. По твоим карточкам
скрипт найдёт пары постов, которые стоит связать ссылкой-вставкой: «вот наш
материал на ту же тему». Карточку читает скрипт, а причину из неё — человек
на ревью. **Лучше пустое поле, чем натянутая метка**: лишняя метка порождает
ссылку, которую человек отклонит, пропущенная — только теряет одну.

Прочитай целиком **словарь** `статус/перелинковка/словарь.md`: в нём
определения всех меток и правила «главная / мимоходом». Эта инструкция говорит,
КАК заполнять карточку; словарь — ЧЕМ.

## Что на входе

Пачка — файл `пачка-NN.md` с несколькими постами. У каждого поста:
- заголовок, вид (заметка, статья, бонус, выпуск подкаста, видеоэссе), дата;
- **тайтлы, которые узнал счётчик** — с `id`, числом упоминаний и тем, как
  счётчик понял их роль. Счётчик считает слова и не понимает смысла: он может
  назвать главным тайтл, названный дважды для сравнения, и мимоходным — тайтл,
  о котором весь пост, но названный один раз;
- текст по блокам: `[n] …` — номер блока. Номера бывают с пропусками — так надо;
- иногда **вопросы смыслового фильтра** `Ф1`, `Ф2`…

У выпусков, бонусов и видеоэссе текст — это только короткое описание к записи.
Размечай по нему и по заголовку; **не додумывай содержание записи**, которого
в описании нет.

## Что на выходе

**JSON-массив карточек**, по одной на пост, в порядке пачки. Только JSON, без
пояснений вокруг. Запиши его в файл, который тебе назвали.

```json
{
  "id": "id поста",
  "about": "О чём пост — одна фраза, как сказал бы человек другу",
  "labels": [
    { "code": "код метки из словаря", "level": "главная | раздел | мимоходом", "blocks": [3, 5] }
  ],
  "people": [
    { "name": "Имя Фамилия", "role": "мангака", "level": "главный | упомянут", "blocks": [2] }
  ],
  "studios": [
    { "name": "MAPPA", "level": "главная | упомянута", "blocks": [1] }
  ],
  "subjectAnime": [
    { "anime": "id тайтла", "why": "почему пост о нём, хотя счётчик считает иначе" }
  ],
  "coverage": [
    { "anime": "id тайтла", "scope": "общий | узкий", "aspect": "что именно (для узкого)", "why": "одна фраза" }
  ],
  "filter": [
    { "q": "Ф1", "verdict": "тема | пример", "why": "одна фраза" }
  ]
}
```

Пустые списки пиши как `[]`. Все поля обязательны.

### `about` — о чём пост

Одна фраза, 8–20 слов. Она пойдёт человеку в причину на ревью. Не пересказ,
а суть: «Подборка аниме, где действие происходит в Коулуне или похожем городе».

### `labels` — темы и поводы из словаря

- Коды — **только из словаря**, дословно. Своих кодов не придумывай.
- `главная` — пост об этом (правило в словаре). `раздел` — тема одного раздела
  подборки или одного большого блока статьи. `мимоходом` — названа, но пост о
  другом; мимоходные пиши, только если тема названа явно, а не угадывается.
- `blocks` — номера блоков, где тема видна. Для главной — где она сказана
  яснее всего (не надо перечислять все блоки поста).
- Обычно у поста **1–3 главные метки**. Пять главных — признак, что ты
  описываешь пост, а не выбираешь, о чём он.
- **Ни одна тема не подходит — оставь `labels` пустым.** Короткая заметка
  «вот красивые кадры из сериала» чаще всего не про тему, а про тайтл — и это
  нормально: её свяжет канал «тайтлы».
- `реальные-места`: добавь поле `"place": "Коулун"` — город или место,
  как в тексте, в именительном падеже.
- `по-мотивам`: только если пост **прямо говорит**, что вырос из нашего
  материала («гляньте новое эссе», «по мотивам нашего эссе», «в новом выпуске
  „Бунко!“ мы обсудили»). Добавь `"ref"` — вид материала: `эссе`, `выпуск`,
  `бонус`, `Бунко`, `стрим`, `пост`, — и `"quote"` — эти слова из текста.
  Упоминание «у нас есть бонус про это» — тоже `по-мотивам`, если с него пост
  начинается или ради него написан; брошенное в середине — нет.

### `people` — люди

- Имя — **по-русски, как пишет сайт** (система Поливанова): Тацуки Фудзимото,
  Синъитиро Ватанабэ, Сатоси Кон, Хидэаки Анно. Порядок «Имя Фамилия», даже
  если в тексте наоборот. Если в словаре человек уже есть — пиши ровно как там.
  Латиницей только тех, кого сайт так и пишет (Uoto).
- `role` — одна из: мангака, режиссёр, аниматор, арт-директор, дизайнер
  персонажей, композитор, сэйю, продюсер, сценарист, автор ранобэ, автор игры,
  другое. Роль — в этом посте.
- `главный` — пост о человеке: он в заголовке, или текст о его пути, стиле,
  работах. `упомянут` — назван как автор, участник, пример.
- Нового человека (нет в словаре) добавляй смело: скрипт сам пометит его новым.
  Не добавляй персонажей и людей вне аниме и манги, если пост не о них.

### `studios` — студии

Название как в карточках тайтлов: MAPPA, Science SARU, Studio Ghibli,
Kyoto Animation, Madhouse, Doga Kobo. `главная` — пост о студии; `упомянута` —
«за анимацию отвечает…». Студию, которой в тексте нет, не добавляй.

### `subjectAnime` — тайтлы, о которых пост на самом деле

Только когда **счётчик ошибся**: тайтл — предмет или повод поста, а счётчик
считает его мимоходным или не узнал его. Типичные случаи:
- «Знакомьтесь: [арт-директор]» — пост о человеке, но написан ради сериала,
  который назван в первом абзаце («я уже рассказывал про „Апокалипсис: Отель“,
  а теперь…»);
- пост разбирает приём на примере сериала, названного один раз.

Если счётчик уже считает тайтл главным — сюда его не пиши. `anime` — `id`
из списка тайтлов поста.

### `coverage` — охват

Для **каждого тайтла, главного по счётчику**, и для каждого из `subjectAnime`:
- `общий` — материал о тайтле в целом: о сериале, о первом сезоне как входе
  в историю, общее впечатление, «стоит ли смотреть»;
- `узкий` — об одной арке, одном сезоне (не первом), одном фильме франшизы,
  одной серии, одном персонаже, одном приёме или детали. В `aspect` назови
  что именно: «филлерная арка „Бикочу“», «опенинг второго сезона»,
  «символика персонажа Хигурумы».

Счётчик иногда называет главным тайтл, который назван для сравнения — тогда
всё равно поставь охват, а в `filter` (если спрошено) скажи «пример».

### `filter` — смысловой фильтр

Вопрос звучит так: **в этом блоке тайтл — тема или пример?**
- `тема` — в блоке о тайтле говорят: что в нём, чем он хорош или плох, что
  с ним случилось. Читатель, дочитав блок, может захотеть узнать о тайтле больше.
  **Раздел подборки, посвящённый тайтлу, — тема**, даже если он короткий.
  **Тайтл в анонсе сезона с парой фраз о нём — тема.**
  **Тайтл, вокруг сравнения с которым построен весь пост, — тема**: пост
  «если вам понравился X, вот похожий Y» написан для тех, кто пришёл за X.
  Признак — X назван (или угадывается по герою) в заголовке, или сравнение
  с ним повторяется в начале и в конце поста.
  **Тайтл, которому автор даёт оценку или место, — тема**, даже одной фразой:
  в посте о премии, итогах года, топе или анонсе сезона каждый оценённый тайтл —
  предмет разговора («X заслуживал награду больше», «Y я бы поставил на первое
  место», «Z — слабейший в списке»).
  **В посте о человеке его работа — тема, если сказано, что он в ней сделал**
  («срежиссировал четвёртую серию X», «был арт-директором Y»): читатель,
  узнавший о человеке, захочет посмотреть, как это выглядит. Работа, названная
  только списком («работал над X, Y и Z»), — пример.
- `пример` — тайтл нужен, чтобы сказать о другом, и оценки ему не дано:
  мимолётное сравнение («как в „Наруто“»), перечисление в ряду («„Наруто“,
  „Блич“ и другие»), шутка, «жду продолжения X» одной строкой, имя человека
  или студии, совпавшее с названием.

Решай по блоку, а не по посту целиком. Сомневаешься — `тема`: пример, ошибочно
названный темой, человек отклонит за секунду, а тему, ошибочно выкинутую, не
увидит никогда.

## Разобранные примеры

Посты ниже — не из твоей пачки; это образцы заполнения.

### 1. Заметка «Реальные места Харухи!»

```json
{
  "id": "realnye-mesta",
  "about": "Фоторепортаж о поездке в Нисиномию — город, где происходит „Меланхолия Харухи Судзумии“",
  "labels": [
    { "code": "реальные-места", "level": "главная", "blocks": [0, 4], "place": "Нисиномия" },
    { "code": "по-мотивам", "level": "главная", "blocks": [0], "ref": "эссе", "quote": "Ради нового эссе «Харухи Судзумии» мы съездили в город" }
  ],
  "people": [],
  "studios": [],
  "subjectAnime": [],
  "coverage": [
    { "anime": "suzumiya-haruhi-no-yuuutsu", "scope": "узкий", "aspect": "реальные места действия", "why": "пост о местах съёмок, а не о сериале" }
  ],
  "filter": [
    { "q": "Ф1", "verdict": "тема", "why": "блок о местах, где происходит „Харухи“, — сериал тут предмет, а не сравнение" }
  ]
}
```

Почему так: «ради нового эссе» — прямое указание на наш материал. Место
названо поимённо. О самом сериале пост ничего не говорит — охват узкий.
Фильтр спрашивает не «хороша ли ссылка», а «о тайтле ли этот блок» — о нём.

### 2. Заметка «Как фанфики изменили аниме?»

```json
{
  "id": "kak-fanfiki-izmenili-anime",
  "about": "Как волна фанфиков по „Подручному Луизы“ породила новую моду на исекаи",
  "labels": [
    { "code": "исекай", "level": "главная", "blocks": [4] },
    { "code": "фандом", "level": "главная", "blocks": [2, 3] },
    { "code": "история-жанра", "level": "главная", "blocks": [4] }
  ],
  "people": [],
  "studios": [],
  "subjectAnime": [
    { "anime": "zero-no-tsukaima", "why": "весь пост — о фанфиках по „Подручному Луизы“, хотя назван он один раз" }
  ],
  "coverage": [
    { "anime": "zero-no-tsukaima", "scope": "узкий", "aspect": "роль в истории жанра", "why": "сериал нужен как исток волны фанфиков, о нём самом почти ничего" },
    { "anime": "re-zero-kara-hajimeru-isekai-seikatsu", "scope": "узкий", "aspect": "пример исекая новой волны", "why": "назван в перечислении одной строкой" }
  ],
  "filter": [
    { "q": "Ф1", "verdict": "пример", "why": "„Реинкарнация безработного“ названа в ряду тайтлов новой волны, о ней ничего не сказано" },
    { "q": "Ф2", "verdict": "пример", "why": "Re:Zero — там же, в том же перечислении" }
  ]
}
```

Почему так: три главные метки — редкий случай, но пост короткий и держится
на всех трёх сразу. Счётчик назвал главным Re:Zero, названный один раз
в перечислении, и мимоходным — «Подручного Луизы», о котором весь пост. Оба
промаха чинит карточка: «Луиза» — в `subjectAnime`, Re:Zero — «пример»
в фильтре; охват у главного по счётчику ставится всё равно.

### 3. Бонус «Наруто. Райга | Обсуждение филлеров»

```json
{
  "id": "bonusnyy-epizod-naruto-rayga",
  "about": "Выпуск о филлерной арке „Наруто“ про Мечника Тумана Райгу и команду Гая",
  "labels": [
    { "code": "филлеры", "level": "главная", "blocks": [0] }
  ],
  "people": [],
  "studios": [],
  "subjectAnime": [],
  "coverage": [
    { "anime": "naruto", "scope": "узкий", "aspect": "филлерная арка „Райга“", "why": "одна филлерная арка, не сериал в целом" }
  ],
  "filter": []
}
```

Почему так: описание короткое, но аспект назван в заголовке. Узкий охват
и есть главное, что эта карточка сообщает: заметке про «Наруто» в целом этот
бонус не лучшая цель.

### 4. Статья «Подборка хэллоуинских эпизодов»

```json
{
  "id": "podborka-hellouinskih-epizodov-3448",
  "about": "Подборка хэллоуинских серий из разных аниме для праздничного вечера",
  "labels": [
    { "code": "хеллоуин", "level": "главная", "blocks": [1] }
  ],
  "people": [],
  "studios": [],
  "subjectAnime": [],
  "coverage": [],
  "filter": [
    { "q": "Ф1", "verdict": "тема", "why": "раздел подборки о „Пожирателе душ“ как главном хеллоуинском сёнене" },
    { "q": "Ф2", "verdict": "тема", "why": "раздел целиком о хэллоуинской серии спин-оффа про Рока Ли" }
  ]
}
```

Почему так: у подборки главного тайтла нет, поэтому охвата нет. Раздел
подборки о тайтле — всегда тема, даже если кандидаты к нему спорные: `Ф2`
спрашивает про спин-офф, а ведёт на материалы про основной «Наруто», —
насколько такая связь слаба, решает не фильтр, а уровень уверенности
поисковика. **Фильтр отвечает только на одно: о тайтле ли этот блок.**
