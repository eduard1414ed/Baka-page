# Подготовка к реализации: семь пунктов

## 1. Что нужно для карты соответствий

Пришлите три вещи — этого хватит.

**Список файлов проекта.** Выполнить в папке проекта:

```
ls -R src | head -100
```

Нужны имена всего, что лежит в `src/components`, `src/layouts`, `src/pages`
и `src/styles`.

**Текущие токены.** Файл `src/styles/tokens.css` целиком — по нему станет
видно, какие переменные уже есть и что придётся переименовать.

**Один компонент карточки.** Файл `src/components/PostCard.astro` —
достаточно его одного, чтобы понять, какие поля приходят из контента
и какими именами они называются.

По этому я сведу таблицу «класс макета → компонент сайта → что меняется»
и приложу к ней порядок работ.

## 2. Тёмная тема

Решение записано в систему: **сайт светлый, тёмной темы нет.**

Что это значит на практике:

- в `tokens.css` заменяются значения, а не добавляется вторая палитра;
- `prefers-color-scheme` не поддерживается — если добавить его позже,
  придётся заново проверять контраст всех сочетаний, а их в системе
  тридцать с лишним;
- **до начала работы прогнать поиск по `src/` на символ `#`.** Любой цвет,
  заданный мимо переменной, при смене темы останется тёмным — и найдётся
  случайно, через месяц, на одной странице.

Команда для проверки:

```
grep -rn "#[0-9a-fA-F]\{3,6\}" src/ --include=*.astro --include=*.css | grep -v tokens.css
```

Пусто — можно менять палитру одним файлом. Не пусто — сначала вынести
найденное в переменные.

## 3. Шрифты

Скачать их я не могу — в моём окружении нет доступа в сеть. Но подготовил
файл `fonts.css` с готовым подключением и точный список того, что нужно
положить.

**Откуда взять:**

| Гарнитура | Где | Что качать |
|---|---|---|
| Literata | fonts.google.com/specimen/Literata | Переменный `.ttf`, начертания Regular и Italic |
| Inter | github.com/rsms/inter/releases | `Inter.var.woff2` из архива |
| IBM Plex Mono | fonts.google.com/specimen/IBM+Plex+Mono | Regular 400 и SemiBold 600 |

**Куда положить:** `public/fonts/` в корне проекта. Имена файлов должны
совпасть с теми, что в `fonts.css`:

```
public/fonts/Literata-Variable.woff2
public/fonts/Literata-Italic-Variable.woff2
public/fonts/Inter-Variable.woff2
public/fonts/IBMPlexMono-Regular.woff2
public/fonts/IBMPlexMono-SemiBold.woff2
```

**Обязательный шаг: конвертация в woff2.** Google отдаёт `.ttf`, они весят
втрое больше. Конвертировать проще всего онлайн-конвертером или утилитой
`woff2_compress`. Это не оптимизация ради оптимизации: `.ttf` переменной
Literata весит около 400 КБ, `.woff2` — около 130.

**Ещё лучше — вырезать лишние символы.** В шрифтах лежат греческий,
вьетнамский и прочие алфавиты, которых на сайте не будет никогда. Утилита
`pyftsubset` из пакета `fonttools` уменьшает файл ещё вдвое:

```
pyftsubset Literata.ttf --unicodes="U+0000-00FF,U+0400-045F,U+2116,U+2000-206F" \
  --flavor=woff2 --output-file=Literata-Variable.woff2
```

**Что удалить после:** строку `@import` с `fonts.googleapis.com` в начале
`baka.css` и подключить вместо неё `fonts.css`.

**Файлов в сборке прибавится пять** — при лимите Cloudflare в двадцать
тысяч это незаметно.

## 4. Кадрирование картинок для соцсетей

Соцсети показывают превью в пропорции **1200×630** (примерно 1.91:1).
Материалы на сайте хранятся в других пропорциях, поэтому кадрирование нужно
всегда.

| Что | Как кадрировать |
|---|---|
| Обложка выпуска 1:1 | Обрезка по центру до 1.91:1 срежет верх и низ — а там обычно название выпуска. **Не обрезать:** вписать квадрат целиком в поле 1200×630 на бумажном фоне, по центру |
| Кадр статьи или видео 16:9 | Обрезка по центру, потери минимальны |
| Постер аниме 2:3 | **Не обрезать.** Вписать по высоте на бумажный фон; справа остаётся место под название — его можно оставить пустым |
| Материал без обложки | Общая картинка сайта: логотип на бумажном фоне |

**Правило одно: обрезаем только то, что и так шире, чем нужно.** Всё
остальное вписывается на бумажный фон. Обрезка квадратной обложки до
широкой полосы срежет ровно ту часть, ради которой обложку рисовали.

Проверять готовые превью удобно ботом `@WebpageBot` в телеграме — он же
сбрасывает кэш, о котором мы уже спотыкались.

## 5. Фавикон

Сделан из логотипа. Комплект лежит в папке макетов:

```
favicon.ico          16, 32, 48 — вкладка браузера
icon-192.png         иконка на телефоне
icon-512.png         крупные размеры и манифест
apple-touch-icon.png 180 — экран «Домой» на iPhone
```

**Взята буква «Б».** Иероглифы из логотипа в размере 32 пикселя
превращаются в кашу — проверял, прикладываю оба варианта в переписке.
Буква же читается и на 16.

Цвета: чернильная буква на бумажном фоне, а не на прозрачном. Прозрачный
фон в тёмной теме браузера сделал бы букву невидимой.

Подключение уже прописано во всех макетах:

```html
<link rel="icon" href="/favicon.ico" sizes="any">
<link rel="apple-touch-icon" href="/apple-touch-icon.png">
<link rel="icon" type="image/png" sizes="192x192" href="/icon-192.png">
```

Файлы кладутся в `public/` в корень.

**На будущее:** хорошо бы получить логотип в векторе. Тогда фавикон можно
отдать как `.svg` — он останется чётким на любом экране, а весит меньше
всех растровых вместе взятых.

## 6. Skip-link

Это ссылка «Перейти к содержимому» — первый фокусируемый элемент страницы.
Обычно её не видно; она появляется, когда человек нажимает Tab.

**Зачем.** Тот, кто пользуется клавиатурой или экранным диктором, начинает
обход страницы с самого начала. Без такой ссылки он каждый раз проходит
логотип, четыре пункта навигации и поиск, прежде чем добраться до текста —
и так на каждой странице.

**Сделано.** Ссылка добавлена на все четырнадцать страниц, ведёт на якорь
`#main`. Стиль в общем CSS: чернильная плашка в левом верхнем углу,
появляется только в фокусе.

Проверить просто: открыть любую страницу и нажать Tab один раз.

## 7. Заголовки и описания

Сведены к одному формату на всех страницах.

**Формат заголовка:** `Название страницы — Бака!`

Исключение одно — главная: `Бака! — подкаст об аниме`. На ней бренд идёт
первым, потому что это единственная страница, где человек может не знать,
куда попал.

Было вразнобой: «Бака! — Главная», «Бака! — Макет статьи», «Наруто —
поиск — Бака!».

**Описание** добавлено на все страницы — раньше его не было нигде.
Требования: до 160 знаков, живым языком, без перечисления ключевых слов.
Оно показывается в выдаче поисковика и в превью ссылки, то есть это
единственный текст, который человек читает до перехода на сайт.

На страницах материалов описание берётся из подводки материала, на
служебных — написано вручную и лежит в макетах.

## 8. Что уже размечено в макетах и что перенести дословно

Этот раздел — для того, кто будет переносить дизайн на сайт. Всё
перечисленное в макетах уже сделано; нужно повторить в `Layout.astro`.

### 8.1. Шапка документа

На каждой странице макета в `<head>` лежит одинаковый набор. Он собирается
из данных страницы, руками не пишется.

```html
<title>{Название страницы} — Бака!</title>
<meta name="description" content="{до 160 знаков, живым языком}">

<link rel="icon" href="/favicon.ico" sizes="any">
<link rel="apple-touch-icon" href="/apple-touch-icon.png">
<link rel="icon" type="image/png" sizes="192x192" href="/icon-192.png">
<link rel="manifest" href="/site.webmanifest">

<link rel="canonical" href="https://bakapodcast.com{путь}">

<meta property="og:type" content="{article для материалов, website для остальных}">
<meta property="og:title" content="{тот же, что в title}">
<meta property="og:description" content="{то же описание}">
<meta property="og:url" content="https://bakapodcast.com{путь}">
<meta property="og:image" content="https://bakapodcast.com/og/{slug}.jpg">
<meta property="og:image:width" content="1200">
<meta property="og:image:height" content="630">
<meta property="og:site_name" content="Бака!">
<meta property="og:locale" content="ru_RU">
<meta name="twitter:card" content="summary_large_image">
```

**Заголовок главной — единственное исключение:** `Бака! — подкаст об аниме`,
бренд первым. Это единственная страница, куда можно попасть, не зная, что
это за сайт.

**`og:image` требует абсолютного адреса.** Относительный путь соцсети
не понимают — превью просто не покажется.

**Картинки превью генерируются при сборке** по правилам из раздела 4:
обрезаем только то, что и так шире 1200×630, остальное вписываем
на бумажный фон. Материал без обложки получает общую картинку сайта
`/og/default.jpg`.

### 8.2. Файлы в корень `public/`

```

apple-touch-icon.png
icon-192.png
icon-512.png
site.webmanifest
fonts/  (пять файлов, см. раздел 3)

character-404.png    иллюстрация для страницы 404
character-empty.png  иллюстрация для заглушки «изображения нет»
```

### 8.3. Первое, что нужно сделать со шрифтами

В `baka.css` первой строкой стоит `@import` с `fonts.googleapis.com` —
он остался от макетов, где иначе шрифты не показать.

**При переносе эта строка удаляется**, вместо неё подключается `fonts.css`.
Если этого не сделать, сайт продолжит ходить за шрифтами на чужой домен,
и вся работа по локальным файлам окажется бесполезной.

Проверить после переноса:

```
grep -rn "googleapis\|gstatic" src/ public/
```

Пусто — сделано правильно.

### 8.4. Проверки, которые стоит гонять после каждой сессии

```
# размеры меньше 11 не существуют
grep -ho "font-size:[0-9]*px" src/ -r | grep -oE "[0-9]+" | awk '$1<11'

# !important не используется
grep -rn "!important" src/ --include='*.astro' --include='*.css'

# auto-fit запрещён, только auto-fill
grep -rn "auto-fit" src/

# цвета мимо переменных
grep -rn "#[0-9a-fA-F]\{3,6\}\|rgba(\|hsl(" src/ --include='*.astro' --include='*.css' | grep -v tokens.css

# видимость и раскладка в одном селекторе (см. §2.1 системы)
grep -rn "display:\s*\(none\|block\)" src/ --include='*.astro' -A2 | grep -i "grid-template\|flex-direction"
```

Все пять должны давать пустой результат.
