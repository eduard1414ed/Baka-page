# Отчёт: разведка под тесты

Сессия «Тесты-1», 8 октября 2026. Код сайта не менялся. Правила по тестам —
в [ТЗ-тесты.md](ТЗ-тесты.md); здесь только то, как устроен сайт и где тесты
в него встанут.

---

## Коротко

**Легко:** интерактив (на сайте уже десяток скриптов без библиотек), поиск
Pagefind (одна пометка на странице), заслон при сборке (готовый образец),
кнопки «поделиться» (уже есть на «Моих девяти аниме»).

**Средне:** админка. Вложенные списки Sveltia умеет, но у нас они проверены
только на одном уровне. Выбора «из результатов этого же теста» у неё нет —
придётся писать id руками, а проверять их при сборке.

**Сложно:** превью-картинки с ТЕКСТОМ. Сейчас сборка умеет только уменьшать
готовую картинку и класть логотип на бумагу. Надписи шрифтами сайта она
не рисует вовсе — это новый механизм.

**Решить до сессии 2** (подробно в разделе «Противоречия с ТЗ»):
1. Отдельная коллекция «Тесты» или тест как ещё одна категория постов.
2. «Панели действий» у статьи нет — что под ней имелось в виду.
3. Значки ✓ и ✗ нарисовать картинкой, а не буквой шрифта.

## Материалы и ленты

### 1. Какие типы материалов есть

Все материалы — **одна коллекция `posts`** (`src/content/posts/*.md`),
схема — `src/content.config.ts`. Тип задаёт поле `category`, список категорий
закрыт и лежит в `src/data/categories.js`:

| id | На карточке | Особенность |
|---|---|---|
| `podcast` | Подкаст | своя шапка с квадратной обложкой и плеером |
| `videoessay` | Видеоэссе | |
| `note` | Заметка | |
| `article` | Статья | |
| `bonus` | Бонус | скрытая: своей вкладки нет, живёт в разделе «Подкаст» |

Есть ещё три коллекции, но это не материалы: `anime` (тайтлы, `.json`),
`transcripts` (расшифровки), `pages` (страницы «О проекте», «Поддержать»,
соглашение, полка «Главная»).

### 2. Адреса и где встанет `/tests/<slug>/`

- Материал: `/posts/<slug>/` (`src/pages/posts/[slug].astro`), slug = имя файла.
- Разделы: `/category/<id>/`, архив `/archive/`, тайтлы `/anime/<slug>/`,
  ещё `/mybest/`, `/search/`, `/about/`, `/support/`, `/legal/`.
- **Папки `tests` в `src/pages/` нет, адрес `/tests/` свободен**, ни с чем
  не конфликтует.

Но есть развилка — от неё зависит адрес (см. «Противоречия», пункт 1):
отдельная коллекция даёт `/tests/<slug>/`, тест-категория поста даёт
`/posts/<slug>/`.

### 3. Как ленты собирают материалы

Список материалов берётся вызовом `getCollection('posts')` — **таких мест 17**:
главная (`index.astro`), архив, разделы, страница тайтла, каталог, поиск,
RSS, карта сайта, `llms.txt`, превью для соцсетей (`og-sources.json.ts`),
сама страница материала и пять служебных списков для админки.

- Карточка — `src/components/PostCard.astro` (два вида: с обложкой и текстом).
- Метка типа — `src/components/PostKicker.astro`: `[ ЗАМЕТКА ] · 4 МИН ЧТЕНИЯ`.
  Подпись она берёт из `labelOne` категории. **Тест получил бы метку
  `[ ТЕСТ ]` автоматически, если он — категория поста.**
- Вкладки ленты — `CategoryTabs.astro`; раскладка главной — `src/lib/homeSlots.mjs`.

### 4. Макет страницы статьи

**Отдельного «макета статьи» нет.** Вся страница материала — один большой файл
`src/pages/posts/[slug].astro` (около 750 строк кода и стилей), он рисует пять
раскладок. Из чего он собран:

| Часть | Где |
|---|---|
| Оболочка сайта: шапка, подвал, теги для соцсетей, плеер внизу | `src/layouts/Layout.astro` — общий, подходит как есть |
| Заголовочный блок: «← Назад», дата, H1, подводка | `src/components/ContentHeader.astro` — отдельный, подходит как есть |
| Тело текста и его стили (колонка 700, отступы, медиа) | **внутри `[slug].astro`** |
| Врезки на наши материалы (`::material`) | плагин разметки, работает внутри текста |
| «Упоминается в материале» (марки тайтлов) | внутри `[slug].astro` + `AnimeBadge.astro` |
| «← Предыдущий / Следующий материал» | внутри `[slug].astro` |
| «Ещё немного нас» и «Поддержать» | `SocialStrip.astro`, `SupportStrip.astro` — отдельные |
| Панель действий (поделиться и т. п.) | **на странице статьи нет** |

**Подставить другое тело без копирования — частично.** Оболочка, заголовок
и хвостовые блоки — отдельные компоненты, их можно взять. Стили тела текста
и соседние материалы живут внутри `[slug].astro`, и сделать вторую страницу
«как статья» без копии не выйдет. Варианты:
- тест — категория поста, и страница теста — ещё одна ветка того же файла;
- либо вынести общую часть страницы в компонент (это правка живого кода,
  которой ТЗ не планирует).

## Админка

### 5. Как описаны коллекции

`public/admin/config.yml`. Самая сложная — **«Посты»**: 24 поля, свои кнопки
редактора, фильтры над списком, цветные кружки у черновиков. Пример
вложенности есть на странице «О проекте»: список «Команда», у каждого
человека шесть полей.

```yaml
- label: Команда
  name: hosts
  widget: list
  summary: '{{fields.name}}'
  fields:
    - { label: Имя, name: name, widget: string, required: false }
    - label: Фото
      name: photo
      widget: image
      required: false
    # …
```

Свои поля админки (выбор тайтлов, имена спикеров и т. п.) зарегистрированы
в `public/admin/index.html`.

### 6. Что умеет наша версия Sveltia

Версия — **0.193.2**, она прибита в `public/admin/index.html`.

| Нужно для тестов | Ответ |
|---|---|
| Вложенные списки (вопросы → варианты) | **Умеет**: встроенный `list` внутри `list`. У нас он проверен руками только на одном уровне («Команда», «Что даёт подписка»). Два уровня сразу ни разу не сохраняли. Проверять в сессии 2 черновиком теста. |
| Выбор значения из другого поля той же записи | **Не умеет.** Её «связь» (`relation`) выбирает другие ЗАПИСИ (посты, тайтлы), а не строки внутри этой же записи. Значит, id результатов пишутся в вариантах руками, а сборка проверяет, что такой результат есть. Опечатка не пройдёт, но поймает её сборка, а не админка. |
| Скрыть поля по условию | **Точно не знаю.** У Sveltia есть «объект с вариантами» (`types`): выбираешь «викторина» или «личностный» — и под ним только поля этого вида. Это заменило бы скрытие по условию. В проекте это не применялось, и в версии 0.193.2 я это не проверял. Проверка: скачать код админки этой версии и поискать там, или завести черновик в локальной админке. Если не умеет — ТЗ уже говорит, что делать: показывать оба набора с подсказками. |

**Правило проекта, которое касается тестов прямо:** свои компоненты внутри
админки дважды теряли данные. Поэтому только встроенные поля (`list`,
`object`, `string`, `image`), никакого своего «редактора теста».

## Сборка и превью

### 7. Превью-картинки для соцсетей

Генерируются при сборке: `src/plugins/og-images-integration.mjs`,
правила — `src/lib/ogImage.mjs`, «из чего делать» — `socialSource`
в `src/lib/postImage.mjs`, список задач — `src/pages/og-sources.json.ts`.
Инструмент — `sharp`.

Что он умеет сейчас:
- уменьшить обложку материала, **не меняя её формы** (квадрат остаётся
  квадратом — так решили 20 августа);
- общая картинка сайта 1200×630: логотип на бумаге.

**Чего не умеет: писать текст.** Для страниц результатов («название теста,
заголовок результата, картинка, логотип, шрифты сайта») нужен новый способ
рисования. Это самая трудная часть всей затеи, и её стоит заранее прикинуть
в сессии 5: возможно, понадобится новая библиотека, а шрифты сайта лежат
в формате, который `sharp` без подготовки не читает.

Ещё одна оговорка: превью 1200×630 из ТЗ расходится с принятым правилом
«превью повторяет форму обложки». Для результатов это оправдано, ведь
картинка рисуется заново, а не берётся готовая. Но это будет второе правило
рядом с первым, и записать его надо явно.

### 8. Проверки, которые останавливают сборку

Да, и есть готовый образец. `npm run build` начинается с
`scripts/check-post-refs.mjs` — проверки врезок на материалы. За сборкой
идут ещё полтора десятка проверок (`package.json`, строка `build`).

Как образец устроен, и это важно для тестов:
- **отдельный скрипт ПЕРЕД сборкой**, код возврата 1, понятное сообщение;
- **опубликованное роняет сборку, черновик — только предупреждает**: иначе
  неготовый тест в админке остановил бы выкладку всего сайта;
- у него есть `--selftest` с подложенными ошибками.

Ловить ошибки «изнутри» разметки нельзя — урок проекта: брошенная оттуда
ошибка сборку не останавливает, а стирает текст материала.

### 9. Поиск Pagefind

`scripts/build-search-index.mjs` после сборки обходит готовые страницы
в `dist/`. Он берёт **только то, что внутри элемента с пометкой
`data-pagefind-body`**. У статьи пометка стоит на `<article>`.

Чтобы тест попал в поиск:
- на странице теста поставить `data-pagefind-body` на основной блок,
  плюс метки `label`, `date`, `desc`, как у статьи (они рисуют результат
  в выдаче);
- на страницах результатов пометки **не ставить** — тогда они в поиск
  не попадут сами, это сходится с `noindex` из ТЗ;
- служебные подписи («Вопрос 1 из 12», кнопки) пометить `data-pagefind-ignore`.

## Интерактив

### 10. Скрипты в браузере

Есть, и много: плеер (`PlayerBar.astro`), расшифровка (`Transcript.astro`),
лента с вкладками (`PostFeed.astro`), поиск, каталог, «Наверх», марка
при наведении, «Мои девять аниме» — всего 17 файлов.

**Библиотек нет ни одной** (`package.json`: только Astro и служебное).
Скрипты — обычный JavaScript в теге `<script>` внутри компонента.
Для тестов так же: один `<script>` в компоненте теста, без новой библиотеки.

Две особенности сайта, о которых надо помнить:
- **переходы без перезагрузки** (`ClientRouter`): скрипт страницы обязан
  запускаться на событии `astro:page-load`, а не один раз при загрузке —
  иначе тест, открытый переходом с главной, не будет нажиматься;
- поделиться уже умеет `/mybest/`: `navigator.share` и копирование ссылки
  (`src/pages/mybest/index.astro`). Можно взять тот же приём.

1 px `--line`.

Важное правило §3.3, на котором стоит половина ТЗ тестов: **«активное
состояние никогда не обозначается только цветом»**. Отсюда ✓ и ✗ обязательны,
а не украшение.

## Противоречия с ТЗ и что решить

1. **Коллекция или категория.** ТЗ: «новая коллекция „Тесты“», адрес
   `/tests/<slug>/` и при этом «в лентах как остальные материалы, та же
   карточка, метка „Тест“». Ленты читают только коллекцию `posts`, мест 17.
   - *Отдельная коллекция:* чистый адрес `/tests/`, но учить показывать тесты
     надо главную, архив, разделы, RSS, карту сайта и поиск — каждое по
     отдельности, и забытое место будет молча без тестов.
   - *Категория `test` у поста* (файлы рядом с постами, в админке можно
     сделать отдельный пункт «Тесты» с отбором по категории): карточка,
     метка `[ ТЕСТ ]`, лента, RSS, карта сайта и поиск работают сами.
     Адрес тогда `/posts/<slug>/`, и надо решить, нужна ли вкладка «Тесты»
     в ленте и раздел `/category/test/` (или тест — скрытая категория, как бонус).

   **Моя рекомендация — категория.** Решать вам в начале сессии 2.
2. **«Панель действий»** в ТЗ (§2) стоит в составе макета статьи, но у статьи
   её нет. Если имелись в виду кнопки «поделиться» — их пока нет нигде,
   кроме `/mybest/`.
3. **✓ и ✗ нельзя набирать буквой.** Шрифты сайта урезаны по списку знаков
   (`fonts.css`), этих двух знаков там нет. Браузер возьмёт их из системного
   шрифта, а на айфоне это может оказаться цветной эмодзи — урок проекта
   про ↗ ровно об этом. Рисовать значки картинкой (SVG) прямо в разметке.
4. **«Превью 1200×630»** для результатов расходится с правилом «превью
   повторяет форму обложки». Для результатов оправдано, но записать надо.
5. **«Скругления — только существующие»** из задания сессии: существующих
   нет, значит углы у вариантов ответа прямые.

## Сколько файлов добавят тесты

На один тест: 1 страница теста + по одной странице на результат + по одной
превью-картинке на результат. Тест с пятью результатами — около 11 файлов.
При лимите 20 000 это немного, но сегодняшнее число файлов в сборке
стоит замерить перед сессией 5.
