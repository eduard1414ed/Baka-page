# TASK-markup.md — разметка, заголовки и подписи

Работаем в репозитории сайта, в отдельной ветке. Задача меняет то, что видят
поисковики, поэтому не в мастере.

## Общие правила

1. **Меняй только то, что перечислено ниже.** Никаких попутных рефакторингов.
2. Меняется только разметка и метаданные. **Видимый текст страниц не трогаем:**
   ни синопсисы, ни порядок блоков, ни вёрстку.
3. Останавливайся на отметках **СТОП**.
4. После каждой части — прогони сборку и проверь хотя бы одну страницу
   валидатором разметки (`https://validator.schema.org/`), прежде чем идти дальше.

## Что уже сделано и что ломать нельзя

- Полные расшифровки лежат прямо в HTML страниц выпусков (144 штуки).
  **Они должны там и остаться** — не выносить в отдельный файл, не прятать за скрипт.
- Таймкоды работают как ссылки вида `/posts/ep-28/#anime=spirited-away&t=1144`.
  Не трогать.
- `robots.txt` и `llms.txt` в порядке, менять не нужно.
- Правило индексации страниц тайтлов (`noindex, follow` при score < 3) уже работает.
  Ничего в нём не меняем.

# ЧАСТЬ 1. Разметка страниц выпусков

Сейчас на странице выпуска стоит только `Article` + `BreadcrumbList`.
При этом на странице есть аудио, встроенные ролики YouTube и полная расшифровка —
для поисковика всего этого не существует.

## 1.1 — PodcastEpisode

Добавить к существующей разметке (не заменять `Article`, а дополнить):

```json
{
  "@context": "https://schema.org",
  "@type": "PodcastEpisode",
  "@id": "<url страницы>#episode",
  "url": "<url страницы>",
  "name": "<заголовок выпуска>",
  "description": "<описание выпуска>",
  "datePublished": "<дата публикации>",
  "dateModified": "<дата последнего изменения файла>",
  "episodeNumber": "<номер выпуска, если есть>",
  "timeRequired": "<длительность в формате ISO 8601, например PT43M07S>",
  "associatedMedia": {
    "@type": "AudioObject",
    "contentUrl": "<прямая ссылка на аудиофайл>",
    "encodingFormat": "audio/mpeg"
  },
  "partOfSeries": {
    "@type": "PodcastSeries",
    "name": "Бака!",
    "url": "https://ru.bakapodcast.com/"
  },
  "transcript": "<полный текст расшифровки>"
}
```

**Про `transcript`.** Это главное в задаче. Расшифровки — единственный по-настоящему
уникальный актив сайта, и сейчас они лежат как обычный текст без всякого обозначения.
Поле `transcript` прямо сообщает поисковику и языковым моделям, что это запись
разговора, а не статья.

Если полный текст в JSON-LD раздувает страницу неприемлемо (проверь на самом длинном
выпуске — сравни вес до и после) — **скажи мне,** обсудим варианты. Не решай сам
и не обрезай текст молча.

## 1.2 — VideoObject

Для каждого встроенного ролика YouTube на странице — отдельный `VideoObject`
с `name`, `description`, `thumbnailUrl`, `uploadDate`, `embedUrl`.

Если каких-то данных в источнике нет — не выдумывай, оставь поле пустым
и скажи мне, чего не хватает.

## 1.3 — dateModified

Сейчас `dateModified` нет нигде, есть только `datePublished`. Добавить во всю разметку
(`Article`, `PodcastEpisode`, и дальше на страницах тайтлов).

Брать из фронтматтера, если поле есть; иначе — из даты изменения файла в гите.

# ЧАСТЬ 2. Страницы тайтлов

## 2.1 — Разметка сущности

Сейчас там **только `BreadcrumbList`**. Страница «Унесённых призраками» никак
не сообщает, что она про фильм.

Добавить `Movie` или `TVSeries` (по типу тайтла, если он есть в данных;
если типа нет — используй `CreativeWork` и скажи мне об этом) с полями `name`,
`alternateName` (оригинальное название), `datePublished` (год), `image`,
`sameAs` (ссылка на Shikimori).

Плюс `ItemList` для блока «упоминания» — это список материалов, где тайтл обсуждался,
и он и есть уникальное содержание страницы.

## 2.2 — Заголовок

Сейчас: `Унесённые призраками — Бака!` — 28 символов при доступных ~60.
В выдаче помещается больше, и заголовок влияет на то, по каким запросам страница
вообще показывается.

Новый шаблон:

```
{название} ({год}) — разбор в {N} материалах «Баки!»
```

Где `N` — число собственных упоминаний. Правила:

- если `N == 0` — оставить старый шаблон, врать нельзя
- если `N == 1` — «разбор в выпуске «Баки!»» без числа
- если года нет — опустить скобки
- если итог длиннее 60 символов — обрезать хвост, а не название

## 2.3 — Описание

Сейчас в `description` кусок синопсиса с Shikimori, обрезанный многоточием.
То есть в выдаче страница представлена чужим текстом, одинаковым с десятками сайтов.

Новый шаблон — из собственных данных:

```
Обсуждали в выпусках {перечисление 2–3 названий}. {N} материалов, {M} упоминаний в разговорах.
```

Держись в пределах 150–160 символов. Если своих материалов нет вообще —
оставь синопсис, это лучше пустоты.

**Видимый синопсис на странице не трогать.** Меняется только мета-тег.

# ЧАСТЬ 3. Автор и подписи

## 3.1 — Person вместо Organization

Сейчас в `author` и `publisher` указано `Organization: Бака!`.
Живой автор с именем — более сильный сигнал, чем безымянная организация.

Оставить `publisher` организацией, а `author` заменить на `Person` с именем,
описанием и `sameAs` — ссылками на профили и на книгу.

Данные для этого блока **спроси у меня**, не бери со страницы «О проекте» наугад.

## 3.2 — Подписи к картинкам

На странице тайтла 12 картинок из 13 с `alt=""`, на странице выпуска 4 из 5.
Пустой `alt` означает «декоративная картинка, не читай» — для логотипа это верно,
для обложек тайтлов и превью материалов нет.

Проставить осмысленные `alt`:

- обложка тайтла → `Постер «{название}»`
- превью материала в карточке → заголовок материала
- логотип, иконки, разделители → оставить `alt=""`, так правильно

Шаблонные подстановки, никакой генерации текста.

## Чего не делать

- Не менять видимый текст, синопсисы, порядок блоков и вёрстку
- Не выносить расшифровки из HTML
- Не трогать таймкоды и ссылки на них
- Не менять `robots.txt`, `llms.txt`, `canonical`
- Не трогать правило индексации
- Не выдумывать данные для разметки — пустое поле лучше выдуманного
- Не обрезать расшифровку в `transcript` без согласования
