# Задача 38. Перелинковка, сессия 3: вставка одобренного

25 сентября 2026. Первая сессия проекта «Перелинковка», которая меняет
опубликованные посты — в рамках исключения из CLAUDE.md (только новые блоки
`::material{…}` в одобренных местах). Полный отчёт с разбором —
`~/baka-audit/crosslinks/09-отчёт-сессии-3.md` (вне репозитория).

## Что вписано

Пилот: пачка 1, **22 вставки в 15 постах**, коммит `939ccef8` (номер в журнале —
`7fff8969`), скрипты — `471afb42`. Журнал — `статус/перелинковка/вставлено.json`.
Пропусков 0. Проверка диффа зелёная 15 из 15: +84 строки, −0. Сборка прошла,
заслон врезок: 93 = 71 прежних + 22. Эд проверил посты локально глазами:
всё на месте.

## Как устроено

- `scripts/crosslinks/apply.mjs` (`npm run crosslinks:apply`). Вход —
  `решения.json → approved`. Отбор `--batch` / `--posts` / `--keys`, без отбора
  не делает ничего; без `--write` — сухой прогон. Пропуск с причиной: цели нет
  или она не опубликована, «играет здесь» цели не по силам, вставка на цель уже
  стоит, место потеряно (отпечаток файла разошёлся и абзац по первым словам
  не нашёлся — такой пост идёт в список «пересмотреть на странице»). Несколько
  вставок в посте — с конца к началу, после каждой текст разбирается заново
  и проверяется, что все вставки стоят после своих абзацев.
- Вид строки — как у 71 вставки Эда (замер): `::material{id="…" label="…" mode="play"}`
  в этом порядке; перед блоком две пустые строки, после — прежние, но не меньше
  двух. Вставка идёт сразу за последним знаком блока, остальной файл не трогается.
- `scripts/crosslinks/verify-diff.mjs` — побайтная сверка «до/после» (строки
  режутся по байту `\n`, читаются как latin1): вынимаются новые строки блока
  с пустыми вокруг, промежуток на их месте можно только расширить, всё прочее
  обязано совпасть. Блок в шапке или вплотную к тексту — красный. Вставлялка
  зовёт её сама и при красном свете возвращает файл.
  Без аргументов сверяет изменённые посты рабочей копии с HEAD.
- `scripts/crosslinks/verify-diff.test.mjs` — на копии папки постов: настоящая
  вставлялка зелёная по всем 15; семь подлогов красные (буква в тексте, удалённая
  пустая строка, фронтматтер, лишняя пустая строка, блок вплотную к абзацу,
  потерянный перевод строки в конце, `\r\n`); порча во время записи — все
  копии возвращены побайтно. **Первый прогон поймал дыру самой проверки:**
  блок, прилепленный к абзацу без пустой строки, проходил зелёным — теперь нет.

## Поиск (find.mjs, pipeline.mjs)

- **Правило места.** Ревью пачки 1: «по мотивам», сдвинутое механически
  за 2-й абзац, Эд не оставил ни разу (0 из 4) — переносил к фразе о выпуске
  или в конец; конец принимал 10 из 10. Теперь такое место — конец текста
  (перед карточками тайтлов). Сдвинуло 14 основных в непройденных постах.
  Решение Эда: «Ок, я если что руками подвину».
- **Закрытые посты** (решение Эда 2). Пройден — если по всем основным
  предыдущего прогона есть «одобрено» или «отклонено» (отложенное — не решение).
  Список `closed` в candidates.json переносится из прогона в прогон. Новый
  основной у закрытого поста — статус `добор`, посмотреть в конце проекта.
- **Одобренное = уже стоящее** (решение Эда 3): одобренные, но не вписанные
  пары занимают места (плотность, «не ближе абзаца») и входят в потолок на цель.
- Страница ревью показывает закрытые посты и после вписывания («одобрено ·
  вписано»). `review-stats.mjs` сверяет копию подписи по умолчанию с
  `src/plugins/remark-post-ref.mjs` (решение Эда 4, код сайта не трогаем).

## Откат пачки

```
git revert --no-edit <коммит-журнала> <коммит-пачки>
```
Для пилота: `git revert --no-edit 7fff8969 939ccef8`. Проверено на пробной
ветке: посты вернулись к состоянию до пачки побайтно. Откат ОДНОГО коммита
пачки упирается в конфликт в `вставлено.json` — его поменял журнальный коммит.

## Решения Эда

- Правка правила места — принята.
- Повтор «обычная ссылка в абзаце + вставка на ту же цель» в «А вот и лето»
  (№133 и №8, свои цели Эда) — вставки оставить, ссылки снять на шаге 5
  первыми: `статус/перелинковка/шаг-5-первыми.json`.

## Чего НЕ проверено

- Живой сайт после выкладки — проверяет Эд (выкладывает сам).
- «Место потеряно» и «пост изменился» на настоящем изменившемся посте —
  не встречались, только на подставных данных в сессии 2.

## Сессия 3б: снятие ссылок-дублей (25.09.2026)

Решение Эда: обычная ссылка на ту же цель в абзаце, после которого стоит
одобренная вставка, снимается. Исключение в CLAUDE.md расширено (пункт 2),
утверждено Эдом дважды: основная формулировка (`b3810ae7`) и YouTube-ролик
цели (`5901f154`). Полный отчёт — `~/baka-audit/crosslinks/10-отчёт-сессии-3б.md`.

**Вписано:** вся пачка 1 — 94 вставки в 71 посте и 11 снятий (4 у пилота,
одно на ролик №74 на YouTube), один коммит `966e913a`. Проверка диффа
зелёная 73/73, сборка прошла, врезок 188. Скрипты и решения — `a1caa5e3`.

**Как устроено:**
- `scripts/crosslinks/unlink.mjs` — единственный дом правила: какие адреса
  — «та же цель» (сайт в любом написании, `t.me/podcastbaka/N` по `tgId`,
  YouTube-ролик, встроенный в пост цели `::video`), склейка ссылки,
  нарезанной на куски подряд, вид дубля (`words` / `rephrase` / `manual`),
  список слов-указателей, «было → станет» и подбор куска для своего варианта
  (наименьший кусок, отличающийся от предложения и накрывающий ссылку,
  в пределах предложения). Зовут его lib, страница, сервер, вставлялка, проверка.
- Страница ревью: блок дубля под плашкой, галочка (по умолчанию — снять,
  если слова связные), свой вариант с предпросмотром (`/api/unlink-preview`),
  список «Дубли у вписанного». Решение — поле `unlink` у записи в
  `решения.json`, «было/стало» дописывает сервер. Сервер печатает строку
  на каждое решение. Клавиша U/Г — только вторым нажатием за 2 секунды.
- `apply.mjs`: снятие после всех вставок; абзац-якорь — текст прямо перед
  `::material` на цель (через картинки), первые слова сверяются с решением,
  кусок должен найтись в абзаце ровно один раз. Снятие у вставки, вписанной
  раньше, идёт без вставки. Журнал — поле `unlinks` у записи вставки.
  `--commit` убран: номер коммита больше не пишется.
- `verify-diff.mjs`: изменённая строка законна, только если получается
  заменами из журнала (каждая «было» ровно однажды, больше ни байта); в «было»
  есть ссылка на цель, в «стало» нет, за абзацем стоит вставка на цель.
  В командной строке новые снятия — разница журнала с `--against`.
- `verify-diff.test.mjs` идёт на временной копии репозитория (git worktree)
  на коммите 4ff56f1e с сегодняшними скриптами поверх: от записанного в посты
  не зависит. Все подлоги красные, каждый по своему правилу.
- `finder.mjs`: пара со ссылкой в абзаце места — обычный кандидат (пометка
  `linkHere`), а не «шаг 5». Пересчёт: основных 404 → 388 (−20 вписанные
  пилотные, +17 бывшие «шаг 5», −14 вытеснены ими в запасные, +1).

**Решения Эда:** отложенное пост не закрывает (без изменений); пачка — один
коммит, откат `git revert --no-edit <коммит-пачки>` — проверено на 966e913a
во временной копии, посты и журнал вернулись побайтно; пары «шаг 5» — на
ревью; YouTube-ролик цели — та же цель; «Слова пузырятся» в «А вот и лето»
(ссылка на текстовый обзор, вставка на бонусный выпуск — разные материалы)
не трогать.

**Потеря решения.** Запись «Какие исекаи посмотреть → №74» дважды пропала
из `решения.json`: Эд набирал «готово» при активном окне страницы, «г» = U =
«вернуть не решено». Второй раз это видно в новом журнале сервера
(`14:21:53 approved · ссылка: words`, `14:21:56 УБРАНО`). Восстановлено
по журналу вставок и журналу сервера при остановленной странице, у записи
поле `restored`.

**Чего НЕ проверено:** живой сайт после выкладки (Эд); свой вариант в
настоящем посте (только на копиях и через сервер); `server.test.mjs` сессии 2
краснеет на двух проверках — опирается на «Список пяти», у которого после
пилота нет основных (так же и на `main` до 3б), не чинился.
