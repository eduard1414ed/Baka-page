# Тесты-2: схема и админка

8 октября 2026. Правила тестов — [ТЗ-тесты](../тз/ТЗ-тесты.md), устройство
сайта под них — [отчёт разведки](../тз/ОТЧЁТ-тесты-разведка.md) (сессия 1).
Здесь — как сделана сессия 2, что решено, что проверено и чем, и что надо
знать сессии 3.

**Итог:** в админке есть пункт «Тесты» (викторина и личностный), сборка
проверяет тесты и останавливается на ошибке опубликованного, два проверочных
черновика сохранены через админку без потерь и на сайте не видны. Страницы
теста нет — это сессия 3.

## Решения заказчика за сессию

| Решение | Почему так | Цена |
|---|---|---|
| Тест — пост категории `test`, адрес `/posts/<slug>/` | ленты, RSS, карта сайта, поиск работают сами | адрес не `/tests/` |
| Категория скрытая, как `bonus`, **без `feedWith`** | метку на карточке пишет РАЗДЕЛ (`sectionOf`): приписанный к «Статьям» тест вышел бы `[ СТАТЬЯ ]` | ссылка «← назад» на странице теста ведёт в несуществующую `/category/test/` — решать в сессии 3 |
| **Хранение — вариант A**: та же папка `src/content/posts/` | ничего в коде сайта не меняется; B требовал своего правила адресов для всех постов и доработки 4 мест, знающих папку по имени | роботы, обходящие папку постов, видят тесты |
| Вид теста — «объект с вариантами» (`types`), **способ 1** | видны только поля выбранного вида | сменить вид можно только удалив блок вместе с вопросами |
| **Поля id у результата нет** | вписывать его руками не хотелось, а собрать из заголовка в админке нельзя (ниже) | адрес результата = заголовок (`src/lib/slug.mjs`); переименовали — адрес сменился, старые ссылки не открываются |
| «Баллы» — **выпадающий список** из результатов этого теста | не набирать заголовки руками | список берётся из СОХРАНЁННОЙ версии: сначала результаты → сохранить → вопросы |
| Результаты стоят **первыми**, вне выбора вида | без этого выпадающий список пуст (ниже) | «От» и «До» видны и у личностного, с пометкой |
| Кнопка «Робот» в админке — в правый нижний угол | закрывала подсказки полей | — |

## Как тест лежит в файле

Всё про тест — под одним ключом `test` (у постов такого поля нет — защита
от формы «Постов», ниже). Вступление — тело поста.

```yaml
title: '[Проверка] Кто вы из отряда Фрирен?'
description: …            # подзаголовок
date: 2026-10-08
category: test
draft: true
cover: ''
test:
  results:                 # первыми; адрес результата — из title
    - title: Фрирен
      image: ''
      text: …              # markdown
      from: null           # только викторина: диапазон верных, включительно
      to: null
      posts: []            # имена файлов постов
      anime: []            # адреса тайтлов
  kind:
    type: personality      # или quiz
    questions:
      - text: Что возьмёте в долгий поход?
        images: []         # [{ src, alt }], до 4
        options:
          - text: Гримуар с бесполезными заклинаниями
            scores: [Фрирен]   # только личностный: ЗАГОЛОВКИ результатов
            reply: …           # только личностный
          # у викторины вместо scores/reply: correct: true|false
        explanation: …     # только викторина, markdown
anime: []                  # дописывает обработчик сохранения админки
```

Полные образцы — `src/content/posts/proverka-viktorina-naskolko-vy-znaete-friren.md`
и `proverka-kto-vy-iz-otryada-friren.md`, оба сохранены админкой.

**Админка дописывает пустоту:** `cover: ''`, `image: ''`, `posts: []`,
`images: []`, `reply: ''`, `correct: false`, `from: null` у личностного.
Схема и проверка это переживают; страница сессии 3 обязана тоже.

## Где что

| Что | Где |
|---|---|
| Категория | `src/data/categories.js`, запись `test` |
| Схема (нестрогая намеренно) | `src/content.config.ts`, `testSchema` — поле `test` у поста |
| Пункт «Тесты» и отбор у «Постов» | `public/admin/config.yml` |
| Проверка при сборке | `scripts/check-quizzes.mjs`, второй шаг `npm run build`; `--selftest` |
| Адрес результата из заголовка | `src/lib/slug.mjs` (то же правило, что адреса постов) |

**Почему схема нестрогая.** Она проверяет и черновики, а её падение роняет
сборку всего сайта. Все правила теста живут в одном месте — в
`check-quizzes.mjs`: опубликованный с ошибкой роняет сборку, черновик только
предупреждает (как `check-post-refs.mjs`).

## Что выяснено про Sveltia 0.193.2 (по её коду)

Код взят с unpkg ровно этой версии, отпечаток совпал с прибитым в
`public/admin/index.html`; читались исходники из карты (`sveltia-cms.js.map`).

1. **Поля, которых нет в форме, при сохранении НЕ выбрасываются** — уходят
   в конец файла (`draft/save/serialize.js`, «Move the remainder»). Но при
   ОТКРЫТИИ записи значение, чей тип расходится с полем формы ТОГО ЖЕ ИМЕНИ
   (список там, где форма ждёт строку), выбрасывается
   (`draft/create/normalize.js`, «nothing to salvage»). Отсюда один ключ `test`.
2. **Отбор коллекции** — `filter: { field, value }` или `{ field, pattern }`;
   отрицание — образцом `^(?!test$)`. Кривой образец Sveltia молча
   выбрасывает, и отбор не пропускает НИЧЕГО (`collection/entries/index.js`).
   Новой записи отбор категорию не ставит — нужно скрытое поле со значением.
3. **`types` у объекта и у списка есть.** Удаление блока стирает все его поля.
4. **Вычисляемое поле (`compute`) внутри списка не видит соседних полей** —
   только поля записи и `{{index}}` (в коде: «@todo Figure out how to handle
   nested fields»). Поэтому id из заголовка в админке не собрать.
5. **`relation` умеет выбирать из строк ЭТОЙ ЖЕ записи**: та же коллекция,
   `filters: [{ field: slug, values: ['{{slug}}'] }]`, `value_field:
   'test.results.*.title'`. Ограничения: (а) строки берутся из сохранённой
   версии; (б) у ни разу не сохранённой записи адреса нет — отбор снимается и
   список показывает строки ВСЕХ записей коллекции (`relation/helpers/filters.js`);
   (в) **внутрь объекта с `types` подсказки не заглядывают**: при их сборке
   описание поля ищется без значений записи (`relation/helpers/entries.js`),
   вид не известен, путь ведёт в пустоту. Поэтому `results` вне `kind`.
6. Обработчик `preSave` в `public/admin/index.html` узнаёт пост по паре
   «категория + дата» — тесты ею обладают, он собирает тайтлы из вступления
   в `anime` и может показать напоминание о неразмеченном тайтле. Безвредно.

## Что проверено и чем

- **Сайт не изменился** от категории и от схемы: сборки до и после сравнены
  по отпечаткам всех 9806 файлов — совпали все страницы. Отличаются только
  файлы поиска Pagefind, и это **не правка**: две пересборки индекса на одних
  и тех же страницах дают разные файлы. То есть поиск при каждой сборке
  выкладывает на зеркало несколько лишних файлов — не чинилось, задача не наша.
- **Отбор «Постов»** прогнан тем же разбором строки, что у Sveltia, по всем
  772 постам: все пять категорий проходят, скрыт только ровно `test`.
- **Схема** — образцы, вынутые из самого `content.config.ts`: нормальные
  тесты, пустоты из админки, буквы в числе, баллы строкой.
- **Проверка тестов** — `--selftest`: 2 здоровых теста без единой беды,
  23 подлога, каждый пойман своим правилом; плюс настоящий прогон на двух
  временных файлах (опубликованный → код 1, черновик → предупреждение),
  файлы удалены.
- **Сохранение через админку** (заказчик, локальная админка): по правке на
  каждом уровне в обоих черновиках. Сравнение по каждому полю: пропало 0,
  порядок сохранён, правки на месте, добавлена только пустота. Список
  внутри списка сохраняется — в проекте проверено впервые.
- **Выпадающий список «Баллов»** (заказчик): ровно три результата своего теста.
- **Форма «Постов»** не открывает тест даже по прямому адресу — «Entry not
  found», файл не изменился.
- **Черновики не на сайте:** сборка с ними совпала со сборкой без них по всем
  страницам; ни в одном файле `dist/` нет их адреса, заголовка или текста;
  **сам Pagefind** спрошен через локальный сервер — контроль «Фрирен» находит
  45, слова из черновиков находят обычные посты и ни одного черновика.

## Чего НЕ проверено

- Админка на живом сайте (bakapodcast.com/admin) — только локальная.
- Выпадающий список «Баллов» у ни разу не сохранённого теста (по коду он
  покажет результаты всех тестов) — пока тест один, проверить нечем.
- Правка теста, открытого одновременно в двух вкладках, — болячка админки
  общая, тестов она касается так же.
- Роботы, обходящие папку постов (перелинковка, телеграм, обложки), на тестах
  не гонялись: пока тесты черновики и их два, им нечего с ними делать.
  Перед первым опубликованным тестом — спросить перелинковку, не предложит
  ли она вставки в тест.

## Сессии 3 — что надо знать

- Данные: `post.data.test.kind.type`, `.kind.questions`, `.results`.
  `scores` — список заголовков. Адрес результата — `slugify(title)`.
- Пустые поля из админки (выше) — норма, не ошибка.
- **«← назад» и хлебные крошки** на странице поста строятся из
  `/category/<раздел>/`; у теста раздела нет. Решить до первой публикации.
- Карточка в ленте получит `data-type="test"`; своих правил вида под этот
  тип нет — посмотреть, как выглядит.
- Цвета «верно/неверно» — в `tokens.css` в сессии 3 (ТЗ §6).
