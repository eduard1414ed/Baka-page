> правила и уроки — в [CLAUDE.md](../CLAUDE.md).

**Случилось 13 августа 2026, около 19:15.** Админка перестала сохранять посты.
На момент записи (14 августа, ночь) флаг не снят.

## Что произошло

Админка выдала окно с ошибкой:

```
There was an error while saving the entry. Please try again later.
The owner of this application has been marked as spammy.
```

Это дословный ответ GitHub, а не наша поломка. **Аккаунт `eduard1414ed`
помечен автоматикой GitHub как спамерский.** Аккаунт заведён 25 июня 2026,
ему семь недель, и в него каждый день коммитят восемь роботов — по всем
признакам сработал автофильтр.

## Как это опознать (флага нигде не написано)

**GitHub НЕ показывает статус нигде: ни в настройках, ни в уведомлениях.**
Под своим логином владелец видит обычный, здоровый профиль. Флаг виден
только снаружи, и опознаётся так:

| Проверка | При флаге | Здоровый аккаунт |
|---|---|---|
| `api.github.com/users/eduard1414ed` | **404** | 200 |
| `github.com/eduard1414ed` для постороннего | **404** | 200 |
| `github.com/eduard1414ed/Baka-page` для постороннего | **404** | 200 |
| `raw.githubusercontent.com/…` | **404** | 200 |
| тот же запрос по токену владельца | видно, `"private": false` | — |

**Публичный репозиторий, невидимый снаружи, — это и есть подпись флага.**

**Обязательно берите контрольный аккаунт** (`octocat`, `torvalds`): если
и он отвечает 404, сломана проверка, а не аккаунт. Сто процентов промахов —
всегда повод заподозрить измеритель, а не мир.

**Заказчику проверять так:** ⌘ + Shift + N (окно инкогнито), адрес
`github.com/eduard1414ed`. Котик-404 — флаг на месте; открылся профиль —
сняли. Обычная вкладка не годится: в ней вы залогинены и видите здоровое.

## Что при этом ломается, а что нет

**НЕ РАБОТАЕТ:**

- **Сохранение из админки на сайте.** Между админкой и GitHub стоит
  приложение-посредник `Ov23lijrECnVBMVbpWV9`, зарегистрированное под этим же
  аккаунтом. Владелец помечен — приложение отключено.
- **Все восемь роботов (GitHub Actions).** Признак жёсткий: в API
  `repos/…/actions/runs` **total_count = 0**, хотя воркфлоу числятся `active`
  и ещё утром того же дня робот коммитил. История походов исчезает вместе
  с профилем.
- **Автосборка Cloudflare** — судя по всему, тоже: пуш в 19:14 за три минуты
  на сайт не уехал при обычной минуте. **Строго не доказано:** первый замер
  был сделан по зеркалу, а не по основному сайту (см. «Грабли» ниже).

**РАБОТАЕТ:**

- **`git pull`, `git push`, чтение репозитория с машины.** Проверено:
  пуш `399cdc57..dbbc0e04` прошёл при висящем флаге.
- **Сам сайт.** Ничего не падает, битых ссылок не появляется.
- **Ручная выкладка `npx wrangler deploy`** и заливка зеркала.

### Почему пуш работает, а админка нет

Разными ключами ходят.

| | Чем открывает | Кому принадлежит ключ |
|---|---|---|
| Админка на сайте | приложением `Ov23li…` | **заказчику** |
| Машина (`gh`, `git push`) | токеном `gho_…` от GitHub CLI | **самому GitHub** |

Блокируется не право входить, а **то, что принадлежит помеченному аккаунту**.
Ключ GitHub CLI принадлежит не ему, поэтому под раздачу не попал.

## Апелляция

Форма: **https://support.github.com/contact/flagged-account** (адрес проверен
запросом, страница отдаёт 200). Из двух карточек нужна правая,
**Reinstatement request**.

Заполнение:

- **Subject** — «Account flagged as spam - profile and public repo hidden
  (eduard1414ed)», 70 знаков из 80 допустимых.
- **Does your claim involve content on GitHub or npm.js?** — GitHub.
- **Why are you requesting reinstatement?** — вторая строка, «I can login,
  but my profile and contributions aren't visible to others». Первая («не могу
  войти») не про нас: войти можно.
- **Username and repository** — `eduard1414ed (repository: eduard1414ed/Baka-page)`.
- В большом поле — перечень четырёх адресов, отдающих 404, время начала сбоя,
  текст ошибки приложения, и объяснение: личный некоммерческий сайт подкаста,
  частые коммиты делают собственные GitHub Actions, рекламы и рассылок нет.
  Отдельно — что включены двухфакторка и подтверждённый телефон.

**Двухфакторка и телефон, добавленные после блокировки, флаг не снимают:**
проверено замером через восемь минут после включения — все четыре адреса
по-прежнему 404. Пометку снимает человек из поддержки по апелляции,
автоматика её не пересчитывает. В апелляции они полезны как довод, и только.

**Обходить блокировку вторым аккаунтом нельзя.** Обход прямо запрещён
Acceptable Use Policies, галочку под которыми заказчик ставит в самой форме
апелляции. Риск несимметричный: выигрыш — пара дней удобства, проигрыш —
отклонённая апелляция и второй аккаунт в бане. Заводить приложение под тем же
аккаунтом бессмысленно: владелец у него будет тот же.

## КАК РАБОТАТЬ, ПОКА ФЛАГ ВИСИТ: АДМИНКА НА МАШИНЕ ЗАКАЗЧИКА

**Способ проверен заказчиком на живой работе и признан рабочим** (14 августа:
отредактировал и опубликовал несколько статей, правки забраны и выложены).

**Настраивать ничего не нужно — режим встроен в Sveltia.** Ожидалась возня
с прокси-сервером и опцией `local_backend` (так это устроено у Decap) —
у Sveltia иначе, конфиг не трогается вовсе, GitHub в этом режиме
не участвует. Взято из документации самой Sveltia, а не Decap: они расходятся
молча, на этом в проекте уже обжигались.

**Порядок:**

1. На машине заказчика в папке проекта: `npm run dev`. Адрес сервер печатает
   сам, обычно `http://localhost:4321/`; занят — берёт следующий.
2. Открыть **`http://localhost:<порт>/admin/index.html`** в **Chrome, Edge
   или Brave**. Safari и Firefox не годятся: режим работает на File System
   Access API, которого у них нет.
3. На экране входа — кнопка **«Work with Local Repository»** рядом с обычным
   входом через GitHub.
4. Выбрать папку проекта целиком (`Сайт Баки`), разрешить Chrome изменять файлы.

**Что проверено без браузера:** админка отдаёт 200, `/anime-index.json` 200
(значит поиск тайтлов в кнопках работает), `/admin-posts.json` 200 (поля
голосов и упоминаний тоже), Sveltia подключается. Саму кнопку и выбор папки
проверял заказчик.

**Три отличия, о которых надо предупреждать:**

- **Сохранение больше не публикует.** Кнопка пишет файл на диск, и всё.
  На сайте ничего не появится, пока правки не заберут и не выложат руками.
- **Порт может смениться** после перезапуска сервера — говорить адрес заново.
- **Сервер живёт, пока не выключен.** Перезагрузка машины его убивает,
  поднимать заново `npm run dev`.

**Забирать правки:** обычный `git status` покажет их как изменения файлов —
дальше коммит, пуш, `npm run build`, `npx wrangler deploy`, и зеркало.

## Что приходится делать руками вместо роботов

- **Добор тайтлов:** `node scripts/sync-anime.mjs`. Ключей и секретов
  не требует, только сеть. Данные берёт **точно по source+sourceId**,
  без поиска по названию, поэтому перепутать похожие тайтлы не может;
  ручной запуск предусмотрен автором скрипта.
  14 августа так добрано 125 карточек (527 → 652) и потом ещё 8.
- **Зеркало:** `node scripts/mirror-sync.mjs` — сначала с `--dry`, он считает
  и ничего не пишет. **Нужны два ключа** `AWS_ACCESS_KEY_ID`
  и `AWS_SECRET_ACCESS_KEY` (статический ключ Яндекс Облака, бакет
  `ru.bakapodcast.com`). С GitHub их не взять: секреты там «только записать»,
  прочитать не может и владелец. Заказчик положил их в `.env` в корне —
  файл закрыт `.gitignore` (строка 17). **Когда роботы оживут, файл удалить.**
- **Выкладка:** `npx wrangler deploy` по правилам из CLAUDE.md (pull → build →
  deploy).

## Цена

Заливка зеркала считается **операциями записи**, бесплатно их 10 000 в месяц.
За 13–14 августа ушло около 7000 (4177 + 1765 + 1033): первый залив был
догоняющим после суток простоя, дальше меньше. **Две-три полные выкладки —
и лимит кончится.** Когда робот оживёт, он доливает по чуть-чуть на каждый пуш,
и вопрос снимается сам.

## Грабли этой задачи

- **МЕРИЛ НЕ ТОТ САЙТ.** Вывод «автосборка Cloudflare встала» был сделан
  по `ru.bakapodcast.com` — это **зеркало**, а не основной сайт. Адрес взят
  из карты сайта, где он стоит потому, что он канонический для поисковиков.
  Основной сайт до выкладки не проверялся ни разу, и теперь проверить нечем:
  выложено поверх. Правило: **сначала выясни, какой из двух адресов ты
  меришь.**
- **Ноль совпадений — повод заподозрить измеритель.** Первый прогон «сколько
  размеченных тайтлов без карточки» дал 39 из 39. Причина: в id осталась
  кавычка на конце. После починки — 0 из 39.
- **Проверка на 404-й странице ничего не значит.** Смотрел, не видно ли
  служебных меток на странице поста, получил «0» — а страница была «Такой
  страницы нет»: пост оказался ссылкой наружу, своей страницы у него нет
  вовсе. Сначала код ответа, потом содержимое.
- **Правило искали не в том файле.** Проверка «уехало ли новое правило CSS
  на сайт» смотрела в саму страницу и ответила «нет». Правило было
  в подключаемом файле `_astro/*.css`. Смотреть надо И встроенное в страницу,
  И то, на что она ссылается.
- **zsh не разбивает значение переменной на слова.** `node скрипт.mjs $list`
  передал весь список одним аргументом, скрипт обработал ноль файлов
  и бодро отчитался. Нужно `${=list}`.
