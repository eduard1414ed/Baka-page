## Цель проекта

Сайт-витрина подкаста: посты, выпуски, транскрипты и связи между ними через
упоминания аниме. Главная фишка — клик по названию тайтла открывает страницу
со всеми постами и выпусками, где он упоминался, вплоть до минуты в разговоре.

## Стек

- **Astro** — статический генератор
- **Sveltia CMS** (или Decap CMS) — админка на `/admin`, логин через GitHub
- **GitHub** — код и контент, GitHub Actions для роботов
- **Cloudflare Workers со статическими файлами** — хостинг сайта и автосборка.
  Не Pages: с 2026 года Cloudflare рекомендует новым проектам сразу Workers,
  возможности у них те же, а развивают только Workers
- **Cloudflare Workers** — сервис-посредник для логина в админку через GitHub
- **Hetzner** (мой сервер) — свои видеофайлы, тяжёлые скрипты, архивы
- **Shikimori API** — данные об аниме, русские названия; **AniList** — запасной
- **Pagefind** — поиск

## Модель данных

### Пост (`src/content/posts/*.md`)

Единая сущность для всего. Выпуск подкаста — тоже пост, с категорией `podcast`.

| Поле | Описание |
|---|---|
| `title` | Заголовок |
| `date` | Дата публикации |
| `category` | `podcast`, `videoessay`, `note`, `review`, `interview`, `bonus` |
| `cover` | Обложка для ленты и соцсетей. **На самой странице поста не выводится** — там картинка уже есть. Путь строкой (`/images/uploads/…`), не `image()` Astro |
| `noCover` | «Обложки нет намеренно» — заметка идёт в ленте одним заголовком. Не то же самое, что пустой `cover` («подбери сам») |
| `anime` | Массив ID тайтлов; заполняется автоматически из разметки в тексте |
| `youtube` | Ссылка на ролик |
| `video` | Своё видео |
| `audioGuid` | Для категории `podcast` — привязка к элементу RSS |
| `externalUrl` | Статья вышла на чужом сайте. **Своей страницы у такого поста не создаётся вовсе**, карточка в ленте ведёт наружу. Признак, а не категория — работает поверх любой |
| `externalSource` | Название площадки («Кинопоиск»). Пусто — подставляется по домену |
| `buttons` | Кнопки: подпись + ссылка + стиль |
| `transcript` | Ссылка на JSON с расшифровкой |
| `script` | Готовый сценарий (для видеоэссе) |
| `draft` | `true` = виден только в админке |
| тело | Markdown |

Тип медиа (текст / галерея / видео) не задаётся руками — выводится из содержимого.
Категория задаёт редакционный формат и фильтры в ленте.

### Тайтл (`src/content/anime/*.json`)

`id` (slug), `shikimoriId`, `titleRu`, `titleOriginal`, `year`, `studio`,
`poster`, `synopsis`, `url`, `aliases`.

**`aliases` — варианты написания, по которым тоже ищутся упоминания**,
правятся в админке. Нужны для трёх случаев: падежи («Ходячего замка»),
как говорят вслух («K-On!» вместо «Кэйон!»), как искажает распознавание
(«Фринен» вместо «Фрирен»). Вариант, вписанный один раз, начинает ловиться
во всём архиве сразу и во всех будущих постах — пересчёт идёт при сборке,
распознавание заново гонять не нужно. Симметрично исключениям упоминаний
из этапа 5: варианты добавляют упоминания, исключения убирают.

**Что правится в админке вручную:** `titleRu`, `synopsis`, `poster`, `aliases`.
Описание из Shikimori бывает сухим или со спойлерами, русское название иногда
не приходит вовсе (AniList), обложка попадается неудачная.

**Правленое вручную поле не перезаписывать при обновлении из API.** Признак
хранить по каждому полю отдельно, а не на всю карточку: описание я перепишу
своими словами, а обложку захочу обновлять автоматически. При пересчёте
справочника такое поле остаётся моим, а в лог идёт строчка, что данные из API
для него проигнорированы.

### Транскрипт (`src/content/transcripts/*.json`)

Массив реплик: `start`, `end`, `speaker`, `text`. Отдельно — карта спикеров
(`speaker_0` → имя) и флаг источника: распознано / выровнено по сценарию.

## Ограничения хостинга (учитывать на всех этапах)

Бесплатный план Cloudflare: трафик не лимитирован, но **не более 20 000 файлов
на сайт** и не более 25 МБ на файл (на платном плане — 100 000 файлов).

Двадцать тысяч звучит много, но Astro генерирует файл на каждую страницу плюс
вариант каждой картинки под каждый размер экрана. При архиве в сотни выпусков
с транскриптами это реально исчерпать. Поэтому:

- каждую картинку пережимать максимум в **два размера**, не в четыре;
- оригиналы медиа, видео и экспорт телеграма хранить на Hetzner,
  в репозиторий класть только то, что реально выводится на страницах;
- после каждого этапа показывать мне, сколько файлов в сборке,
  чтобы я видел запас.

## Место на сервере

На Hetzner у меня **40 ГБ на всё**, включая систему. Отсюда правила:

- Аудио выпусков не хранить. Для транскрибации скачивать по одному файлу,
  отправлять на распознавание и **сразу удалять**. Не выкачивать архив целиком.
- Перед любой массовой операцией проверять свободное место и говорить мне,
  сколько её потребуется.
- Видеоэссе по умолчанию живут на YouTube и встраиваются по ссылке.
  Свои файлы — только для того, что на YouTube выложить нельзя.
- Экспорт телеграма и оригиналы картинок в git-репозиторий не класть никогда.

## Границы

Не делаем: комментарии, рассылку, личные кабинеты, платный контент,

## Как проверяем работу (правило на весь проект)

**Расширение Chrome для проверки страниц в этом проекте не используется.**
Оно не работало, и заказчик просил к нему не возвращаться. Значит:

- проверяем тем, что работает без браузера: проходит ли сборка, есть ли
  нужная разметка в собранных файлах (`dist/`), прогоняем логику в Node
  на реальных данных, считаем размеры файлов;
- **всё, что живёт в браузере — клики, поиск, раскрытие блоков, вид на
  телефоне, — проверяет заказчик руками.** Значит после каждой такой правки
  надо прямо говорить: вот адрес, вот что нажать, вот что должно произойти;
- в `СТАТУС.md` честно писать, что проверено, а что нет. Не выдавать
  «разметка на месте» за «работает».

Локальный сервер для ручной проверки: `npm run build`, затем `npm run preview`
(адрес он печатает сам — обычно `http://localhost:4321/`, а если порт занят,
берёт следующий).

## Уроки проекта

Короткие правила, выведенные из уже совершённых ошибок. Каждый оплачен
временем, деньгами или тихо испорченными данными. Подробности, откуда
что взялось, — в файлах `статус/этап-*.md`.

### Деньги и внешние сервисы

- **Цену платной операции брать из реального списания в кабинете сервиса**,
  не из формулы в коде и не из чужих обзоров. Константа `CREDITS_PER_MINUTE`
  завышала расход в 12 раз, и из-за неё этап чуть не переехал на другой сервис.
- **Результат платной операции записывать на диск сразу**, до любых
  необязательных шагов. Сверка названий ходила в сеть уже после оплаты —
  сбой сети означал бы вторую оплату того же выпуска.
- **Платный шаг и бесплатный пересчёт разделять, сырые данные сохранять.**
  Пословные данные распознавания весят 20–80 КБ и позволяют переразбить
  реплики бесплатно; без них любая правка правил — повторная оплата архива.
- **Перед тратой спрашивать подтверждение**, а из-под `nohup` без явного
  `--yes` не запускаться совсем.
- **У одного сервиса бывает два API, и они расходятся.** Старый REST Shikimori
  отдавал `missing_original.jpg` там, где новый GraphQL и сам сайт показывали
  настоящий постер: два тайтла попали в справочник без обложек, хотя код
  отработал правильно. Данных нет — переспросить второй ручкой того же
  сервиса, прежде чем считать, что их нет вовсе. **И следить за переездом
  домена:** `shikimori.one` отвечает 301 на `shikimori.io`, а редирект
  превращает POST в GET и теряет тело запроса — GraphQL молча отвечал
  «Unexpected end of document».
- **Обложку из запасного источника брать только со сверкой названия.** Поиск
  по имени легко приводит к сиквелу, спешлу или ремейку, а чужая обложка хуже
  отсутствующей: она выглядит правильной и не будет замечена никогда.
  Не совпало — не берём и говорим в лог.
- **Поисковый движок проверять запуском движка, а не чтением его выдачи
  в разметке.** Pagefind собирается в браузерный модуль, но запускается
  и в Node: копия `pagefind.js` плюс `options({ basePath })` на локальный
  сервер. Три ошибки, которых разбором разметки не видно вовсе, нашлись
  за один прогон: **список значений у фильтра это «И», а не «ИЛИ»**
  (`type: ['Посты','Выпуски']` требует, чтобы страница была сразу и тем,
  и другим, и находит ровно ноль — «или» пишется через `any`); **сводка
  по фильтрам на первом запросе сеанса приходит пустой**, потому что файл
  фильтров ещё не скачан, и счётчики врали нулями на реальной выдаче;
  **движок ищет по основам слова, а поиск внутри страницы — буква в букву**,
  поэтому в ссылку надо класть слово, которое правда стоит в тексте
  («студии»), а не то, что набрал человек («студия»).
- **Поисковый движок, не найдя слова, отрезает у него хвост.** Pagefind ищет
  «кейон» → «кейо» → «кей» → «ке» → «к» и находит предлог «к» на шестнадцати
  страницах: в выдаче светятся «Ксюша», «Кэйго», «каждый». Отключить это
  нельзя. Значит найденное слово надо сверять с набранным самим: либо оно
  начинается с запроса целиком, либо отличается ТОЛЬКО ОКОНЧАНИЕМ — совпадает
  всё, кроме двух последних букв запроса, и своего хвоста у него не больше
  трёх букв. **Порог «половина длины» слишком мягок:** у шестибуквенного
  запроса это три буквы, и «Мотоко» находит «мотив». Половина растёт вместе
  с длиной слова, а окончание — нет. И сверять надо ЧАСТИ слова, а не слово
  с обчищенными краями: в расшифровке попадается `что"Фрирен`, кавычка внутри,
  и настоящее упоминание иначе отбрасывается целиком.
- **Результат поиска нельзя запоминать между запросами.** В куске индекса
  лежит не только текст страницы, но и места совпадений с отрывком — они
  посчитаны под конкретный запрос, а ключ у куска один и тот же на все.
  Память, пережившая запрос, показывает чужие подсветки и чужие цитаты:
  адрес, заголовок и картинка при этом правильные, поэтому подмену не видно.
- **Отрывок вокруг найденного слова — не то же самое, что описание материала.**
  Отрывок цепляет служебное начало страницы («] · №135. … Пампам. 12:04 —
  Новый блок. Транскрипт.») и в выдаче нечитаем. Под заголовком ставим
  описание, которое уже есть у материала, а место находки показываем отдельной
  группой результатов.
- **Проверять по первоисточнику, а не по ТЗ, документации и своей памяти.**
  Модель `scribe_v1` из ТЗ была снята с поддержки; поля Shikimori проверялись
  запросом к API; параметры сжатия картинок у хостинга — восемью реальными
  запросами, прежде чем решить, что он так не умеет.

### Проверка и приёмка

- **Готово — только после проверки руками в браузере.** «Разметка на месте
  в `dist/`» это не «работает». Писать явно: вот адрес, вот что нажать.
- **Забрать правки заказчика — половина дела: после `git pull` НАДО ПЕРЕСОБРАТЬ.**
  Выкладка берёт готовую папку `dist/`, а не репозиторий. Собрал, потом забрал
  правки, потом выложил — на сайт уехала сборка БЕЗ них, и выглядит это ровно
  так же, как если бы `pull` вообще не делали: заказчик сохранил в админке,
  коммит на месте, а на сайте пусто. Наступили 9 августа на странице
  «Поддержать»: вписанная в админке третья ссылка не появилась. Порядок один:
  **pull → build → deploy**, и `build` после каждого `pull`.
- **Убеждаться, что запушено, а не только закоммичено.** Однажды на GitHub
  не уехало 37 коммитов, и «вторая копия транскриптов вне сервера» три недели
  была фикцией. Плюс отдельно проверять, что новые файлы попали в коммит:
  правка `publish-cron/` была описана и задеплоена, а в репозиторий не попала.
- **Любую новую формулу гонять по всему архиву, а не на паре примеров.**
  Выпуск на 18 секунд округлялся в «0 мин слушать» — нашлось только прогоном
  по всем 145 постам.
- **Пороги и лимиты подбирать замером на живых данных.** Порог блока 90 секунд,
  8 минут в карточке тайтла, `MIN_IMPROV_WORDS = 3`, лимит длины подзаголовка —
  все выведены из замеров по архиву, а не назначены на глаз.
- **Мерить вес страницы целиком, а не то, что кажется тяжёлым.** Оптимизировали
  транскрипт (46 КБ), а 94 % веса страницы оказалось обложкой (862 КБ).
- **Макет противоречит не только соседнему макету, но и сам себе.** В разметке
  «Поддержать» шапка блока завёрнута в обёртку, а стили назначают колонки
  её ДЕТЯМ — то есть элементам, которые до сетки секции не дотягиваются:
  заголовок встал бы в одну двенадцатую ширины экрана. В соседней секции
  того же макета тот же самый заголовок стоит прямым ребёнком, и там всё
  сходится. **Спорят разметка и стили — верить стилям:** они говорят
  о намерении («вот в каких колонках это лежит»), а обёртка чаще всего
  осталась от копирования соседнего блока.
- **Вынося вид в общий класс, проверить, что правило контейнера его
  не перебивает.** `.hero-lead p` — это класс, метка компонента и тег против
  одного класса у общего `.lead`, и общий вид молча проиграл ему кегль,
  интерлиньяж и цвет. То есть правило, только что вынесенное в одно место
  ради одинаковости, перестало работать ровно там, ради чего его выносили,
  и ошибки не появилось никакой. **Лечится не весом, а тем, что контейнер
  не пишет правил на теги внутри:** зазоры задаются `gap`, а чужая разметка
  (например, приехавшая из markdown) лежит в своей обёртке.
- **Проверка по `dist/` обязана отделять наш код от чужого.** В сборке лежат
  библиотека Pagefind и правила переходов от самого Astro: разбор собранного
  CSS выдал 27 `!important` и 44 «цвета мимо палитры», среди которых нет
  ни одного нашего. **И цвета сравнивать по значению, а не по записи** —
  сборщик сжимает `rgba(216,143,159,.1)` из палитры в `#d88f9f1a`, и посимвольное
  сравнение объявляет законный токен нарушением.
- **Одинаковость проверяется замером, а не взглядом на один экран.** Правый
  край правой колонки на «Поддержать» задавался тремя разными способами сразу
  — `6/12`, `6/11`, `10/13` плюс три разные `max-width` (730, 700, 640), — и на
  экране 1440 это 1096, 1208 и 1320 px. В коде это три безобидные строчки
  в разных местах файла, каждая скопирована из макета правильно. Увидеть можно
  только глазом на живой странице или **посчитав правый край каждого блока
  в пикселях**. Второе дешевле и делается разбором собранного CSS.
- **Вид, у которого нет одного дома, разъезжается тем вернее, чем он мельче.**
  Стрелка ↗ стояла в пяти местах пятью описаниями: у трёх акцентная, у двух
  наследовала цвет ссылки и выходила чернильной. Никто не заметил, пока
  заказчик не посмотрел на почту. **Мелочь не спасает от правила «одно
  описание — одно место»: она его усугубляет**, потому что расхождение мелочи
  не читается ошибкой, а читается неряшливостью, и чинить его никто не идёт.
- **Логотип чужого бренда нельзя нарисовать «на глаз».** Пять срисованных
  значков площадок заказчик назвал кривыми, и был прав: узнаваемый знак либо
  взят настоящим, либо нет, приблизить его нельзя. Настоящие берутся из
  открытых наборов (Simple Icons, CC0) или с favicon самой площадки; чего нет
  ни там, ни там, — оставляем без иконки, а место под неё всё равно занимаем,
  иначе названия встают рваным краем.
- **Толщину обводки внутри значка числом не задать.** Рисунок живёт в своей
  системе координат (32×32) и показывается в другом размере (30 px), поэтому
  `stroke-width: 1` даёт на экране 0.94 px — почти, но не столько же, сколько
  у рамки соседней кнопки. Ровно один пиксель при любом масштабе даёт
  `vector-effect: non-scaling-stroke`.
- **Макеты противоречат друг другу, и молча.** Один и тот же элемент — подводка
  справа от заголовка раздела — в макете архива набран Body L чернилами,
  а в макете поиска Body S приглушённым. Каждая страница по отдельности
  выглядит правильно, расхождение видно только при переходе между разделами,
  и нашёл его заказчик. Правило: элемент, который есть в нескольких макетах,
  сверять во ВСЕХ, а не верстать по тому, который открыт. Дизайн-система
  при этом может молчать о нём вовсе — тогда решение за заказчиком, а место
  ему одно на весь сайт.
- **Любой прогон, который трогал исходники, обязан кончаться пересборкой.**
  Проверка «пустое поле не ломает страницу» правит файл, собирает, разбирает —
  и последний её случай остаётся лежать в `dist/`. Файл при этом возвращён,
  `git status` чист, всё выглядит безупречно, а в готовой папке ПУСТАЯ
  страница. Выложи в эту минуту — на сайт уедет она, при совершенно здоровом
  репозитории. Это та же мина, что «pull без пересборки», только с другой
  стороны: **сборка живёт отдельно от исходников и о них ничего не знает.**
- **Проверка, разворачивающая медиазапросы, склеивает разные правила в одно.**
  `.x{display:none}` в базе и `.x{display:grid;…}` в медиазапросе — это
  обычное «на узком прячем, на широком показываем», а после снятия обёртки
  `@media` они выглядят одним правилом, совмещающим видимость и раскладку.
  Проверка объявляет нарушением здоровый код. Смотреть надо внутрь одного
  блока `{…}`, а не по всем правилам с таким селектором.
- **«Пусто» у проверки ничего не значит, пока не показано, что она умеет
  находить.** Дописать в собранный CSS правило, нарушающее все пункты сразу,
  убедиться, что поймано, и вернуть файл — это полминуты. Без этого шага
  проверка, сломавшаяся от опечатки в регулярном выражении, будет молча
  выдавать «всё хорошо» до конца проекта.
- **Проверку писать ФАЙЛОМ, а не однострочником `node -e '…'`.** Обратный слэш
  внутри однострочника проходит через две системы экранирования подряд, и `\b`
  доезжает до JavaScript литеральным слэшем: выражение перестаёт совпадать
  вообще ни с чем. Проверка при этом НЕ ПАДАЕТ — она отвечает «правил 0»
  и «ничего не найдено», то есть врёт ровно в сторону «всё хорошо». За одну
  сессию соврала так дважды подряд.
- **Честно записывать, что не проверено.** Раздел «Чего НЕ проверено» —
  обязательная часть отчёта, а не признак незавершённой работы.
- **Проверку, которая врёт, чинить сразу — вместе с тем, что она поймала.**
  Поиск «цветов мимо переменных» принимал числовую запись пробела `&#8201;`
  за шестнадцатеричный цвет. Проверка, дающая ложные срабатывания, перестаёт
  что-либо проверять через две сессии. В разметке пишем именные записи
  (`&thinsp;`). **И в комментариях не цитируем то, что ищет проверка:**
  строчка «было `rgba(0,0,0,.85)`, стало `--ink`» — честное объяснение,
  которое навсегда ломает поиск цветов мимо палитры. Объясняем словами.
  Второй раз это случилось с запретом `auto-fit`: комментарий «`auto-fill`,
  а не `auto-fit`» — ровно то, что проверка считает нарушением. Пишем
  «сетка заполняющая, а не схлопывающая».
- **Две записи одного свойства подряд сборщик схлопывает в последнюю.** Приём
  «сначала то, что понимают все, следом то, что понимают не все» в собранном
  файле не выживает: `align-items: end` перед `align-items: last baseline`
  исчез, и в браузере без поддержки не осталось ничего. Запасной вариант ставим
  правилом, а новый — в `@supports`: там схлопывать нечего. **И проверяем это
  в собранном CSS**, а не в исходнике — в исходнике обе строки на месте.
- **Утилитный класс приносит с собой не только то, за чем его позвали.**
  `.tech` на кнопке фильтра главной притащил ГАРНИТУРУ, и вкладки главной
  оказались моноширинными, а точно такие же вкладки архива — нет. Кегль,
  капслок и трекинг при этом совпадали, поэтому расхождение читалось как
  «другое написание», а не как ошибка. Ставя утилиту, смотреть весь её список
  свойств, а не одно нужное.
- **Комментарий `{/* … */}` не может стоять первым внутри `условие && (…)`.**
  Astro видит два выражения подряд и отвечает `Expected , or ) but found class`,
  роняя сборку целиком. Пояснение к такому блоку уезжает в заголовок файла
  обычным `//`, а не остаётся рядом с разметкой.
- **Незакрытый комментарий в CSS съедает всё до следующего `*/`.** Убирая
  правило, которое переехало в общий файл, легко оставить на его месте
  объяснение и забыть `*/` — и тогда пропадают десятки правил ниже, включая
  ширину колонки чтения. **Сборка при этом проходит, разметка правильная,
  ошибок нет ни одной**, а страница разъезжается во всю ширину экрана.
  Наступили дважды в одном файле за одну правку, нашёл заказчик глазами.
  Считать `/*` и `*/` в каждом тронутом файле — это одна строка проверки,
  и она дешевле любого разбора вёрстки.
- **Убирая атрибут-метку, помни: она и есть всё поведение.** При перестройке
  блока таймкодов потерялась `data-seek="youtube"` — единственное, чем блок
  сообщает скрипту, что перематывать надо ролик. Разметка осталась правильной,
  блок рисовался, нажатие работало — и запускало звук вместо видео. Поведение,
  висящее на одном атрибуте, обязано проверяться разбором собранной страницы
  после КАЖДОЙ правки разметки, а не после первой.
- **Разбор собранного CSS обязан читать и стили, вставленные прямо в страницу.**
  Astro часть правил кладёт файлом в `_astro/`, часть вставляет в `<head>`
  страницы, и скрипт, читающий только файлы, отвечает «такого правила нет»
  про правило, которое есть. Плюс современный синтаксис медиазапросов:
  сборщик отдаёт `@media (width>=1101px)`, а не `min-width` — разбор
  по `min-width` молча считает, что правило действует на всех ширинах.
- **Чего нет в живых данных — проверять временной подменой.** Плашки «Бонус»
  и поста-ссылки на чужой сайт на сайте не было ни одного, и обе новые ветки
  кода остались бы непроверенными. Подменить пару постов, собрать, посмотреть
  разметку, вернуть файлы и убедиться, что `git status` чист. **Так же
  и с порогами:** пагинация на 11 материалах при пороге 24 не появляется вовсе,
  поэтому порог временно опускается до трёх, листание разбирается в собранных
  файлах и возвращается на место. Иначе механизм ждал бы проверки до того дня,
  когда данных станет достаточно, — то есть до продакшена.
- **Нарушение, снятое на одной ширине, снято наполовину.** Две линии подряд
  под панелью фильтров чинились только до 761 px: выше решили, что линии над
  карточками первого ряда «идут в ряд, так и задумано». Правило §5 ширин
  не знает, и заказчик увидел на широком экране ровно то, что чинили на узком.
  Оговорка «на такой-то ширине это выглядит нормально» — почти всегда попытка
  не считать столбцы.
- **Правку remark-плагина не видно, пока не стёрт разбор постов.** Astro держит
  его в ДВУХ папках сразу — `.astro/` и `node_modules/.astro/`, — и сборка
  после правки плагина проходит успешно, отдавая ПРЕЖНЮЮ разметку. Разбор
  собранной страницы при этом честно показывает старое, и легко решить, что
  правка не работает. Чистить обе папки, иначе проверяешь вчерашний код.
- **Вынос контрола за край блока считается по реальной ширине оболочки,
  а не по брейкпоинту из системы.** Стрелки галереи на `-58px` при 1101 px
  вылезали за край страницы: там свободно 32 + (ширина окна − 1064) / 2, то
  есть 50, а нужно 58. Полоса 1101…1115 давала бы горизонтальный скролл —
  тот самый, который прятать запрещено. Считать арифметику и писать её
  в комментарий, а не брать ближайший знакомый брейкпоинт.
- **Картинки, нарисованные под тёмную тему, на светлой невидимы — и код
  об этом молчит.** Логотип `logo.png` оказался белым на прозрачном (средний
  цвет непрозрачных пикселей ровно 255,255,255), на бумажном фоне его
  не было бы видно вовсе. Проверяется замером цвета, а не чтением имени файла.

### Данные и надёжность

- **Автоисправления не применять молча — только предлагать.** Из 21 предложения
  по исправлению названий не годилось ни одно («круто» → «Наруто», падежи).
  Тихо подменённое слово хуже неисправленного.
- **Событие `error` у `<audio>` не означает, что всё пропало.** Браузер шлёт
  его и на прерванную загрузку, и на неудачную первую попытку, после которой
  берёт файл со второго раза. Плашка «не удалось загрузить» поверх играющего
  плеера — прямая ложь читателю. Признавать ошибку, только если сошлось всё:
  элемент в состоянии ошибки, код не «прервано», данных не набралось совсем.
- **Ряд грида растягивает свои ячейки, и это перебивает `aspect-ratio`.**
  Квадратная обложка рядом с длинным заголовком превращается в полосу,
  а картинка внутри болтается по центру. Растягиваться должна только та
  колонка, которой это нужно; остальным — `align-self: start`.
- **Спрятанное держим в `<template>`, а на место ставим скриптом.** Два
  требования к спойлеру противоречат друг другу: содержимое не должно попадать
  ни роботу, ни в поиск — значит его не может быть в разметке; и строка
  не должна прыгать при раскрытии — значит текст обязан стоять на месте
  и только менять видимость. Сходятся они в одной точке: в собранной странице
  лежит `<template>`, а браузер переносит текст внутрь кнопки при загрузке.
  Прятать через `display` нельзя — дёргается вся страница.
- **Ломаться громко лучше, чем тихо врать.** Потерялась привязка исключения —
  показываем упоминание и пишем предупреждение в сборку, а не прячем.
- **Якорь привязки выбирать так, чтобы он пережил пересчёт данных.** Не таймкод
  (сдвинется), не номер вхождения (сдвинется от нового варианта написания),
  а номер реплики + позиция в тексте.
- **Блок объявляет о себе сам, а не значится в чужом скрипте по имени.**
  Лента главной прятала витрину по `getElementById('all-layout')`, и второй
  такой блок (каталог аниме) пришлось бы вписывать в её скрипт третьей
  строчкой, четвёртый — четвёртой. Теперь блок помечен `data-only-mode`,
  а лента прячет всё помеченное: страница добавляет свои блоки, не трогая
  компонент. Признак беды — правка чужого файла ради своей разметки.
- **Блок, переехавший на индексируемую страницу, обязан выйти из тела поиска.**
  На главной и «О проекте» `data-pagefind-body` нет вовсе, и блок со ссылками
  на площадки там безобиден. Тот же блок на странице выпуска или тайтла попадает
  внутрь индексируемого тела — и «Telegram · Новости, мысли и новые материалы»
  встаёт в цитату выдачи у КАЖДОГО материала, а запрос «телеграм» находит весь
  сайт разом. Ставится за пределами тела И помечается `data-pagefind-ignore`:
  первое решает задачу, второе переживёт следующую перестановку разметки.
- **Служебная обвязка блока в поиск не идёт.** Счётчик «01 / 06», стрелки
  листания, подпись кнопки спойлера — это органы управления, и в цитате
  выдачи они читаются мусором: «[ галерея ]01 / 06. ‹ ›». Помечается
  `data-pagefind-ignore`, как навигация в части 5. Подпись самого блока при
  этом остаётся в индексе — она текст материала.
- **Свой размер внутри компонента спорит с местом, куда его ставят, — и спор
  решает порядок файлов.** У иконки площадки стояли `1.1em` внутри
  `PlatformIcon`, а новый макет ставит её в коробку 28×28. Правило страницы
  `.platform-icon :global(svg)` весит РОВНО СТОЛЬКО ЖЕ, сколько правило `svg`
  внутри компонента (класс плюс тег против тега плюс метка), и кто победит,
  зависит от того, чей файл в сборке позже. Компонент рисует, коробку меряет
  тот, кто ставит.
- **Одни правила — один код, второй копии не писать.** Админка, страница выпуска
  и указатель упоминаний считают разметку одним модулем; две копии разъехались
  бы молча. Где дублирование неизбежно (админка не импортирует из `src`) —
  комментарий «меняете тут — поправьте и там». Это правило уже нарушалось
  и уже стоило: снятие markdown было написано дважды, счётчик времени чтения
  умел снимать метку тайтла `:anime[…]{…}`, а подводка — нет, и код разметки
  уехал на карточку, в описание для поисковика и в превью телеграма. Теперь
  общий `src/lib/plainText.mjs`.
- **Геометрию картинки задаёт материал, а не место, куда его положили.**
  Пропорции обложки стояли в стилях каждого слота главной. Пока в «широкий»
  слот не попал выпуск подкаста — работало; попал — и квадратную обложку
  обрезало до полосы. Слот решает, сколько дать места; какой картинка формы,
  знает один компонент (`PostMedia.astro`).
- **Ручные правки защищать по каждому полю отдельно**, а не на всю карточку:
  описание своё навсегда, обложка пусть обновляется из API.
- **Два счётчика рядом обязаны считать одно и то же.** В выдаче поиска число
  у области и число в заголовке группы стоят в двадцати пикселях друг от друга.
  Считай они разное — страницы и строки, — читатель решит, что один из них
  врёт, и будет прав. Если точного числа нет (сколько раз слово прозвучало
  внутри выпуска, видно только в скачанном куске индекса), счётчик делается
  живым у обоих, а не правдоподобным у одного.
- **Размер рамки под картинку считать по замеру самих картинок, а не по числу
  из ТЗ.** Дизайн-система утверждала, что постеры хранятся строго 2:3, и из
  этого выводила ширину колонки 112. Замер справочника дал разброс 0.666–0.717:
  ровно 2:3 оказался один постер из одиннадцати. Постер не дотягивал до краёв
  марки на 5–12 px, у каждого по-своему. Обрезать нельзя, значит рамку считаем
  от самого широкого реального постера — и **держим это число одним токеном
  на все места, где рисуется постер**: грабли сработали дважды, сначала
  в горизонтальной марке, потом в каталоге, где над картинкой оставалась
  пустая полоса у самой перфорации. **Пустота сбоку читается рамкой, пустота
  сверху — дырой**, поэтому рамка равняется на широкий постер, а не на узкий.
- **Поле, заведённое для поиска, обязано попасть во ВСЕ поиски.** «Варианты
  написания» тайтла искал каталог, а поиск по сайту про них не знал — и запрос
  «кейон» не находил «Кэйон!», хотя ровно этот вариант в карточке записан
  руками. Заказчик вписывает вариант один раз и вправе ждать, что тайтл начнёт
  находиться везде.
- **Расширение поиска на весь архив — только с ручным подтверждением.** Один
  плохой вариант написания даёт ложные упоминания сразу везде и молча,
  а отменять их пришлось бы по одному выпуску.
- **Один контрол, описанный в двух компонентах, — это две копии.** Кнопка
  «играть» и перемотка стоят и в плеере страницы, и в закреплённой панели;
  описания разъехались бы молча — сначала размером зоны нажатия, потом цветом
  наведения. Общие контролы живут в базе, компоненту остаётся раскладка.
- **Что записано латиницей, по-русски не ищется.** Студии и оригинальные
  названия приходят из Shikimori латиницей, и «гибли» не находил ни одного
  из трёх тайтлов Ghibli — а это самый вероятный запрос в каталог, вообще
  не являющийся названием. Лечится записью латинской части кириллицей
  в невидимое поле поиска (`src/lib/translit.mjs`): она только ДОБАВЛЯЕТ
  совпадения, оригинал в том же поле остаётся. Переводить надо данные,
  а не запрос: «гибли» → «gibli» не совпадёт с «ghibli», по-русски «h»
  не пишется вовсе.
- **Порядок, которого нет в данных, нельзя выдать за порядок.** «Сортировка
  по порядку добавления» упиралась в то, что даты добавления у тайтла нет:
  ни Shikimori, ни AniList такого не отдают. Алфавит выдать за неё — тихая
  ложь; поле в карточку не завести — админка переписывает файл целиком
  и незнакомое поле рискует потерять. Порядок собран из истории git
  в отдельный список (`src/data/animeOrder.js`), а чего в нём нет — встаёт
  в конец: новый тайтл всегда добавлен позже всех.
- **Не дублировать факт, у которого есть хозяин.** Длительность принадлежит
  RSS, обложка — хостингу подкаста: копия в 141 файле замёрзла бы навсегда.
- **Картинка превью для соцсетей — только jpeg или png, никогда webp.**
  Телеграм webp-превью разворачивает ненадёжно, а это главная площадка
  подкаста. Astro по умолчанию отдаёт webp, формат приходится задавать явно.
- **Картинку превью отдавать со своего домена и своим файлом.** Ссылка на
  обложку у хостинга подкаста (чужой домен, `Cache-Control: no-cache`, 1,5 МБ
  при 2000×2000) в телеграме не разворачивалась вовсе, хотя отдавалась с кодом
  200. Своя копия 1200 px на ~150 КБ — и заработало. Это единственное поле,
  где правило «не дублировать факт, у которого есть хозяин» не действует:
  файл делается из уже скачанной обложки, а не тянется заново.
- **`twitter:card` всегда `summary_large_image`.** Телеграм по этому тегу
  решает, показывать ли картинку вообще: при `summary` превью выпуска вышло
  без картинки совсем. Забота о том, что широкая карточка обрежет квадратную
  обложку, обошлась дороже самой обрезки.
- **Проверять превью отправкой ссылки, а не наличием тегов.** Все теги стояли,
  все картинки отдавались с кодом 200 — и превью всё равно было пустым.
  «Разметка на месте» тут значит ещё меньше, чем обычно.
- **Список для поисковика строить из тех же данных, что и сами страницы**,
  а не из готовых файлов в `dist/`. Иначе «черновиков в карте нет» нечем
  пересчитать, а черновиков у нас 138 против 8 опубликованных постов.
- **У чего нет страницы, то не попадёт ни в карту сайта, ни в поиск само.**
  Pagefind индексирует собранные страницы, карта строится из них же. Появилась
  сущность без страницы (пост-ссылка на чужой сайт) — её надо класть в индекс
  отдельной записью (`index.addCustomRecord`) и отдельно же не пускать в карту.
  Три места, где живёт правило «страницы нет», перечислены в `externalPost.mjs`.
- **Адрес, введённый руками, проверять в админке, а не только схемой.**
  `z.string().url()` на пустую строку рассчитан, а на «kinopoisk.ru» без
  `https://` — нет: сборка всего сайта падает. `pattern` у поля в CMS ловит
  опечатку там, где её делают.

### CMS (Sveltia)

- **`pattern` у поля проверяется ВСЕГДА, и на пустом значении тоже.** `required:
  false` на это не влияет никак — в коде Sveltia это отдельная проверка строчкой
  выше, а `pattern` просто гонит `re.test(String(value))` по чему угодно.
  Значит поле с проверкой становится обязательным по побочному действию,
  и человек видит не «заполните поле», а «адрес должен начинаться с https://»
  на пустой строке. **Пустоту разрешаем в самом выражении: `^$|…`.** Наступили
  дважды подряд — на поле поста и на поле нового блока.
- **Зарегистрировать кнопку редактора мало — её надо вписать в `editor_components`
  у поля.** Пока этот список задан в `config.yml`, Sveltia показывает в меню
  ТОЛЬКО перечисленное в нём, а всё остальное зарегистрированное молча не зовёт:
  ошибки нет, кнопки нет. Список у нас появился ради другого — убрать встроенный
  простой блок картинки, — и с тех пор каждая новая кнопка невидима по умолчанию.
  **Признак этих граблей: код на сайте правильный, а в меню пусто.** Проверять
  не глазами в браузере (там ещё и кэш), а сверкой двух списков: что
  зарегистрировано в `index.html` и что перечислено в `config.yml`.
- **Проверка ищет в собранной странице — ищи в НУЖНОМ ТЕГЕ, а не по странице
  целиком.** Собранная страница содержит и разметку, и скрипты, и стили,
  вставленные в `<head>`. Поиск строки по всему файлу находит её в скрипте,
  где она стоит запросом к разметке, — и отвечает «есть» про то, чего в самой
  разметке нет. Так проверялись `enablejsapi` (нашлась в тексте скрипта)
  и `data-seek="youtube"` (то же самое): обе сказали «всё на месте», обе
  соврали. Спрашивать надо про конкретный тег: `<section class="…"[^>]*>`,
  `<iframe[^>]*src="…"`. **За две сессии проверка соврала трижды**, и каждый
  раз в сторону «всё хорошо».
- **У запроса к живому сайту сначала смотрим КОД ОТВЕТА, потом содержимое.**
  Наступили дважды за одну сессию, и оба раза проверка соврала уверенно.
  Пустое тело у `/admin/index.html` — это не «файла нет», а переадресация
  на `/admin/`, за которой надо идти отдельно (`curl -L`). Непустое тело
  у старого файла стилей — это не «правило на месте», а **404**: у ошибки
  тело не пустое, там страница-заглушка, и искомое слово нашлось в ней.
  Тело без кода ответа врёт в обе стороны сразу.
- **API Sveltia сверять по её коду, а не по документации Decap.** Совместимость
  неполная, расходятся молча: в поле приходит `{ value, field, forID, … }`,
  никакого `props.entry`. На этом все новые поля были глухими.
- **Предпросмотр своей кнопки не должен начинаться с HTML-тега.** Sveltia зовёт
  `toPreview` с ПУСТЫМИ данными, берёт первый тег ответа и после этого
  перехватывает все такие теги при вставке (`importDOM`). Наши кнопки отдавали
  `<div>` и `<span>` — и текст, скопированный из соцсетей, при вставке
  рассыпался на наши блоки: каждый `<span>` становился плашкой «Аниме
  (не выбрано)». В документации Decap об этом нет ни слова.
- **Картинки из админки — строкой и своим сжатием, не через `image()` Astro.**
  CMS кладёт файлы в `public/`, а `image()` их не видит: сборка падает целиком
  с `ImageNotFound`. Поле `cover` пролежало такой миной, пока его не было
  в админке.
- **Молчание не должно значить две разные вещи.** Метки времени не было и у
  короткой заметки, и у выпуска, не нашедшего себя в RSS, — читатель различить
  их не мог. Если нечего сказать по двум разным причинам, хотя бы одна обязана
  сказать о себе вслух («меньше 3 мин читать»).
- **«Пусто» и «намеренно ничего» — разные состояния, и путать их нельзя.**
  Пустая обложка значит «подбери сам», галочка «Без обложки» — «картинки быть
  не должно». Одним полем это не выражается, нужен отдельный флаг.
- **Значение, уезжающее в атрибут строкой, проверять на пусто.** У материала
  без своего описания и без подходящего первого абзаца `postDescription`
  возвращает пустоту, и метка для поиска уехала в индекс словом «undefined» —
  ровно так оно и печаталось в выдаче. Шаблонная строка не падает никогда,
  она просто подставляет туда слово.
- **Схема обязана переживать пустую строку в любом необязательном поле.**
  CMS пишет `""`, а не пропускает поле; `z.coerce.date("")` роняло сборку
  целиком. Обычным сохранением поста можно было положить сайт, и тихо.
- **Открытая вкладка админки держит СВОЮ копию поста и перезапишет мою правку
  молча.** Правило «забрать правки заказчика перед работой» знает только одну
  сторону гонки. Вторая: вкладка, открытая до моей правки файла, при сохранении
  запишет поверх то, что скачала когда-то. Так вернулся в тело список
  таймкодов `ep-102` и опустело поле — **тело после сохранения совпало
  побайтно с телом ДО правки**, то есть админка мой файл даже не читала.
  Выглядит это как «формат записи не подошёл», а формат тут ни при чём.
  Значит: правя файлы, которые есть в админке, **сказать заказчику закрыть её
  и открыть заново** — не перейти по ссылке, а перезагрузить, ей надо скачать
  посты с GitHub. И проверять по первопричине: совпало ли тело с дозаписочным.
- **Длинных строк с переносом (`>-`) Sveltia не пишет — она пишет одной
  строкой.** Заведённый руками файл с аккуратными переносами она при первом же
  сохранении разложит по-своему, и коммит придёт с разницей на весь файл.
  Данные при этом целы, ломаться нечему — но **проверка «пустой коммит»
  на таком файле не работает, пока он не сохранён хоть раз**. Заводя файл
  руками, писать длинные значения одной строкой.
- **Сохранение в админке без изменений — лучшая проверка своего формата.**
  Если моя запись совпала с тем, что пишет Sveltia, коммит от неё приходит
  **пустой, с нулём изменённых файлов**. Расхождение в один пробел дало бы
  разницу на весь файл. Дешевле любой сверки глазами: записать один пост,
  попросить сохранить, посмотреть `git show --stat`.
- **Одно сохранение CMS = один файл.** Поля, которым нужно писать в два файла,
  не делать вовсе — обходной путь через прямые коммиты в GitHub даёт
  расползание данных.
- **Не пускать CMS в дорогие данные.** Она переписывает файл целиком. Всё,
  что правится руками, — компактной строкой в самом посте; оплаченные реплики
  транскрипта лежат отдельно и CMS их не трогает.
- **Полку опознавать по её собственным полям, а не «всё остальное — пост».**
  Обработчик сохранения делил записи на «тайтл» и «всё прочее», и первая же
  новая полка («О подкасте») стала получать чужое поле `anime`. Проверка
  на остатке ломается ровно тогда, когда добавляют третью сущность.
- **Списки внутри своего компонента CMS сохраняет ненадёжно** (галерея, тайтлы —
  дважды теряла и портила данные). Решение: маркер в тексте, вся логика
  на стороне сайта при сборке. **Ровно внутри своего — встроенный `list`
  работает нормально** («Кнопки» у поста, «Ведущие» на странице «О подкасте»,
  проверено руками). Не расширять это правило на все списки подряд.

### Astro и сборка

- **В коде из `src/lib/` не полагаться на `import.meta.url` и пути к файлам.**
  Сборщик их меняет, проверка молча отвечает «нет». Списки данных класть
  отдельным `.js` (не `.json` — его по-разному импортируют node и Astro).
- **Помнить лимит 20 000 файлов.** Отдельный индекс по 24 900 репликам упёрся
  бы в него сразу; после каждого этапа считать файлы в сборке и говорить запас.
- **Число файлов в сборке гуляет на ±3**: превью-обложки выпусков делаются
  из скачанных по сети картинок, и при сбое сети их выходит меньше. Запас
  считать по большей цифре, разброс в пару файлов паникой не считать.
- **Внутри одного файла правило проигрывает по весу соседнему.** Не только
  `hidden`: `.pagination-status{display:none}` (один класс) не пересиливает
  `.pagination span{…}` (класс плюс тег) двумя строками выше. И то же самое
  сломало сетку архива: базовое `.list-grid:not([hidden])` весит больше, чем
  `.list-grid` в медиазапросах, поэтому число колонок не применялось вовсе —
  список ехал в одну колонку на любой ширине, а вертикальные линии (селектор
  длиннее) сдвигали каждую вторую карточку вправо. **Правило: все правила
  одного компонента пишутся ОДНОЙ формой селектора**; уточнение вроде `:not`
  ставится либо везде, либо нигде. Лечить весом нельзя — пометка приоритета
  запрещена. **И проверять это не глазами:** разбором собранного CSS, который
  считает вес всех правил свойства и говорит, какое побеждает на каждой ширине.
- **Две строки текста в одной линейке выравниваются по базовой линии,
  а не по центру.** `align-items: center` выравнивает КОРОБКИ: разойдись их
  высоты на пиксель — от другой гарнитуры у стрелки, от округления строки, —
  и текст встанет на разной высоте при одинаковом кегле. Выглядит как съехавшая
  вёрстка, а причина невидима. `align-items: baseline`.
  **Читать это надо как «базовую линию задаём ЯВНО», а не как «не пишите
  center».** Второй раз грабли сработали там, где `center` не было вовсе:
  в строке врезки со ссылками стояло значение по умолчанию, то есть по верху
  коробок, — и адрес 14 px встал заметно ниже подписи 11 px. Нашёл заказчик
  глазами на живой странице. Разные кегли в одной линейке — всегда `baseline`.
- **`margin-top: auto` не заменяет отступ.** Прижатие к низу колонки
  схлопывается в ноль, как только содержимое переросло место, — и прижатый блок
  встаёт вплотную к соседу. Зазор задаётся `padding` обёртки: его auto-margin
  не съедает.
- **Внутри контейнера, где дети центруются `margin-inline: auto`, сокращённый
  `margin` писать нельзя.** Он сбрасывает боковые поля в ноль, и всё
  содержимое молча уезжает к левому краю. Ошибки нет, ширина правильная,
  а колонка стоит не по центру. Пишется `margin-block`.
- **Медиа «до краёв экрана» считается от полей страницы, а не от `100vw`.**
  Ширина окна включает место под полосу прокрутки (`scrollbar-gutter: stable`),
  поэтому `100vw` шире документа — и картинка во всю ширину сама создаёт
  тот горизонтальный скролл, который на сайте запрещено прятать.
- **`content-visibility: auto` врёт про высоту, пока блок за кромкой экрана.**
  Содержимое не разложено, `scrollHeight` равен видимой высоте — и проверка
  «есть ли что прокручивать» отвечает «нет». Решать по классу состояния,
  а не по измерению; а если мерить всё-таки надо — после кадра отрисовки,
  и не одного: обработчики кадра выполняются ДО пересчёта раскладки.
- **Ширина окна зависит от длины страницы.** Короткая страница не прокручивается,
  браузер убирает полосу прокрутки, окно становится шире — и всё, что
  центрируется по окну, съезжает вбок. Выглядит как поломка вёрстки конкретной
  страницы. Лечится `scrollbar-gutter: stable` один раз на весь сайт.
- **Текст для поисковика и текст для читателя — разные тексты.** Описание
  раздела из метатега, поставленное подводкой на страницу, сделало шапки разделов
  разной высоты (62 знака против 100), и список под ними прыгал при переключении
  вкладок. **Длина такой подводки — часть вёрстки**, и диапазон надо записывать
  рядом с самим текстом, иначе его нарушит первая же правка.
- **Подпись блока ВНУТРИ МАТЕРИАЛА — обычным весом и в квадратных скобках.**
  Это `[ о выпуске ]`, `[ о видеоэссе ]`, `[ аудиоверсия ]`, `[ таймкоды ]`,
  `[ галерея ]` — одна сущность, один вид (`.body-label` и `.gallery-kicker`
  в `global.css`). **Скобки рисует CSS одним правилом, руками их не пишем:**
  вписанные в разметку, они разошлись бы с первой же новой подписью, а заодно
  лезли бы в цитаты выдачи поиска.
  **Это отмена прежнего правила, и вот почему.** Раньше подпись блока
  набиралась полужирным, а данные обычным — так было в макетах, и так было
  записано здесь с оговоркой «выглядит как разнобой ровно там, где на экране
  видна одна подпись и ни одной второй». Как только на странице видеоэссе
  сошлись оглавление и аудиоверсия, разнобой стало видно, и заказчик его
  увидел. Оговорка сработала — правило отменено 9 августа 2026.
  **Полужирный в техническом слое остаётся у надзаголовков СЕКЦИЙ:**
  `[ короткие заметки ]`, `[ из архива ]`, `Материалы` у фильтров,
  надзаголовки архива и каталога, «Упоминается в материале». Обычные, как
  и были: метастрока материала `[ подкаст ] · №147 · 31:27`, `CAT. 001`, даты,
  счётчики. Дизайн-система вес технического слоя не задаёт вовсе — в §3.2
  только кегль, интерлиньяж, трекинг и капслок, поэтому решение за заказчиком.
- **Рамкой линию от края не отодвинуть — это делает псевдоэлемент.** В сайдбаре
  главной вертикальную линию рисует колонка, а карточки лежат внутри её поля,
  и линии не встречаются. В архиве обе линии рисовала одна карточка
  (`border-left` и `border-top`), а рамка всегда идёт от края коробки — линии
  обязаны сойтись углом, и лента читается таблицей. Горизонтальную линию
  рисуем псевдоэлементом со сдвигом на величину отступа, а саму величину
  держим переменной рядом с `padding-left`: это одно число, и копий у него
  быть не должно.
- **Уточнение `:not([hidden])` поднимает вес ВСЕГО правила — и оно начинает
  перебивать чужие.** Лечили одно: чтобы атрибут «скрыто» не проигрывал
  `display` компонента. Сломали другое: правило карточки стало весить столько
  же, сколько правило общей сетки, а стоит в документе позже — и его
  `padding` целиком победил `padding-left`, которым сетка отодвигает текст
  от вертикальной линии между колонками. Текст прилип к разделителю сразу
  на трёх страницах, а разметка и оба правила по отдельности были правильные.
  **Сначала смотреть, нужен ли `display` вообще:** ребёнок сетки и так
  становится блочным, а у правила без `display` спорить с `hidden` нечему —
  и вес остаётся прежним. Уточнять — только когда `display` действительно
  нужен.
- **Атрибут `hidden` проигрывает по весу любому `display` из компонента.**
  Селектор `[hidden]` — это один атрибут, а правило компонента в Astro всегда
  длиннее (`.grid[data-astro-cid-x]`), и `display: grid` побеждает. Разметка
  при этом правильная, атрибут на месте, а на странице скрытое видно.
  Лечится `:not([hidden])` прямо в правиле раскладки. **Эти грабли сработали
  трижды** — сетки режимов на главной, плашка «не удалось загрузить аудио»
  поверх играющего плеера, строка «показаны все упоминания тайтла», висевшая
  всегда, — и каждый раз их находил заказчик глазами. Теперь есть проверка:
  `node scripts/check-hidden.mjs` после сборки разбирает собранный CSS и
  говорит, где `hidden` не сработает. **Гонять её вместе с пятью проверками
  раздела 8.4.**
- **Разметку, сделанную remark-плагином, стили компонента не видят.** Astro
  метит своей меткой только то, что написано в самом файле, — а блок, собранный
  плагином при разборе markdown, приходит без метки. Значит вид, общий у блока
  из разметки и у блока из плагина, описывается через `:global`, **и ВСЕ его
  правила пишутся этой формой**, включая медиазапросы: смешаешь `:global(.x)`
  с голым `.x` — правила разойдутся по весу и часть перестанет применяться
  молча. Соблазн вместо этого написать вторую копию стилей рядом с плагином
  силён и всегда неправильный: два блока, обязанные выглядеть одинаково,
  разъезжаются с первой правки.
- **Набор символов для обрезки шрифта сверять с реально используемыми знаками**
  в `src/`, а не брать типовой список. В заказанном наборе не было `▶ → ← ↗`,
  которые сайт уже рисует. И проверять, что знак вообще нарисован в гарнитуре:
  `⏸` и `✕` не нарисованы ни в Literata, ни в Inter, ни в Plex Mono.
  **Мало положить знак в файл — его надо пустить `unicode-range`'ем.** Диапазон
  решает, брать ли гарнитуру для знака, ещё ДО того, как выяснится, что знак
  в ней есть: `← → ↗ ▶` лежали в файлах, но в диапазон не попали и полгода
  рисовались системным шрифтом. Сверять диапазон с `cmap` самих файлов
  (`fontTools`), а не с памятью.

### Инфраструктура и деплой

- **Добавляя `routes` воркеру, сначала посмотреть, кто ходит на его
  `workers.dev`-адрес** — деплой его молча отключает. Так чуть не умерла сверка
  названий с Hetzner; `publish-cron` и `baki-cms-auth` спасает явное
  `"workers_dev": true`.
- **Смена домена ломает не только ссылки.** Список `ALLOWED_DOMAINS` у воркера
  входа в админку правится только в панели Cloudflare, и без него вход умирает.
- **Файл `_redirects` у Workers не умеет переезд между доменами** («Domain-level
  redirects ❌» в документации). Редирект www → голый домен делается правилом
  в панели Cloudflare, а не файлом в репозитории.
- **«Первый раз висит, второй работает» — это не код, а протокол, который
  сервер обещает, а брандмауэр режет.** Caddy включает HTTP/3 сам и пишет
  в каждом ответе `alt-svc: h3=":443"`, а `ufw` был открыт только на
  `443/tcp` — весь UDP молча выбрасывался. Браузер запоминает обещание
  на 30 дней, при первой загрузке идёт по UDP, ждёт в тишине и показывает
  пустой плеер; не дождавшись, помечает HTTP/3 сломанным и на перезагрузке
  идёт по TCP — и всё работает. **Признак ровно этот: перезагрузка лечит.**
  Лечится `ufw allow 443/udp`. **И проверяется без браузера:** послать на порт
  пакет QUIC с несуществующей версией — сервер обязан ответить списком
  поддерживаемых. Ответ есть — UDP проходит. `curl` тут бесполезен: он ходит
  по TCP и говорит «всё хорошо».
- **Сторожевые команды: `pgrep -f "[p]ipeline.py"`**, иначе проверка находит
  сама себя. И не путать «процесса нет» с «ssh не достучался» (код 255) —
  сверяться по `state.json` или по строке итога в логе.
- **Долгие прогоны — через `nohup`**, и включать построчный вывод
  (`line_buffering`), иначе лог многочасового прогона остаётся пустым.
- **Скрипт копировать на сервер вместе с зависимостями** (`pipeline.py` без
  папки `providers/` не запускается) — автосинхронизации нет.
- **macOS хранит «й» в именах файлов разложенной** — перед сравнением имён
  `unicodedata.normalize('NFC', …)`.
- **Сопоставления фиксировать файлом, а не считать на лету.** Переименованный
  сценарий молча увёл бы текст к другому выпуску (`essay-map.json`).

## Куда что писать

- **`CLAUDE.md`** — выводы и правила: то, чему надо следовать всегда. Наступили
  на грабли — правило в раздел «Уроки проекта», одной-двумя строками.
- **`СТАТУС.md`** — только сводка: что готово по этапам, где что лежит, ключевые
  адреса, текущие хвосты и невылеченные болячки. Держать в районе 150 строк.
  **Это оглавление, а не справочник:** любой список, который растёт от сессии
  к сессии, переезжает в `статус/` отдельным файлом, а в сводке остаётся
  строчка-указатель. Так уже вынесены три:
  [карта-кода](статус/карта-кода.md) (где какое правило живёт),
  [хвосты-и-болячки](статус/хвосты-и-болячки.md) (подробности к спискам)
  и [что-смотреть](статус/что-смотреть.md) (проверка руками по частям).
- **`статус/этап-N.md`** — подробности сессии: как устроено, что проверено и чем,
  какие решения приняты и почему. Растёт свободно, читается по ссылке из сводки.
  Новый файл — новая ссылка в сводке.
- **Разъехавшийся факт чинится в обоих местах сразу.** Сводка живёт дольше
  подробностей и устаревает незаметно: строчка «шрифты лежат, но в CSS
  не подключены» пережила ту часть, где их подключили. Меняете поведение —
  ищите, где о нём написано, а не только где оно написано кодом.
