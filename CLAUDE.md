- **ВЫКЛАДЫВАЕТ САЙТ ПУШ, А НЕ ТЫ. Механизмов ДВА, и это надо знать наизусть.**
  *(Так было до пометки «спам» и так снова станет, когда её снимут.)*
  Основной: Cloudflare собирает и выкладывает сайт САМ при каждом пуше (Workers
  Builds), 52–79 секунд от коммита до живого сайта. Именно поэтому правка
  из админки появляется, когда никого нет за компьютером. **Запасной:
  `npx wrangler deploy` с машины — он кладёт поверх сборку из МЕСТНОЙ папки
  `dist/`, и кто выложил позже, тот и на сайте.** Запасной оставлен решением
  заказчика: им можно выложить, не пушив.
  **Отсюда весь класс старых граблей «выложил, не забрав правки».** Причина
  не в забытом `git pull`, а в том, что выкладок две и побеждает поздняя:
  ручная выкладка из копии без свежих правок затирает правильную сборку
  Cloudflare, и выглядит это ровно как «правка молча пропала».
  **Правила пользования запасным — три, и все обязательны:**
  1. **`git pull` перед ним.** Заказчик правит посты в админке, а она коммитит
     прямо в репозиторий. Наступили: пуш отказал из-за чужих коммитов уже ПОСЛЕ
     того, как деплой ушёл.
  2. **Смотреть на исход `pull`, а не только запускать его,** и не ставить
     деплой с ним в одну цепочку через `&&`. Разошлось — `pull --rebase`.
  3. **`npm run build` после `pull`, всегда.** Выкладка берёт готовую папку
     `dist/`, а не репозиторий: собрал, потом забрал правки, потом выложил —
     на сайт уехала сборка БЕЗ них. Порядок один: **pull → build → deploy.**
  **Обычной работе всё это не нужно:** закоммитил, запушил, через минуту
  на сайте. Тянись за `wrangler deploy` только тогда, когда правда нужно
  выложить без пуша или когда сборка Cloudflare молча упала.
- **Сначала выложить на сайт, потом писать документацию.** Как только код
  работает и проверен — коммит и пуш, и сразу сказать мне адрес и что нажать.
  Документацию (`статус/`, `СТАТУС.md`, `CLAUDE.md`) писать уже после: пока ты
  её пишешь, я успеваю проверить результат вживую, и если что-то не так —
  правка попадёт в ту же сессию, а не в следующую.
  Порядок именно такой: **работает → выложено → рассказано → записано.**

- **Не забегай вперёд.** Делай только текущий этап, даже если видишь,

## Цель проекта

Сайт-витрина подкаста: посты, выпуски, транскрипты и связи между ними через
упоминания аниме. Главная фишка — клик по названию тайтла открывает страницу
со всеми постами и выпусками, где он упоминался, вплоть до минуты в разговоре.

## Стек

- **Astro** — статический генератор
- **Sveltia CMS** (или Decap CMS) — админка на `/admin`, логин через GitHub
- **GitHub** — код и контент, GitHub Actions для роботов
- **Cloudflare Workers со статическими файлами** — хостинг сайта и автосборка.
  Не Pages: с 2026 года Cloudflare рекомендует новым проектам сразу Workers,
  возможности у них те же, а развивают только Workers
- **Cloudflare Workers** — сервис-посредник для логина в админку через GitHub
- **Hetzner** (мой сервер) — свои видеофайлы, тяжёлые скрипты, архивы
- **Shikimori API** — данные об аниме, русские названия; **AniList** — запасной
- **Pagefind** — поиск

## Модель данных

### Пост (`src/content/posts/*.md`)

Единая сущность для всего. Выпуск подкаста — тоже пост, с категорией `podcast`.

| Поле | Описание |
|---|---|
| `title` | Заголовок |
| `date` | Дата публикации |
| `category` | `podcast`, `videoessay`, `note`, `review`, `interview`, `bonus` |
| `cover` | Обложка для ленты и соцсетей. **С 12 августа 2026 показывается и в начале текста — но только если картинок в тексте нет ни одной** (не у выпусков, бонусов и видеоэссе: там своя картинка сверху). Раньше на странице поста не выводилась никогда, довод был «там картинка уже есть» — у обзоров, написанных руками, её нет вовсе, и страница открывалась голым заголовком. Отменено решением заказчика, механизм — `src/plugins/remark-lead-cover.mjs`. Путь строкой (`/images/uploads/…`), не `image()` Astro |
| `noCover` | «Обложки нет намеренно» — заметка идёт в ленте одним заголовком. Не то же самое, что пустой `cover` («подбери сам») |
| `anime` | Массив ID тайтлов; заполняется автоматически из разметки в тексте |
| `audioGuid` | Для категории `podcast` — привязка к элементу RSS |
| `externalUrl` | Статья вышла на чужом сайте. **Своей страницы у такого поста не создаётся вовсе**, карточка в ленте ведёт наружу. Признак, а не категория — работает поверх любой |
| `externalSource` | Название площадки («Кинопоиск»). Пусто — подставляется по домену |
| `buttons` | Кнопки: подпись + ссылка + стиль |
| `transcript` | Какую расшифровку прицепить. **Пусто почти всегда:** файл ищется по `audioGuid`. Заполняется только там, где записи в RSS нет вовсе — у видеоэссе с одного YouTube. Поле в админке с 15 августа 2026 |
| `script` | Готовый сценарий (для видеоэссе) |
| `draft` | `true` = виден только в админке |
| тело | Markdown |

Тип медиа (текст / галерея / видео) не задаётся руками — выводится из содержимого.
Категория задаёт редакционный формат и фильтры в ленте.

**ВРЕЗКА НА ДРУГОЙ НАШ МАТЕРИАЛ ставится кнопкой «Наш материал»** в меню
редактора, рядом с «Изображением», «Видео», «Подписью блока», «Ссылкой
врезкой», «Спойлером» и «Аниме» (задача 33, 31 августа 2026). В файл ложится
`::material{id="ep-152"}` — **и это ЕДИНСТВЕННАЯ вставка проекта, которая
хранит ссылку, а не данные.** Заголовок, обложка, длительность, номер выпуска
и время чтения берутся из коллекции при сборке, поэтому переименованный
выпуск меняет название во всех врезках архива сам. Сохрани мы заголовок
в файл — он соврал бы при первом переименовании, **и сборка бы не упала.**

Видов три и различаются они ДЕЙСТВИЕМ: врезка указывает (линии нет),
мини-плеер и фасад видеоэссе играют на месте (линия снизу есть). «Играет
здесь» бывает только у выпуска подкаста и у видеоэссе — у статьи, заметки,
бонуса и материала с чужого сайта играть нечего, и такую врезку **выкладка
не пропустит**: `scripts/check-post-refs.mjs` стоит первым шагом
`npm run build`. Почему заслон отдельным скриптом, а не броском ошибки
из плагина, — урок ниже, он оплачен пропавшим текстом статьи.

Не путать со «Ссылкой врезкой»: та ведёт на ЧУЖОЙ адрес и складывается
с соседними в один список. Имена разведены нарочно — слова «ссылка» в новом
пункте нет, слова «материал» в старом.

**ПОЛЕЙ «ССЫЛКА НА РОЛИК» И «СВОЁ ВИДЕО» В ПОСТЕ БОЛЬШЕ НЕТ** (решение
заказчика 15 августа 2026). Они ставили окошко в ШАПКУ материала и были
первоначальным замыслом «ролик у поста один»; на деле роликов бывает
несколько и стоят они по ходу рассказа. Видео вставляется **кнопкой «Видео»
в редакторе** — блоком `::video{youtube="…"}` или `::video{video="…"}` прямо
в текст; так сделано 112 постов. Вид у двух путей совпадал нарочно, то есть
двери вели в одну комнату, а заполнены поля были у нуля постов из 747.

### Тайтл (`src/content/anime/*.json`)

`id` (slug), `shikimoriId`, `titleRu`, `titleOriginal`, `year`, `studio`,
`poster`, `synopsis`, `url`, `aliases`.

**`aliases` — варианты написания, по которым тоже ищутся упоминания**,
правятся в админке. Нужны для трёх случаев: падежи («Ходячего замка»),
как говорят вслух («K-On!» вместо «Кэйон!»), как искажает распознавание
(«Фринен» вместо «Фрирен»). Вариант, вписанный один раз, начинает ловиться
во всём архиве сразу и во всех будущих постах — пересчёт идёт при сборке,
распознавание заново гонять не нужно. Симметрично исключениям упоминаний
из этапа 5: варианты добавляют упоминания, исключения убирают.

**Что правится в админке вручную:** `titleRu`, `synopsis`, `poster`, `aliases`.
Описание из Shikimori бывает сухим или со спойлерами, русское название иногда
не приходит вовсе (AniList), обложка попадается неудачная.

**Правленое вручную поле не перезаписывать при обновлении из API.** Признак
хранить по каждому полю отдельно, а не на всю карточку: описание я перепишу
своими словами, а обложку захочу обновлять автоматически. При пересчёте
справочника такое поле остаётся моим, а в лог идёт строчка, что данные из API
для него проигнорированы.

### Транскрипт (`src/content/transcripts/*.json`)

Массив реплик: `start`, `end`, `speaker`, `text`. Отдельно — карта спикеров
(`speaker_0` → имя) и флаг источника: распознано / выровнено по сценарию.

## Ограничения хостинга (учитывать на всех этапах)

Бесплатный план Cloudflare: трафик не лимитирован, но **не более 20 000 файлов
на сайт** и не более 25 МБ на файл (на платном плане — 100 000 файлов).

Двадцать тысяч звучит много, но Astro генерирует файл на каждую страницу плюс
вариант каждой картинки под каждый размер экрана. При архиве в сотни выпусков
с транскриптами это реально исчерпать. Поэтому:

- каждую картинку пережимать максимум в **два размера**, не в четыре;
- оригиналы медиа, видео и экспорт телеграма хранить на Hetzner,
  в репозиторий класть только то, что реально выводится на страницах;
- после каждого этапа показывать мне, сколько файлов в сборке,
  чтобы я видел запас.

## Место на сервере

На Hetzner у меня **40 ГБ на всё**, включая систему. Отсюда правила:

- Аудио выпусков не хранить. Для транскрибации скачивать по одному файлу,
  отправлять на распознавание и **сразу удалять**. Не выкачивать архив целиком.
- Перед любой массовой операцией проверять свободное место и говорить мне,
  сколько её потребуется.
- Видеоэссе по умолчанию живут на YouTube и встраиваются по ссылке.
  Свои файлы — только для того, что на YouTube выложить нельзя.
- Экспорт телеграма и оригиналы картинок в git-репозиторий не класть никогда.

## Границы

Не делаем: комментарии, рассылку, личные кабинеты, платный контент,
мобильное приложение, английскую версию.

**Опубликованные посты не правим.** Текст, фронтматтер и вставки
в опубликованном посте меняет только заказчик, в админке.

**Исключение — проект «Перелинковка»** (с 24 сентября 2026, расширено
25 сентября). Опубликованные посты меняет только вставлялка, и разрешено ей
ровно два вида правок:
1. **Добавить блок `::material{…}`** в месте, которое заказчик одобрил
   на странице ревью.
2. **Снять обычную ссылку, повторяющую вставку**: ссылка стоит в том абзаце,
   сразу после которого идёт одобренная вставка, и ведёт на ту же цель
   (страница материала на сайте в любом написании адреса, его пост
   в Telegram или его ролик на YouTube, встроенный в пост блоком видео). Снимается одним из двух способов: убрать разметку ссылки,
   оставив её слова как есть, **или** заменить фрагмент со ссылкой (в пределах
   её предложения) текстом, который заказчик сам вписал на странице ревью.
   Ссылки в других абзацах и на другие цели не трогаются.

Больше ничего: текст, фронтматтер и существующие вставки не меняются.
В бонусы вставки не ставятся — значит, и ссылки там не снимаются. Каждая
правка записывается в журнал, и `verify-diff.mjs` сверяет с ним файл
побайтно: хоть одно отличие, которого нет в журнале, — стоп, файл
возвращается, пачка не выкладывается. Материалы проекта — `~/baka-audit/crosslinks/` (вне
репозитория). Скрипты проекта — `scripts/crosslinks/`. Одобренные решения —
`статус/перелинковка/`. Страница ревью — `npm run crosslinks:review` (только
`127.0.0.1`; пишет ровно два файла — `статус/перелинковка/решения.json`
и `отклонено.json`, в посты не пишет ничего).

**В посты пишет ТОЛЬКО вставлялка** — `npm run crosslinks:apply -- --batch N`
(или `--posts a,b`, `--keys …`). Она вставляет блоки и снимает ссылки-дубли
по решениям страницы ревью (поле `unlink`). Без `--write` — сухой прогон,
с ним — запись и сразу побайтная проверка диффа по журналу
(`scripts/crosslinks/verify-diff.mjs`): красный свет — файл возвращается сам.
Руками посты не правим никогда. **Перед `--write` заказчик закрывает ВСЕ
вкладки админки** — открытая вкладка сохранит свою копию поста поверх вставки
молча. Порядок пачки: ревью на странице → сухой прогон → закрыть админку →
`--write` → `npm run build` → глазами локально → **ОДИН коммит пачки: посты
и `вставлено.json`** → pull → push → выкладка заказчиком. Номер коммита
в журнал больше не пишется (решение заказчика 25.09.2026); коммит пачки
находится так: `git log -- статус/перелинковка/вставлено.json`. **Откат пачки —
одна команда:** `git revert --no-edit <коммит-пачки>` (проверено 25.09.2026
на пачке 1: посты и журнал вернулись побайтно). Пилот сессии 3 — старый
порядок, два коммита: `git revert --no-edit 7fff8969 939ccef8`.
**Отложенное решение пост не закрывает:** пост пройден, только когда по всем
его основным есть «одобрено» или «отклонено».
**Страница ревью, пока открыта, держит решения в памяти** — править
`решения.json` руками можно только при остановленной странице. И на ней каждая
буква — команда: текст, набранный не в том окне, меняет решения (так дважды
стёрлось решение 25.09.2026). Подробно — `статус/задача-38-перелинковка-вставка.md`.

## Как проверяем работу (правило на весь проект)

**Расширение Chrome для проверки страниц в этом проекте не используется.**
Оно не работало, и заказчик просил к нему не возвращаться. Значит:

- проверяем тем, что работает без браузера: проходит ли сборка, есть ли
  нужная разметка в собранных файлах (`dist/`), прогоняем логику в Node
  на реальных данных, считаем размеры файлов;
- **всё, что живёт в браузере — клики, поиск, раскрытие блоков, вид на
  телефоне, — проверяет заказчик руками.** Значит после каждой такой правки
  надо прямо говорить: вот адрес, вот что нажать, вот что должно произойти;
- в `СТАТУС.md` честно писать, что проверено, а что нет. Не выдавать
  «разметка на месте» за «работает».

Локальный сервер для ручной проверки: `npm run build`, затем `npm run preview`
(адрес он печатает сам — обычно `http://localhost:4321/`, а если порт занят,
берёт следующий).

### Деньги и внешние сервисы

- **Цену платной операции брать из реального списания в кабинете сервиса**,
  не из формулы в коде и не из чужих обзоров. Константа `CREDITS_PER_MINUTE`
  завышала расход в 12 раз, и из-за неё этап чуть не переехал на другой сервис.
- **Результат платной операции записывать на диск сразу**, до любых
  необязательных шагов. Сверка названий ходила в сеть уже после оплаты —
  сбой сети означал бы вторую оплату того же выпуска.
- **Платный шаг и бесплатный пересчёт разделять, сырые данные сохранять.**
  Пословные данные распознавания весят 20–80 КБ и позволяют переразбить
  реплики бесплатно; без них любая правка правил — повторная оплата архива.
- **Перед тратой спрашивать подтверждение**, а из-под `nohup` без явного
  `--yes` не запускаться совсем.
- **«ЗА ЭТО УЖЕ ПЛАТИЛИ?» НЕЛЬЗЯ СПРАШИВАТЬ У ФАЙЛА, КОТОРОГО НЕТ
  В РЕПОЗИТОРИИ.** Журнал расшифровки лежал рядом со скриптом и был закрыт
  `.gitignore` — то есть существовал ровно на той машине, где шла работа.
  На машине заказчика в нём одна запись при 142 готовых расшифровках
  в репозитории; замер: старое правило запросило бы **$25.64 за 108 уже
  оплаченных выпусков**. Спрашивать надо ВСЕ источники разом, и первым —
  тот, что переживает потерю сервера: готовый результат в git, у которого
  имя файла и есть ключ. **И «источника нет» обязано отличаться
  от «не оплачено»** — молча приравняв первое ко второму, платишь дважды.
- **Журнал платежей пишется ЦЕЛИКОМ ИЛИ НИКАК.** Прямая запись поверх файла
  сначала обрезает его, потом наполняет; обрыв ровно в этот миг оставляет
  огрызок, который не читается, — а что там было, знал только он сам. Пишем
  во временный файл рядом и переставляем имя.
- **У одного сервиса бывает два API, и они расходятся.** →
  [история](статус/уроки-подробно.md)
- **Обложку из запасного источника брать только со сверкой названия.** Поиск
  по имени легко приводит к сиквелу, спешлу или ремейку, а чужая обложка хуже
  отсутствующей: она выглядит правильной и не будет замечена никогда.
  Не совпало — не берём и говорим в лог.
- **Поисковый движок проверять запуском движка, а не чтением его выдачи в
  разметке.** → [история](статус/уроки-подробно.md)
- **Поисковый движок, не найдя слова, отрезает у него хвост.** →
  [история](статус/уроки-подробно.md)
- **Результат поиска нельзя запоминать между запросами.** В куске индекса
  лежит не только текст страницы, но и места совпадений с отрывком — они
  посчитаны под конкретный запрос, а ключ у куска один и тот же на все.
  Память, пережившая запрос, показывает чужие подсветки и чужие цитаты:
  адрес, заголовок и картинка при этом правильные, поэтому подмену не видно.
- **Отрывок вокруг найденного слова — не то же самое, что описание материала.**
  Отрывок цепляет служебное начало страницы («] · №135. … Пампам. 12:04 —
  Новый блок. Транскрипт.») и в выдаче нечитаем. Под заголовком ставим
  описание, которое уже есть у материала, а место находки показываем отдельной
  группой результатов.
- **Догадка, записанная в ТЗ, — всё равно догадка, и проверять её надо
  замером.** → [история](статус/уроки-подробно.md)
- **Проверять по первоисточнику, а не по ТЗ, документации и своей памяти.**
  Модель `scribe_v1` из ТЗ была снята с поддержки; поля Shikimori проверялись
  запросом к API; параметры сжатия картинок у хостинга — восемью реальными
  запросами, прежде чем решить, что он так не умеет.
- **«КАЖДЫЙ ПРОСМОТР КАЧАЕТ ВСЁ ЗАНОВО» ПРОВЕРЯЕТСЯ УСЛОВНЫМ ЗАПРОСОМ, А НЕ
  ЧТЕНИЕМ ЗАГОЛОВКА.** `max-age=0, must-revalidate` заставляет браузер
  ПЕРЕСПРОСИТЬ, а не перекачать: вернувшийся читатель предъявляет отпечаток
  и получает 304 и ноль байт. Оценка расхода, на которой стояла целая правка,
  опровергнута двумя командами: 200 и 13 484 байта против 304 и нуля. Цену
  трафика спрашивают у сервера, а не у названия заголовка.
- **Кэш ускоряет читателя, но от травли не защищает совсем.** Кто пришёл
  разорить — кэш не использует: качает заново каждый раз, и заголовки ему
  не указ. От счётчика без потолка защищает ровно одно: предел расходов
  в кабинете сервиса. Путать эти две вещи опасно вдвойне — правка кэша
  ВЫГЛЯДИТ защитой и позволяет отложить настоящую.

### Проверка и приёмка

- **Готово — только после проверки руками в браузере.** «Разметка на месте
  в `dist/`» это не «работает». Писать явно: вот адрес, вот что нажать.
- **Забрать правки заказчика — половина дела: после `git pull` НАДО
  ПЕРЕСОБРАТЬ.** → [история](статус/уроки-подробно.md)
- **Убеждаться, что запушено, а не только закоммичено.** Однажды на GitHub
  не уехало 37 коммитов, и «вторая копия транскриптов вне сервера» три недели
  была фикцией. Плюс отдельно проверять, что новые файлы попали в коммит:
  правка `publish-cron/` была описана и задеплоена, а в репозиторий не попала.
- **Любую новую формулу гонять по всему архиву, а не на паре примеров.**
  Выпуск на 18 секунд округлялся в «0 мин слушать» — нашлось только прогоном
  по всем 145 постам.
- **Пороги и лимиты подбирать замером на живых данных.** Порог блока 90 секунд,
  8 минут в карточке тайтла, `MIN_IMPROV_WORDS = 3`, лимит длины подзаголовка —
  все выведены из замеров по архиву, а не назначены на глаз.
- **Мерить вес страницы целиком, а не то, что кажется тяжёлым.** Оптимизировали
  транскрипт (46 КБ), а 94 % веса страницы оказалось обложкой (862 КБ).
- **ПАМЯТЬ БРАУЗЕРА СЧИТАЕТСЯ ПО ПИКСЕЛЯМ, А НЕ ПО ВЕСУ ФАЙЛА, И ЛЕЧИТСЯ ЭТО
  РАЗНЫМ.** → [история](статус/уроки-подробно.md)
- **Макет противоречит не только соседнему макету, но и сам себе.** →
  [история](статус/уроки-подробно.md)
- **Вынося вид в общий класс, проверить, что правило контейнера его не
  перебивает.** → [история](статус/уроки-подробно.md)
- **Проверка по `dist/` обязана отделять наш код от чужого.** В сборке лежат
  библиотека Pagefind и правила переходов от самого Astro: разбор собранного
  CSS выдал 27 `!important` и 44 «цвета мимо палитры», среди которых нет
  ни одного нашего. **И цвета сравнивать по значению, а не по записи** —
  сборщик сжимает `rgba(216,143,159,.1)` из палитры в `#d88f9f1a`, и посимвольное
  сравнение объявляет законный токен нарушением.
- **Одинаковость проверяется замером, а не взглядом на один экран.** →
  [история](статус/уроки-подробно.md)
- **Вид, у которого нет одного дома, разъезжается тем вернее, чем он мельче.**
  Стрелка ↗ стояла в пяти местах пятью описаниями: у трёх акцентная, у двух
  наследовала цвет ссылки и выходила чернильной. Никто не заметил, пока
  заказчик не посмотрел на почту. **Мелочь не спасает от правила «одно
  описание — одно место»: она его усугубляет**, потому что расхождение мелочи
  не читается ошибкой, а читается неряшливостью, и чинить его никто не идёт.
- **ПОМЕТКА «МЕНЯЕТЕ ТУТ — ПОПРАВЬТЕ И ТАМ» НЕ УДЕРЖИВАЕТ НИЧЕГО.** →
  [история](статус/уроки-подробно.md)
- **Логотип чужого бренда нельзя нарисовать «на глаз».** Пять срисованных
  значков площадок заказчик назвал кривыми, и был прав: узнаваемый знак либо
  взят настоящим, либо нет, приблизить его нельзя. Настоящие берутся из
  открытых наборов (Simple Icons, CC0) или с favicon самой площадки; чего нет
  ни там, ни там, — оставляем без иконки, а место под неё всё равно занимаем,
  иначе названия встают рваным краем.
- **Толщину обводки внутри значка числом не задать.** Рисунок живёт в своей
  системе координат (32×32) и показывается в другом размере (30 px), поэтому
  `stroke-width: 1` даёт на экране 0.94 px — почти, но не столько же, сколько
  у рамки соседней кнопки. Ровно один пиксель при любом масштабе даёт
  `vector-effect: non-scaling-stroke`.
- **Макеты противоречат друг другу, и молча.** →
  [история](статус/уроки-подробно.md)
- **Любой прогон, который трогал исходники, обязан кончаться пересборкой.** →
  [история](статус/уроки-подробно.md)
- **Проверка, разворачивающая медиазапросы, склеивает разные правила в одно.**
  `.x{display:none}` в базе и `.x{display:grid;…}` в медиазапросе — это
  обычное «на узком прячем, на широком показываем», а после снятия обёртки
  `@media` они выглядят одним правилом, совмещающим видимость и раскладку.
  Проверка объявляет нарушением здоровый код. Смотреть надо внутрь одного
  блока `{…}`, а не по всем правилам с таким селектором.
- **Подлог для самопроверки писать ТАК, КАК ПИШУТ В ЖИЗНИ.** →
  [история](статус/уроки-подробно.md)
- **Ноль, полученный разбором чужого формата, — не ноль.** Попытка прочитать
  файлы поискового индекса как gzip+JSON дала «всего записей: 0» и вывод
  «страницы 404 в поиске нет» — а на деле разбор просто не понял формата.
  Спрашивать надо движок, а не его файлы, **и обязательно с контрольным
  запросом**: без него ноль неотличим от мёртвого индекса.
- **Инструмент, который не умеет проверяемого, отвечает «всё хорошо».**
  `curl` в macOS собран без HTTP/3 и на вопрос «работает ли HTTP/3» бодро
  отвечает кодом 200 — просто потому, что ходит по TCP. Прежде чем верить
  ответу, проверить, что инструмент вообще умеет то, о чём его спрашивают.
- **Равный вес — это тоже перевес, и решает его порядок.** →
  [история](статус/уроки-подробно.md)
- **Псевдоэлемент в собранном CSS пишется ОДНИМ двоеточием.** Сборщик отдаёт
  `:after`, а не `::after`, и `inset:0` — без единицы. Поиск накладок по
  `::after` и по `0px` не находит ни одной и отвечает «зону нажатия ничто
  не добирает» про сайт, где её добирают везде. Те же грабли, что `min-width`
  против `width>=`: спрашивать надо тем языком, на котором отвечает сборщик,
  а не тем, на котором писали исходник.
- **Что измеритель не считает — он обязан ЗНАТЬ, а не считать по-старому.** →
  [история](статус/уроки-подробно.md)
- **Измеритель обязан говорить «не знаю», а не выдавать число.** Замер краёв
  по CSS не умеет считать дорожку грида по содержимому, авторазмещение и детей
  flex — там ширину задаёт текст. Первый прогон честно посчитал навигацию
  на 2584 px при окне 1440, и поверить в это было легко: число выглядело
  как измерение. Теперь такие места помечаются знаком «≈». **Правдоподобное
  число хуже пропуска:** пропуск ищут дальше, а числу верят.
- **ПРИЗНАК, ЗНАЮЩИЙ НЕ ВСЕ ЗАКОННЫЕ ФОРМЫ, ВРЁТ В СТОРОНУ «СЛОМАНО» — И ПО
  НЕМУ ИДУТ ЧИНИТЬ ЗДОРОВОГО.** Проверка «умеет ли робот сказать, что упал»
  знала два способа из трёх и объявила бедой применение решений по кандидатам,
  у которого заголовок письма как раз и различает три исхода. Обычно
  проверки врут в сторону «всё хорошо», и потому эту сторону стерегут; здесь
  цена другая, но не меньше — правку внесут в работающее. **Спрашивать надо
  ПО СУЩЕСТВУ («есть ли шаг, который выполнится при падении, и заводит ли он
  письмо»), а не по форме записи.**
- **«Пусто» у проверки ничего не значит, пока не показано, что она умеет
  находить.** Дописать в собранный CSS правило, нарушающее все пункты сразу,
  убедиться, что поймано, и вернуть файл — это полминуты. Без этого шага
  проверка, сломавшаяся от опечатки в регулярном выражении, будет молча
  выдавать «всё хорошо» до конца проекта.
- **Русские буквы в пути к проекту ломают сравнение «меня запустили
  напрямую?»** → [история](статус/уроки-подробно.md)
- **Сверяя свой разбор с тем, что человек уже поправил руками, ручные правки
  надо перечислить СПИСКОМ, а не размягчить сравнение.** →
  [история](статус/уроки-подробно.md)
- **Проверку писать ФАЙЛОМ, а не однострочником `node -e '…'`.** Обратный слэш
  внутри однострочника проходит через две системы экранирования подряд, и `\b`
  доезжает до JavaScript литеральным слэшем: выражение перестаёт совпадать
  вообще ни с чем. Проверка при этом НЕ ПАДАЕТ — она отвечает «правил 0»
  и «ничего не найдено», то есть врёт ровно в сторону «всё хорошо». За одну
  сессию соврала так дважды подряд.
- **Левый край каждого блока страницы считать в пикселях, а не смотреть.** →
  [история](статус/уроки-подробно.md)
- **Прозрачность — не цвет.** Сборщик сжимает `transparent` в `#0000`,
  и проверка «цвета мимо палитры» объявляет нарушением снятую рамку.
- **Чек-лист устаревает раньше документа, в котором лежит.** Правку вносят
  в тело («постеры не 2:3, колонка 120»), а строчку в чек-листе не трогают —
  и приёмка идёт по ней, отменяя принятые решения. В §25 таких строк нашлось

- **`| tail -N` у прогона, который что-то СООБЩАЕТ, съедает начало сообщений.**
  Добор тайтлов помечает названия, которым нужна галочка «линковать только
  внутри кавычек», — и это единственное, ради чего его лог читают. Хвост
  в 60 строк показал 22 карточки из 24, а про две помеченных сказать было
  нечего: сам прогон при этом прошёл успешно, и потеря видна только пересчётом
  «сколько файлов завелось против скольких строк в логе». Лог таких прогонов
  берётся целиком, а сокращается уже при чтении.
- **«НЕ РАБОТАЕТ» СНАЧАЛА ПРОВЕРЯЕТСЯ ТЕМ, ЧТО ПРАВКА ВООБЩЕ ДОЕХАЛА.** Заказчик
  сказал «не работает» дважды подряд, и оба раза был прав про сайт и не прав
  про причину: правка лежала на GitHub, а на сайт не уезжала (пометка «спам»
  выключила автосборку). Первый вопрос при жалобе — не «что я сломал», а **что
  живой сайт сейчас отдаёт**: имя собранного скрипта в разметке, отпечаток
  файла, обе копии. Три починки пролежали невыложенными, и час ушёл на поиск
  несуществующей поломки.
- **ПОДЛОГ, МЕНЯЮЩИЙ ЗНАЧЕНИЕ ВО ВСЕХ КОПИЯХ СРАЗУ, РАСХОЖДЕНИЯ НЕ СОЗДАЁТ.**
  Сверка «вид марки одинаков во всех местах» проверялась подлогом, который
  заменял размер зубца по всему собранному CSS, — описание оставалось ОДНО,
  просто другое, и проверка законно молчала. Подлог обязан развести ОДНУ копию:
  дописать одному месту своё описание, как это и случится в жизни, когда
  поправят в одном файле и не поправят в трёх.
- **Пример, взятый из живых данных, ИСЧЕЗАЕТ, когда правка применена.** Две
  самопроверки задач 16–19 падали не от поломки, а от успеха: хештегов и блоков
  ссылок в архиве не осталось, потому что эти же скрипты их и убрали. Правило
  «пример доставать из данных, а не вписывать именем» верное — но у него есть
  вторая половина: **нет примера — сказать вслух и взять записанный образец**,
  а не падать. Красную проверку, которую нечем сделать зелёной, убирают.
- **Ключ, склеивающий два места в одно, прячет расхождение между ними.** Сверка
  стрелок звала обе марки одним именем `.arrow`, и вторая затирала первую
  в списке: мест три, показывала два, а разошлись бы как раз затёршиеся.
  Ключом берётся то, что места РАЗЛИЧАЕТ, — у Astro это метка компонента
  в селекторе.
- **Проверка, у которой ОТВЕТ ЗАВИСИТ ОТ ОБРАЗЦА, обязана сравниваться
  с собой же.** Замер «что достаётся элементу» отбрасывал правила без классов
  (`a {…}`, `:root`), и чем точнее его спрашивали, тем меньше он отвечал:
  93 свойства на один образец, 14 на другой. Поодиночке оба числа выглядят
  измерением. Видно это только тем, что один и тот же элемент спросили дважды.
- **ЧИСЛО, КОТОРОГО НЕ МОЖЕТ БЫТЬ, — ТАКОЙ ЖЕ ПРИЗНАК ПОЛОМКИ, КАК НОЛЬ.**
  Замер «сколько идёт робот» выдал 0,14 секунды на морфологию по 655 карточкам.
  Число не пустое, не подозрительное на вид — просто слишком маленькое для этой
  работы. Скрипт падал на второй строке, и робот падежных форм не отработал бы
  вовсе; чтением этого не нашли бы, потому что читать пошли бы не туда.
  **Замеряя время, посмотри и на ВЫВОД**: быстро — это ответ, но иногда ответ
  на другой вопрос.
- **ПРАВИЛО, ПРОЙДЕННОЕ ПО САЙТУ, НЕ ПРОЙДЕНО ПО СКРИПТАМ — И ГРАНИЦА ЭТА
  НЕВИДИМА.** «Схема обязана переживать пустую строку» было выведено, записано
  уроком и применено — к схеме сборки. А скрипты читают те же файлы СЫРЫМИ,
  мимо схемы, и для них правила не существовало: сборка проходила, проверки
  зеленели, падал только робот. Выведя правило про данные, спроси: **кто ещё
  читает эти же файлы другим путём.**
- **ТРИ ПОЧИНКИ, КАЖДАЯ ВЕРНАЯ, СКЛАДЫВАЮТСЯ В ЧЕТВЁРТУЮ БЕДУ.** Походу к RSS
  добавили повторы (одна находка), потом срок на попытку (другая находка) —
  и «сборка ходит к молчащему хостингу на каждой из 142 страниц» выросла
  с «медленно» до 346 минут, то есть до «никогда». Ни одна из трёх правок
  не была ошибкой. **Добавляя запас времени куда-либо, посчитай, во что он
  превращается там, где это место зовут в цикле.**
- **РАЗОВАЯ УБОРКА ПРАВИЛА НЕ УДЕРЖИВАЕТ, И СРОК ЕЙ — ДО ПЕРВОЙ ПРАВКИ
  РУКАМИ.** Жирный внутри заголовков сняли по всему архиву 13 августа;
  15-го он снова стоял в четырёх ОПУБЛИКОВАННЫХ постах — заказчик дописывал
  заголовки в админке, и правило туда не доехало. В одном посте от этого
  оказались обе формы разом, то есть ровно та беда, ради которой правило
  и заводили. Узнать об этом было неоткуда: механизма нет, проверки нет,
  сборка молчит. **Правило, которое заказчик может нарушить обычной работой,
  обязано жить в сборке**, а не в скрипте, который однажды прогнали.
- **Число копий правила, названное реестром, — нижняя оценка.** Реестр
  говорил «две копии повтора при сбое сети в `dtf/`» — их оказалось три;
  «шесть копий экранирования кавычки» — нашлось седьмое место, собиравшее
  подпись мимо правила. Оба лишних нашёл не глаз, а ПОИСК ПО ПРИЗНАКУ,
  написанный при сведении. Сводя копии в один дом, сразу пиши проверку
  «а нет ли ещё» — и запускай её ДО того, как поверишь числу из реестра.
- **«МЁРТВОЕ» ПО ПОИСКУ ИМПОРТОВ — НЕ МЁРТВОЕ.** `@astrojs/markdown-remark`
  числилась лишней: импортов ноль, поиск не врал. На ней держатся ВСЕ плагины
  разметки — её просит не наш код, а настройка сборщика. И щель тут шире, чем
  кажется: снятие строки из `package.json` пакет из `node_modules` не убирает,
  сборка после снятия честно проходит, а падает — на разборе настроек, ещё
  до первой страницы — только после следующей чистой установки. То есть
  у робота или на новой машине. **Прежде чем снять зависимость, спроси
  не «кто её импортирует», а «кто её ЗОВЁТ», и снеси её из `node_modules`
  по-настоящему.**
- **Число, названное реестром, — нижняя оценка и про мёртвое тоже.** Реестр
  говорил «семь имён старого слоя не читает никто» — их оказалось шестнадцать
  (вся шкала кеглей, все скругления, ширина колонки). Нашёл не глаз, а пересчёт
  ВСЕХ имён файла, написанный перед сносом. Та же болезнь, что с числом копий;
  лечится тем же — сначала свой замер, потом доверие чужому числу.
- **Проверке, которая сегодня не может покраснеть, подлог возвращает БУДУЩУЮ
  поломку, а не прошлую.** Заслон «версию сборщика не поднимать» на закреплённой
  версии зелен по определению и будет зелен годами — а зелёную проверку, которую
  нечем уронить, однажды сочтут пустой и снимут. Подлог поэтому вставляет
  в код нынешней версии тот самый шаг, который добавила новая: дословно,
  включая место вызова. Красный — на подлоге, зелёный — сразу после уборки.
- **СВОЙСТВО ПРИНАДЛЕЖИТ ТОМУ ТИПУ, У КОГО ОНО ЧИСЛИТСЯ В СЛОВАРЕ, А НЕ ТОМУ,
  У КОГО ЕГО НАРИСОВАЛИ В ЗАДАНИИ.** Поле `transcript` в ТЗ стояло у
  `PodcastEpisode`; валидатор ответил `UNKNOWN_FIELD`, а словарь Schema.org —
  что оно принадлежит `AudioObject` и `VideoObject`, то есть самой записи,
  а не рассказу о ней. Переставили на уровень ниже — ошибок ноль, смысл тот же.
  Разметка не видна глазами: неверное поле молчит годами, и обнаружить его
  можно только спросив словарь.
- **Чужая проверялка отвечает капчей, и это не поломка проверяемого.** После
  десятка запросов `validator.schema.org` начал отдавать `/sorry/index` на
  ЛЮБОЙ файл, включая тот, что проходил часом раньше. Признак прежний —
  сломан измеритель, а не измеряемое. Лечится вторым путём к тому же вопросу:
  сверкой со словарём-первоисточником (`schemaorg-current-https.jsonld`),
  и она же обязана уметь краснеть — вернули поле на прежнее место, ответила
  тем же самым.
- **Предел молча отбрасывает целый класс данных, и виден он только замером.**
  Заголовок «не влезает в 60 знаков» звучит как редкий случай; замер по архиву
  дал 101 тайтл из 571 — то есть каждый пятый терял новый заголовок целиком.
  Третья ступень сокращения вернула 43 из них. Ставя предел, считайте не «а
  бывает ли такое», а **сколько данных за него не проходит**.
- **«РОЛИК СУЩЕСТВУЕТ» И «РОЛИК ЗАИГРАЕТ» — РАЗНЫЕ ВОПРОСЫ, И ПЕРВЫЙ ОТВЕЧАЕТ
  ЗА ОБА.** Официальный oEmbed YouTube вернул название и картинку для
  видеоверсии ep-41 — то есть ответил «всё хорошо». Страница того же ролика
  говорит другое: `"status":"UNPLAYABLE"`, «заблокировано из-за контента,
  на который заявил права TV Tokyo Anime Rights Management». Поставь мы его
  по ответу oEmbed — на странице было бы окошко с ошибкой вместо пустого
  места, то есть хуже, чем было. Спрашивать надо `playabilityStatus`
  и `playableInEmbed` у самой страницы. Та же семья, что `curl` без HTTP/3.
- **МЕСТО ПРОПАВШЕГО ЭЛЕМЕНТА В РЯДУ ЧИТАЕТСЯ ПО УЦЕЛЕВШИМ СОСЕДЯМ, А НЕ
  ПО ДОГАДКЕ.** Двенадцать мёртвых роликов надо было заменить, и «что тут
  стояло» выглядело вопросом на угадывание: у одного ролика текст с двух
  сторон, и оба подходят. Ответ дали живые соседи — их названия уже лежали
  в кэше: у всех до единого ролик стоит ПЕРЕД тем абзацем, который
  иллюстрирует. После этого ни одной догадки не осталось. **Прежде чем гадать
  о пропавшем, спроси у соседей по ряду, как этот ряд устроен.**
- **КЭШ, КОТОРЫЙ ЗАПОЛНЯЕТСЯ ТОЛЬКО РУКАМИ, — ЭТО ДЫРА С ОТЛОЖЕННЫМ СРОКОМ,
  И ПЕРВЫМ О НЕЙ СООБЩАЕТ ЧУЖОЙ СЕРВИС.** Названия и даты встроенных роликов
  добирает `scripts/fetch-youtube-meta.mjs`, и его не звал ни один робот
  и ни одна сборка — только человек. Выпуск ep-154 вышел 10 сентября 2026
  с новым роликом, кэш последний раз писался 31 августа, а 13-го пришло письмо
  Google Search Console. Заслон в сборке при этом стоял и **сторожил обратное**
  («у каждого окошка есть объект»), поэтому три дня честно зеленел.
  Заводя кэш, спрашивай не «как его заполнить», а **кто будет заполнять его
  завтра, когда меня тут не будет**. → [задача-37](статус/задача-37-разметка-роликов.md)
- **РАЗМЕТКА БЕЗ ОБЯЗАТЕЛЬНЫХ ПОЛЕЙ ХУЖЕ ОТСУТСТВУЮЩЕЙ, И «ПУСТОЕ ЛУЧШЕ
  ВЫДУМАННОГО» ЭТОГО НЕ ОТМЕНЯЕТ.** Объект `VideoObject` печатался всегда, хоть
  из одного адреса: выдумывать нельзя — верно, а вот «объект всё равно нужен,
  окошко-то стоит» — нет. Огрызок не даёт ничего, кроме ошибки в консоли, и
  страница с ним **к показу в выдаче не допускается вовсе**. Нет обязательного
  поля — нет и объекта. **Подмена разрешена только необязательному** (описание
  ролика можно заменить описанием материала), и граница тут не по удобству:
  дата поста и дата выхода ролика — разные вещи, и поисковик их сверяет.
- **Честно записывать, что не проверено.** Раздел «Чего НЕ проверено» —
  обязательная часть отчёта, а не признак незавершённой работы.
- **СНОС ПОСТА РВЁТ ССЫЛКИ В ЧУЖИХ ПОСТАХ, И СПИСОК ФАЙЛОВ ОБ ЭТОМ МОЛЧИТ.**
  Заказчик снёс в админке бонусный пост 2023 года как дубль нового выпуска —
  правильное решение. Но на этот пост вели ссылки из двух ОПУБЛИКОВАННЫХ
  постов, страница была живой, и в `git status` это выглядело одной строкой
  «D». Проверка `scripts/check-broken-links.mjs` такое ловит, но её нет
  в сборке: она отдельная команда, и позвать её надо самому. **Снося что-то
  опубликованное, сначала спроси, кто на него ссылается**, и только потом
  собирай. Та же семья, что «снос дубля — это ещё и потеря того, чем он
  отличался»: там теряется разметка, здесь — входящие ссылки.
- **Проверку, которая врёт, чинить сразу — вместе с тем, что она поймала.** →
  [история](статус/уроки-подробно.md)
- **Две записи одного свойства подряд сборщик схлопывает в последнюю.** Приём
  «сначала то, что понимают все, следом то, что понимают не все» в собранном
  файле не выживает: `align-items: end` перед `align-items: last baseline`
  исчез, и в браузере без поддержки не осталось ничего. Запасной вариант ставим
  правилом, а новый — в `@supports`: там схлопывать нечего. **И проверяем это
  в собранном CSS**, а не в исходнике — в исходнике обе строки на месте.
- **Точку маркированного списка браузер рисует САМ, и гарнитура на неё не
  действует.** → [история](статус/уроки-подробно.md)
- **Утилитный класс приносит с собой не только то, за чем его позвали.**
  `.tech` на кнопке фильтра главной притащил ГАРНИТУРУ, и вкладки главной
  оказались моноширинными, а точно такие же вкладки архива — нет. Кегль,
  капслок и трекинг при этом совпадали, поэтому расхождение читалось как
  «другое написание», а не как ошибка. Ставя утилиту, смотреть весь её список
  свойств, а не одно нужное.

- **Знак, которого нет в обрезанном шрифте, уезжает в СИСТЕМНЫЙ ЭМОДЗИ —
  и видно это только с телефона.** Шрифты на сайте урезаны по списку знаков,
  и ↗ у Literata не нарисован вовсе. Стрелка внутри заголовка наследовала
  Literata, знака там нет — браузер шёл по списку дальше и на айфоне доходил
  до шрифта эмодзи: синяя плашка посреди заголовка. На компьютере беды

  латиницы и кириллицы, назначайте ему гарнитуру явно** — ту, в чьём диапазоне
  он перечислен.
- **ИЕРАРХИИ ПО ЦВЕТУ НЕ БЫВАЕТ.** Три ступени мелких заголовков в теле
  материала были набраны одним кеглем, одной гарнитурой и одним капслоком,

  тайтла: «удалить всё, что начинается на `k-on`» унесло бы вместе с пустым
  `k-on-movie` живой `k-on` с 27 упоминаниями. Имя файла сравнивается ЦЕЛИКОМ
  (`<адрес>.<расширение>` или `<адрес>-320w.<расширение>`), а заслон отдельно
  проверяет, что живые соседи в план сноса не попали.
- **Сводя две копии правила в одну, спроси у обеих ВСЕ вопросы, а не тот,
  из-за которого пришёл.** Реестр называл одно расхождение двух скриптов
  про жирный в заголовке — где действует правило. Их было два: второй скрипт
  вдобавок видел только заголовок, жирный ЦЕЛИКОМ, и «Часть **жирная**, часть
  нет» пропускал молча. То же у дубликатов: искали разъехавшийся порог,
  а нашли, что одна копия сравнивала с ним ОКРУГЛЁННЫЙ процент, а другая долю.
  Оба вторых расхождения нашлись только тем, что копии посадили рядом
  и спросили одним и тем же набором образцов.
- **Параметры визита — ОБЩЕЕ ДЕРЕВО НА ВЕСЬ СЧЁТЧИК, и отбор в запросе
  обязателен.** Раздел «зеркало против основного адреса» брал `paramsLevel1/2`
  без отбора; с появлением целей туда же легли `query`, `found`, `place`,
  `episode`, `path`. Список сортируется по числу заходов — и первая же людная
  неделя поиска выдавила бы в таблицу адресов строчку «site — 40». Читалось бы
  это поломкой вёрстки, а не чужой строкой. Заводя события с параметрами,
  пройди все отчёты, которые эти параметры уже читают.
- **ЧЕЛОВЕКА В СПИСКЕ ИЩУТ ПО ИМЕНИ, А НЕ ПО МЕСТУ.** Автором материалов стал
  ведущий со страницы «О проекте», и взять его «первым в списке» было
  соблазнительно. Ведущих трое, порядок задаётся в админке перетаскиванием —
  и однажды автором каждого поста молча стал бы другой человек, вместе с чужой
  биографией. Ищем по имени; не нашли — говорим вслух и оставляем прежнее,
  а не подставляем соседа.
- **Слово из шаблона задания бывает неправдой на части данных.** «Разбор
  в выпуске «Баки!»» верно, когда материал и правда выпуск; у 274 тайтлов
  единственный материал — заметка, бонус или видеоэссе. Слово вышло бы ложью
  в том самом заголовке, где задание запрещает врать про число. Шаблон,
  называющий вид материала, обязан спрашивать этот вид у данных.
- **`textContent` НЕ ЭКРАНИРУЕТ ДВОЙНУЮ КАВЫЧКУ, И В АТРИБУТЕ ЭТО ДЫРА.**
  Чистильщик поиска строил текст через `textContent` → `innerHTML`: `&`, `<`
  и `>` он трогает, кавычку — нет. Пока в атрибуты уезжали только адреса
  картинок, это ничего не значило; поехали заголовки, которые набирают
  руками, — и кавычка закрыла бы атрибут раньше времени. Сегодня её нет ни
  в одном из 754 заголовков, но появится она ровно тогда, когда её не ждут.
  Для значения атрибута нужен свой чистильщик.
- **ОДНО ПОЛЕ С ДВУМЯ СМЫСЛАМИ РАЗБИРАЕТСЯ ПО ЗАЧИНУ СТРОКИ, А ГРАММАТИКА
  В НЁМ — ЭТО УКАЗАНИЕ, КАК ЧИТАТЬ.** Поле маркировки рекламы носит и саму
  маркировку, и подпись автора: 4 против 23 на 31 августа 2026. Различает их
  зачин («Автор…»), а не догадка по содержимому. А запятую внутри читает
  ЧИСЛО: у «Авторы текста: А, Б, В» она разделяет имена, у «Автор текста:
  Кристина, «крисгринпис на связи»» принадлежит имени. Слово, которое человек
  выбрал сам, и говорит, как разбирать строку, — своей догадки тут не нужно.
- **СПОСОБ ВЫХОДА — НЕ ФОРМА ПРОИЗВЕДЕНИЯ, И ПЕРЕВОДИТЬ ОДНО В ДРУГОЕ
  НЕЛЬЗЯ.** У Shikimori шесть значений типа, а в разметку переведены два.
  `ova` и `ona` — это «вышло сразу на видео» и «вышло сразу в сеть»: под обоими
  живут и односерийные фильмы, и полноценные сериалы. А среди трёх
  `tv_special` лежит «Здесь слышен океан» — полнометражный фильм Ghibli,
  снятый для телевидения: назови его сериалом, и это прямая неправда
  в машинном поле, которую никто никогда не увидит глазами. Остальные четыре
  значения остаются общим «произведением» — беднее, но верно.
- **У ЗАСЛОНА ДВА РОДА НАХОДОК, И РОНЯТЬ СБОРКУ ИМЕЕТ ПРАВО ТОЛЬКО ОДИН.**
  Проверка подписей автора ловит и поломку кода («сказано „Автор“,
  а разобралось двое» — так падает подлог), и опечатку человека («Автор
  перевода:» вместо «Автор текста:»). Первое обязано ронять сборку: это
  ошибка, которой в репозитории быть не должно. Второе — только печатать
  строчку: иначе выкладка сайта встанет из-за слова, набранного в админке,
  и заслон снимут вместе с пользой. **Разделяя находки, спрашивай не
  «насколько это плохо», а „кто это может завести — код или человек“.**
- **Ломаться громко лучше, чем тихо врать.** Потерялась привязка исключения —
  показываем упоминание и пишем предупреждение в сборку, а не прячем.
- **Якорь привязки выбирать так, чтобы он пережил пересчёт данных.** Не таймкод
  (сдвинется), не номер вхождения (сдвинется от нового варианта написания),
  а номер реплики + позиция в тексте.
- **Блок объявляет о себе сам, а не значится в чужом скрипте по имени.**
  Лента главной прятала витрину по `getElementById('all-layout')`, и второй
  такой блок (каталог аниме) пришлось бы вписывать в её скрипт третьей
  строчкой, четвёртый — четвёртой. Теперь блок помечен `data-only-mode`,
  а лента прячет всё помеченное: страница добавляет свои блоки, не трогая
  компонент. Признак беды — правка чужого файла ради своей разметки.
- **Блок, переехавший на индексируемую страницу, обязан выйти из тела
  поиска.** → [история](статус/уроки-подробно.md)
- **Служебная обвязка блока в поиск не идёт.** Счётчик «01 / 06», стрелки
  листания, подпись кнопки спойлера — это органы управления, и в цитате
  выдачи они читаются мусором: «[ галерея ]01 / 06. ‹ ›». Помечается
  `data-pagefind-ignore`, как навигация в части 5. Подпись самого блока при
  этом остаётся в индексе — она текст материала.
- **Свой размер внутри компонента спорит с местом, куда его ставят, — и спор
  решает порядок файлов.** → [история](статус/уроки-подробно.md)
- **Одни правила — один код, второй копии не писать.** →
  [история](статус/уроки-подробно.md)
- **Геометрию картинки задаёт материал, а не место, куда его положили.**
  Пропорции обложки стояли в стилях каждого слота главной. Пока в «широкий»
  слот не попал выпуск подкаста — работало; попал — и квадратную обложку
  обрезало до полосы. Слот решает, сколько дать места; какой картинка формы,
  знает один компонент (`PostMedia.astro`).
- **Ручные правки защищать по каждому полю отдельно**, а не на всю карточку:
  описание своё навсегда, обложка пусть обновляется из API.
- **Два счётчика рядом обязаны считать одно и то же.** В выдаче поиска число
  у области и число в заголовке группы стоят в двадцати пикселях друг от друга.
  Считай они разное — страницы и строки, — читатель решит, что один из них
  врёт, и будет прав. Если точного числа нет (сколько раз слово прозвучало
  внутри выпуска, видно только в скачанном куске индекса), счётчик делается
  живым у обоих, а не правдоподобным у одного.
- **Размер рамки под картинку считать по замеру самих картинок, а не по числу
  из ТЗ.** → [история](статус/уроки-подробно.md)
- **Поле, заведённое для поиска, обязано попасть во ВСЕ поиски.** «Варианты
  написания» тайтла искал каталог, а поиск по сайту про них не знал — и запрос
  «кейон» не находил «Кэйон!», хотя ровно этот вариант в карточке записан
  руками. Заказчик вписывает вариант один раз и вправе ждать, что тайтл начнёт
  находиться везде.
- **Расширение поиска на весь архив — только с ручным подтверждением.** Один
  плохой вариант написания даёт ложные упоминания сразу везде и молча,
  а отменять их пришлось бы по одному выпуску.

  наведения. Общие контролы живут в базе, компоненту остаётся раскладка.

- **Картинку превью отдавать со своего домена и своим файлом.** Ссылка на

  при 2000×2000) в телеграме не разворачивалась вовсе, хотя отдавалась с кодом
  200. Своя копия 1200 px на ~150 КБ — и заработало. Это единственное поле,
  где правило «не дублировать факт, у которого есть хозяин» не действует:
  файл делается из уже скачанной обложки, а не тянется заново.
- **`twitter:card` всегда `summary_large_image`.** Телеграм по этому тегу
  решает, показывать ли картинку вообще: при `summary` превью выпуска вышло
  без картинки совсем. Забота о том, что широкая карточка обрежет квадратную
  обложку, обошлась дороже самой обрезки.
- **Проверять превью отправкой ссылки, а не наличием тегов.** Все теги стояли,
  все картинки отдавались с кодом 200 — и превью всё равно было пустым.
  «Разметка на месте» тут значит ещё меньше, чем обычно.
- **Список для поисковика строить из тех же данных, что и сами страницы**,
  а не из готовых файлов в `dist/`. Иначе «черновиков в карте нет» нечем
  пересчитать, а черновиков у нас 138 против 8 опубликованных постов.
- **У чего нет страницы, то не попадёт ни в карту сайта, ни в поиск само.**
  Pagefind индексирует собранные страницы, карта строится из них же. Появилась
  сущность без страницы (пост-ссылка на чужой сайт) — её надо класть в индекс
  отдельной записью (`index.addCustomRecord`) и отдельно же не пускать в карту.
  Три места, где живёт правило «страницы нет», перечислены в `externalPost.mjs`.

- **У СВЕЖЕСТИ ЕСТЬ БЕЗОПАСНЫЙ МИГ, И ОН ОДИН: ПОКА НЕКОМУ ДЕРЖАТЬ КОПИЮ.**
  Локальная админка отставала от репозитория, и напрашивалось обновлять её
  пока она открыта. Это не «слабее помогает» — это ПРОИЗВОДИТ вторую беду:
  открытая вкладка Sveltia держит свою копию поста и при сохранении пишет её
  целиком, поэтому файл, изменённый под ней, возвращается к прежнему виду
  молча (так откатился ep-102). Обновление поэтому стоит в запуске ярлыка —
  до того, как админка появится на свете. **Выбирая, КОГДА обновлять данные,
  спроси не «как часто», а „кто в этот миг держит их копию“.**
- **ЗАТИРАНИЕ ЧУЖОЙ РАБОТЫ ДЛЯ GIT — ЗАКОННАЯ ПРАВКА, И НИ ОДИН ЗАСЛОН
  ВЫКЛАДКИ ЕГО НЕ ВИДИТ.** Замер в песочнице из настоящих репозиториев:
  сохранение старой копии поверх правки робота даёт обычный diff «человек
  удалил строчку» — git не возражает, коммит проходит, пуш проходит, сборка
  проходит, сайт выкладывается. Три заслона быстрой выкладки (незакоммиченное,
  незапушенное, отстали) слепы: там всё в порядке. Ловится это только вопросом
  «а не пропали ли строки, которые робот добавил ПОСЛЕ прошлой выкладки», и
  заслон обязан стоять ПЕРЕД записью, а не после.
- **ЗАСЛОН БЕЗ ВЫХОДА — НЕ ЗАСЛОН, А ЗАМОК.** Тот же заслон затирания ловил
  заодно и снос: файла нет — значит работа робота пропала. 03.09.2026 заказчик
  убрал два поста НАРОЧНО и не смог выложить сайт ничем вообще: единственным
  советом в окне было «позовите Claude Code». Разница в том, ЧТО ЧЕЛОВЕК ЗНАЛ:
  затирание за него сделала открытая вкладка (он о нём не подозревает — стена),
  а файл вкладка удалить не может, снос всегда его собственное действие
  с подтверждением (он знает всё — вопрос). **Спрашивать «правда ли вы этого
  хотели» имеет смысл только там, где человек это делал.** Ответ даётся вторым
  нажатием той же кнопки: у выкладки из строки меню нет ни экрана, ни
  клавиатуры, зато её отказ показывается окном целиком. И разрешение именное —
  помнит отпечаток снесённого, живёт полчаса, тратится один раз: иначе одно
  «да» тихо разрешило бы завтрашний случайный снос. **И цену сноса заслон
  обязан называть настоящую**: первая версия вопроса грозила «исчезнет
  с сайта», хотя заслон смотрит на привезённое ПОСЛЕ прошлой выкладки — то
  есть на сайт ещё не попавшее. Заслон, пугающий сильнее, чем стоит беда,
  врёт так же, как и молчащий.
- **ОТСТУП ФАЙЛА ПРИНАДЛЕЖИТ ТОМУ, КТО ЕГО ПИШЕТ.** В карточках тайтлов живут
  два формата, и это не беспорядок: робот (`writeAnimeEntry`) пишет табом,
  админка Sveltia — двумя пробелами. То есть пробелами набраны РОВНО ТЕ
  карточки, которые заказчик правил руками. Скрипт, дописывавший одно поле,
  привёл их к своему виду — и диффом вышло 29 файлов целиком, причём именно
  тех, которых трогать не стоило; первое же сохранение в админке вернуло бы
  пробелы обратно. Дописывая поле в чужой файл, отступ берут У ФАЙЛА.
- **Родство, взятое у источника, точнее догадки по имени — но ШИРЕ
  человеческого родства.** Догадка по началу адреса роднила «Принцессу
  Мононоке» (1997) с «Мононокэ» (2007): общего у них только кусок слага.
  Поле `franchise` у Shikimori такой ошибки не делает — у «Принцессы» франшизы
  нет вовсе. Зато оно кладёт в одну франшизу разные фильмы одной вселенной:
  «Дитя погоды» и «Твоё имя», «Стального алхимика» и «Братство». Точный
  источник снимает ложное родство, но не отвечает на вопрос «а считает ли это
  родством человек» — на него отвечает второй признак, свой.

- **ПРАВИЛО, ГЛЯДЯЩЕЕ НА СОСЕДНИЙ ЗНАК, ОБЯЗАНО РАЗЛИЧАТЬ СТОРОНУ КАВЫЧКИ.**
  Упоминания тайтлов ищутся нарочно БЕЗ различения открывающей и закрывающей:
  архив писан в мессенджере, там сплошь «Монстр“ с лапкой не с той стороны.
  Но у вопроса «начинается ли тут фраза в кавычках» ответ зависит от стороны,
  и общее послабление тут врёт: слева от тайтла сплошь и рядом стоит
  ЗАКРЫВАЮЩАЯ кавычка соседа — «Боруто», «Фури-кури», «Приоритет чудо-яйца» —
  и три ссылки из 1317 потеряли номер ни за что. Список открывающих заведён
  отдельно и намеренно без симметричных: по прямой кавычке и апострофу сторону
  не определить, а замер архива говорит, что все 999 пар вокруг ссылок — ёлочки.
- **«ЕСТЬ ЛИ ЭТО В СПРАВОЧНИКЕ» СПРАШИВАЮТ ПО НОМЕРУ ИСТОЧНИКА, А НЕ ПО
  НАЗВАНИЮ ИЗ ТЕКСТА.** Замер сравнивал фразу «Стального алхимика: Братство»
  из статьи с названиями карточек, не находил и отвечал «тайтла нет» — а тайтл
  был, просто в тексте он в родительном падеже. По этому ответу уже собирались
  завести четыре ДУБЛИКАТА, и остановил их не глаз, а заслон «слаг уже занят»,
  стоявший перед записью. Вопрос «есть ли произведение» и вопрос «встречается
  ли эта строка среди названий» — разные, и второй отвечает «нет» почти всегда.
- **ЗАВОДЯ ПРОДОЛЖЕНИЕ ИЛИ ФИЛЬМ, БЕРИТЕ ЕГО ПО ТОЧНОМУ НОМЕРУ, А НЕ ПОИСКОМ
  ПО НАЗВАНИЮ.** У «Блича» четыре кура отдельными тайтлами, у «Истребителя
  демонов» три фильма подряд, у «Гандама» рядом пролог и рекап. Поиск по имени
  вернёт первое похожее, и подмена сериала фильмом не будет замечена никогда —
  та же семья, что «обложку из запасного источника брать только со сверкой
  названия». У источника для этого есть `findById`, а ответ всё равно сверяется
  с ожидаемым оригинальным названием: не совпало — не пишем.

### CMS (Sveltia)

- **Шаблон подписи в списке умеет ровно одно: «есть значение / нет» по ОДНОМУ
  полю.** → [история](статус/уроки-подробно.md)
- **`pattern` у поля проверяется ВСЕГДА, и на пустом значении тоже.** →
  [история](статус/уроки-подробно.md)
- **Зарегистрировать кнопку редактора мало — её надо вписать в
  `editor_components` у поля.** → [история](статус/уроки-подробно.md)
- **Проверка ищет в собранной странице — ищи в НУЖНОМ ТЕГЕ, а не по странице
  целиком.** → [история](статус/уроки-подробно.md)
- **У запроса к живому сайту сначала смотрим КОД ОТВЕТА, потом содержимое.** →
  [история](статус/уроки-подробно.md)
- **API Sveltia сверять по её коду, а не по документации Decap.** Совместимость
  неполная, расходятся молча: в поле приходит `{ value, field, forID, … }`,
  никакого `props.entry`. На этом все новые поля были глухими.
- **ПРЕЖДЕ ЧЕМ ПИСАТЬ СВОЁ — СПРОСИТЬ, НЕ УМЕЕТ ЛИ ЭТОГО САМА CMS.** →
  [история](статус/уроки-подробно.md)
- **Предпросмотр своей кнопки не должен начинаться с HTML-тега.** Sveltia зовёт
  `toPreview` с ПУСТЫМИ данными, берёт первый тег ответа и после этого
  перехватывает все такие теги при вставке (`importDOM`). Наши кнопки отдавали
  `<div>` и `<span>` — и текст, скопированный из соцсетей, при вставке
  рассыпался на наши блоки: каждый `<span>` становился плашкой «Аниме
  (не выбрано)». В документации Decap об этом нет ни слова.
- **Картинки из админки — строкой и своим сжатием, не через `image()` Astro.**
  CMS кладёт файлы в `public/`, а `image()` их не видит: сборка падает целиком
  с `ImageNotFound`. Поле `cover` пролежало такой миной, пока его не было
  в админке.
- **Молчание не должно значить две разные вещи.** Метки времени не было и у
  короткой заметки, и у выпуска, не нашедшего себя в RSS, — читатель различить
  их не мог. Если нечего сказать по двум разным причинам, хотя бы одна обязана
  сказать о себе вслух («меньше 3 мин читать»).
- **«Пусто» и «намеренно ничего» — разные состояния, и путать их нельзя.**
  Пустая обложка значит «подбери сам», галочка «Без обложки» — «картинки быть
  не должно». Одним полем это не выражается, нужен отдельный флаг.
- **Значение, уезжающее в атрибут строкой, проверять на пусто.** У материала
  без своего описания и без подходящего первого абзаца `postDescription`
  возвращает пустоту, и метка для поиска уехала в индекс словом «undefined» —
  ровно так оно и печаталось в выдаче. Шаблонная строка не падает никогда,
  она просто подставляет туда слово.
- **Схема обязана переживать пустую строку в любом необязательном поле.**
  CMS пишет `""`, а не пропускает поле; `z.coerce.date("")` роняло сборку
  целиком. Обычным сохранением поста можно было положить сайт, и тихо.
- **Открытая вкладка админки держит СВОЮ копию поста и перезапишет мою правку
  молча.** → [история](статус/уроки-подробно.md)
- **Длинных строк с переносом (`>-`) Sveltia не пишет — она пишет одной
  строкой.** Заведённый руками файл с аккуратными переносами она при первом же
  сохранении разложит по-своему, и коммит придёт с разницей на весь файл.
  Данные при этом целы, ломаться нечему — но **проверка «пустой коммит»
  на таком файле не работает, пока он не сохранён хоть раз**. Заводя файл
  руками, писать длинные значения одной строкой.
- **Сохранение в админке без изменений — лучшая проверка своего формата.**
  Если моя запись совпала с тем, что пишет Sveltia, коммит от неё приходит
  **пустой, с нулём изменённых файлов**. Расхождение в один пробел дало бы
  разницу на весь файл. Дешевле любой сверки глазами: записать один пост,
  попросить сохранить, посмотреть `git show --stat`.
- **Одно сохранение CMS = один файл.** Поля, которым нужно писать в два файла,
  не делать вовсе — обходной путь через прямые коммиты в GitHub даёт
  расползание данных.
- **Не пускать CMS в дорогие данные.** Она переписывает файл целиком. Всё,
  что правится руками, — компактной строкой в самом посте; оплаченные реплики
  транскрипта лежат отдельно и CMS их не трогает.
- **Полку опознавать по её собственным полям, а не «всё остальное — пост».**
  Обработчик сохранения делил записи на «тайтл» и «всё прочее», и первая же
  новая полка («О подкасте») стала получать чужое поле `anime`. Проверка
  на остатке ломается ровно тогда, когда добавляют третью сущность.
- **Списки внутри своего компонента CMS сохраняет ненадёжно** (галерея, тайтлы —
  дважды теряла и портила данные). Решение: маркер в тексте, вся логика
  на стороне сайта при сборке. **Ровно внутри своего — встроенный `list`
  работает нормально** («Кнопки» у поста, «Ведущие» на странице «О подкасте»,
  проверено руками). Не расширять это правило на все списки подряд.
### Astro и сборка

- **В коде из `src/lib/` не полагаться на `import.meta.url` и пути к файлам.**
  Сборщик их меняет, проверка молча отвечает «нет». Списки данных класть
  отдельным `.js` (не `.json` — его по-разному импортируют node и Astro).
- **Помнить лимит 20 000 файлов.** Отдельный индекс по 24 900 репликам упёрся
  бы в него сразу; после каждого этапа считать файлы в сборке и говорить запас.
- **Число файлов в сборке гуляет на ±3**: превью-обложки выпусков делаются
  из скачанных по сети картинок, и при сбое сети их выходит меньше. Запас
  считать по большей цифре, разброс в пару файлов паникой не считать.
- **Внутри одного файла правило проигрывает по весу соседнему.** →
  [история](статус/уроки-подробно.md)
- **Гарнитура не помещается в свою строку, и обрезка режет буквы.** →
  [история](статус/уроки-подробно.md)
- **Две строки текста в одной линейке выравниваются по базовой линии, а не по
  центру.** → [история](статус/уроки-подробно.md)
- **`margin-top: auto` не заменяет отступ.** Прижатие к низу колонки
  схлопывается в ноль, как только содержимое переросло место, — и прижатый блок
  встаёт вплотную к соседу. Зазор задаётся `padding` обёртки: его auto-margin
  не съедает.
- **Внутри контейнера, где дети центруются `margin-inline: auto`, сокращённый
  `margin` писать нельзя.** Он сбрасывает боковые поля в ноль, и всё
  содержимое молча уезжает к левому краю. Ошибки нет, ширина правильная,
  а колонка стоит не по центру. Пишется `margin-block`.
- **Заменяемому элементу одних отрицательных полей для выноса до краёв мало.**
  → [история](статус/уроки-подробно.md)
- **Обрезать ширину по контейнеру измеритель не имеет права: шире родителя —
  законное состояние.** Из-за этой обрезки настоящий вынос до краёв экрана
  и СЛОМАННЫЙ (коробка шириной с колонку, увезённая влево) выглядели в отчёте
  ОДИНАКОВО — оба по ширине колонки. То есть проверка не просто молчала,
  а активно скрывала целый класс поломок; нашёл заказчик глазами на телефоне.
- **Медиа «до краёв экрана» считается от полей страницы, а не от `100vw`.**
  Ширина окна включает место под полосу прокрутки (`scrollbar-gutter: stable`),
  поэтому `100vw` шире документа — и картинка во всю ширину сама создаёт
  тот горизонтальный скролл, который на сайте запрещено прятать.
- **`content-visibility: auto` врёт про высоту, пока блок за кромкой экрана.**
  Содержимое не разложено, `scrollHeight` равен видимой высоте — и проверка
  «есть ли что прокручивать» отвечает «нет». Решать по классу состояния,
  а не по измерению; а если мерить всё-таки надо — после кадра отрисовки,
  и не одного: обработчики кадра выполняются ДО пересчёта раскладки.
- **Ширина окна зависит от длины страницы.** Короткая страница не прокручивается,
  браузер убирает полосу прокрутки, окно становится шире — и всё, что
  центрируется по окну, съезжает вбок. Выглядит как поломка вёрстки конкретной
  страницы. Лечится `scrollbar-gutter: stable` один раз на весь сайт.
- **Текст для поисковика и текст для читателя — разные тексты.** Описание
  раздела из метатега, поставленное подводкой на страницу, сделало шапки разделов
  разной высоты (62 знака против 100), и список под ними прыгал при переключении
  вкладок. **Длина такой подводки — часть вёрстки**, и диапазон надо записывать
  рядом с самим текстом, иначе его нарушит первая же правка.

- **ДВОЕТОЧИЕ ПЕРЕД СЛОВОМ РАЗБОР СЧИТАЕТ МЕТКОЙ, И СЛОВО ПРОПАДАЕТ.** →
  [история](статус/уроки-подробно.md)
- **КТО ОБЪЯВЛЯЕТ ОБЩИЙ ИНСТРУМЕНТ, ОБЯЗАН ОБЪЯВИТЬ ЕГО ДО ОБРАБОТЧИКОВ
  ЗАГРУЗКИ СТРАНИЦЫ.** Панель плеера клала `window.__bakaPlayer` внутрь своего
  `astro:page-load`, а обработчики бегут в порядке тегов `<script>`; расшифровка
  идёт на странице раньше панели и спрашивала плеер, которого ещё нет. Итог:
  на ПЕРВОЙ открытой странице выпуска расшифровка мертва — нет кнопки «Следить
  за плеером», нажатие на реплику не перематывает. **При хождении по сайту беды
  не видно вовсе:** переходы идут без перезагрузки, объявленное живёт на `window`
  и переживает их, поэтому вторая и все следующие страницы работают. Ломается
  ровно та, которую открыли по ссылке из мессенджера или поиска. Лечится одной
  строкой: объявлять при исполнении модуля, а не внутри обработчика. Проверка —
  `scripts/transcript-player-order.test.mjs`, гоняет ДВА настоящих собранных
  скрипта на подделке окна; `--selftest` возвращает прежнее правило.
- **СВОЙ ОБРАБОТЧИК КЛИКА ПРОИГРЫВАЕТ РОУТЕРУ, И ЭТО МОЛЧАЛИВО.** →
  [история](статус/уроки-подробно.md)
- **ОБНОВЛЕНИЕ СБОРЩИКА СВЕРЯЕТСЯ НЕ ТОЛЬКО ПО ВЫВОДУ, НО И ПО ПОВЕДЕНИЮ —
  И ВТОРОЕ НЕ ВИДНО В СОБРАННОЙ ПАПКЕ ВОВСЕ.** Astro 7.2.2 меняла в страницах
  две мелочи: метку версии и имя файла скрипта переходов. Сверка «до и после»
  этим и кончилась бы — 1402 страницы, различие объяснено, вывод «обновление
  ничего не сломало». А имя файла меняется ОТ СОДЕРЖИМОГО: внутри скрипта
  появился шаг, пересоздающий каждый `<video>` и `<audio>` новой страницы,
  включая перенесённый через `transition:persist`, — то есть звук обрывался бы
  при каждом переходе по ссылке. **Переименованный файл — это не «мелочь
  в разнице», а указатель: содержимое другое, идите смотреть какое.**
  Заслон — `scripts/persist-audio.test.mjs`, гоняет настоящую функцию Astro
  на подделке дерева; версия закреплена в `package.json` точной цифрой.
- **Гигиена пакетов проверяется замером ПОСЛЕ, а не обещанием ДО.** Обновление
  затевалось ради предупреждения `nanoid` — после него `npm audit` ругался
  по-прежнему. Все четыре предупреждения сняли два соседних шага: обновление
  `wrangler` и одна строка в `package-lock.json`. То есть обновление, ради
  которого чуть не сломали главную особенность сайта, не давало НИЧЕГО, и это
  выяснилось одной командой.
- **`/admin/` В РЕЖИМЕ РАЗРАБОТКИ ОТДАЁТ 404, А `/admin/index.html` — 200.**
  Astro не достраивает имя файла к папке из `public/`: на живом сайте
  «красивый» адрес работает, у себя на машине — нет. Ярлык админки, открывший
  заученный адрес, показал бы человеку страницу «не найдено» вместо админки.
  Адрес, по которому что-то открывают, спрашивается ЗАПРОСОМ.
- **Сборка и живой сервер разработки уживаются — проверено, а не решено.**
  Опасение «`astro dev` и `astro build` лезут в одну служебную папку» выглядело
  здравым, и под него была написана целая ветка «погасить админку на время
  сборки, потом поднять». Замер: четыре полные сборки подряд при живом
  `astro dev`, все четыре успешные. Ветка не понадобилась вовсе.- **Импорт модуля ВЫПОЛНЯЕТ ЕГО ЦЕЛИКОМ, а не достаёт из него список.**
  Скрипт целей Google импортировал перечень целей из скрипта Метрики — и тот
  при каждом запуске ходил бы в Метрику и переписывал реестр, то есть дёргал
  чужую работу за компанию. Данные, нужные двоим, живут третьим файлом.

- **ЭЛЕМЕНТ, ВЫШЕДШИЙ ИЗ `display: none` И ПОЛУЧИВШИЙ КОНЕЧНОЕ ЗНАЧЕНИЕ В ТОМ
  ЖЕ КАДРЕ, НЕ ПЕРЕХОДИТ, А ПРЫГАЕТ.** Браузеру не с чего начинать переход:
  раскладка для показанного элемента ещё не посчитана, и два состояния
  склеиваются в одно. `requestAnimationFrame` не спасает — он выполняется ДО
  пересчёта. Выглядит это как «сделано резко», и починкой кажется анимация,
  которой на самом деле там нет вовсе: у марки при наведении переход был задан
  с самого начала и не запускался ни разу. Лечится не приёмом в скрипте,
  а тем, что прячем `visibility` (с отложенной на длительность перехода сменой),
  а не `display`: элемент разложен всегда, начальное состояние у него есть.
  Заодно появляется и плавный УХОД, которого при `display` не бывает в принципе.

- **СБОРКА ИДЁТ С `astro build --force`, И СНЯТЬ ЭТОТ КЛЮЧ — ЗНАЧИТ ВЕРНУТЬ
  НА САЙТ ВЧЕРАШНЮЮ РАЗМЕТКУ.** Astro держит разобранный markdown в двух
  папках и правку remark-плагина не замечает: сборка проходит успешно, кодом
  0, и отдаёт ПРЕЖНЮЮ разметку. 31 августа 2026 робот выкладки на Hetzner
  собрал свежий код со старым разбором и положил его ПОВЕРХ правильной
  сборки: у ссылок на тайтлы пропали номера сносок, подчёркивание и чернильный
  цвет. **Диагноз дало то, что на ОДНОЙ И ТОЙ ЖЕ живой странице лежала новая
  панель площадок и старая разметка тайтлов** — компоненты собираются заново,
  посты берутся из разбора. Один коммит, разная разметка; ошибки нет, журнал
  чист, видно только глазами. **Ключ живёт в `package.json`, а в JSON нельзя
  писать комментарии** — значит рядом с ним нет объяснения, и первый, кто
  станет ускорять сборку, снимет его как лишний. Заслона на это пока нет.
  **Замер: обычная сборка 203 с, с ключом 197 и 202 — разницы нет**, время
  съедают картинки и десять скриптов после `astro build`.
  → [задача-35](статус/задача-35-площадки-подкаста.md)

- **`rm -rf` СЛУЖЕБНОЙ ПАПКИ УБИВАЕТ РАЗБОР У ЖИВОГО `astro dev`, А КЛЮЧ
  `--force` — НЕТ.** Первой починкой того же вечера был снос `.astro`
  и `node_modules/.astro` перед сборкой, и он работал — но на машине заказчика
  админка открыта как раз тогда, когда жмут «ВЫЛОЖИТЬ НА САЙТ». После сноса
  страницы постов на ней стали отдавать 404, **сборка их не починила**,
  помог только перезапуск сервера. С `--force` та же админка отвечает 200
  и отдаёт правильную разметку. Прежде чем чистить чужой кэш руками, спроси
  у инструмента, нет ли у него своего ключа: он знает, что можно трогать,
  а что занято.

### Инфраструктура и деплой

- **Документы описывают механизм, а не перечисляют механизмы, — и второй живёт
  незамеченным годами.** → [история](статус/уроки-подробно.md)
- **ВЫКЛАДОК ДВЕ, И ПАДАЮТ ОНИ ПОРОЗНЬ — сверять надо ОБЕ копии.** →
  [история](статус/уроки-подробно.md)
- **КТО СОБИРАЕТ ДОЛГО, ОБЯЗАН ПЕРЕД ВЫКЛАДКОЙ СПРОСИТЬ, НЕ ВЫЛОЖИЛИ ЛИ БЕЗ
  НЕГО.** Робот собирает шесть минут и всё это время держит в руках состояние
  на момент СТАРТА. Пока он собирал, быстрая выкладка с машины положила на сайт
  свежий коммит — а робот через пятнадцать секунд накрыл его своей сборкой,
  собранной ДО него: 12:55:01 против 12:55:16. Та же «выкладок две, побеждает
  поздняя», только поздней тут оказалась старая, и одиннадцать минут сайт стоял
  назад во времени. Спрашивать хранилище надо не при старте, а ПЕРЕД тем, как
  класть; ушло вперёд — не выкладывать вовсе и отметку «докуда выложено»
  не двигать. **Починилось это тогда само и по случайности** — робот затёр
  чужую отметку своей, более старой, и через десять минут пересобрал всё
  заново, — то есть беду прятал ещё и лишний шестиминутный прогон.
  Заслон — `scripts/deploy-race.test.mjs`, гоняет НАСТОЯЩИЙ блок из
  `hetzner/run-deploy.sh` в песочнице из двух git-репозиториев.
- **СПРАШИВАТЬ НАДО НЕ «БЫЛ ЛИ КОММИТ», А «ЧТО В НЁМ ПОМЕНЯЛОСЬ».** Робот
  телеграма не нашёл в канале ни одного поста — и всё равно закоммитил: он
  пишет себе закладку «докуда дошёл», а в ней время захода, и оно новое всегда.
  Робот выкладки увидел новый коммит и собрал сайт 336 секунд, получив его байт
  в байт прежним. В тишине так было бы четырежды в сутки. **Список неэфирного
  при этом обязан быть коротким и закрытым**: ошибка в нём стоит невыложенной
  правки, поэтому туда попадает только то, чего сборка не читает ВООБЩЕ, а
  незнакомое считается влияющим. Заслон — `scripts/deploy-idle.test.mjs`, и
  главное его утверждение не «закладка не будит сборку», а **«закладка ВМЕСТЕ
  с постом собирается»**: робот кладёт их в один коммит.
  → [задача-21](статус/задача-21-роботы-на-hetzner.md)
- **Письмо о новостях обязано считать новости тем же, чем оно их называет.**
  Зелёное «📥 забрано новых постов: 0» ушло потому, что письмо срабатывало
  на любой коммит, а число считало файлы постов. Условие и счётчик смотрели
  на разное, и разошлись они молча. Письмо о новостях, приходящее в тишину,
  через неделю перестают открывать вместе с настоящими.
- **ЗАМЕЧАНИЕ, ПРИЦЕПЛЕННОЕ К ПИСЬМУ ОБ УСПЕХЕ, НЕ ПРИДЁТ НИКОГДА.** Робот
  умеет сказать «бот молчит двенадцатый день» и «бота, похоже, выкинули
  из канала» — а в письмо это попадало только вместе с новыми постами, то есть
  ровно тогда, когда тревожиться не о чем. В воркфлоу на GitHub шаг стоял
  с `if: always()`, при переезде на сервер условие потерялось, и потеря
  выглядела как «письма просто нет». **Спрашивая себя «доедет ли тревога»,
  проверяй её на том случае, ради которого она заведена**, а не на удачном.
- **Файл замечаний, закрытый `.gitignore`, переживает заход — и вчерашнее
  приедет как сегодняшнее.** Скрипт пишет его, только когда есть о чём сказать;
  значит «сказать нечего» обязано выглядеть пустым местом, а не прошлым
  разговором. Стирать перед прогоном. **И знаки `& < >` в таком письме
  экранировать**: телеграм читает их разметкой и на кривой отвечает отказом —
  письмо не уходит ВОВСЕ, а в замечаниях лежит текст постов. **Оба правила были написаны про робота
  телеграма и не доехали до робота выпусков:** 28 августа его письмо рассказало
  про «Расшифрован ep-153» — выпуск, расшифрованный НАКАНУНЕ, и выглядело это
  второй оплатой. Денег это не стоило, соврал только хвост письма, но письму
  робота верят. Заслоны — `scripts/telegram-notify.test.mjs`
  и `scripts/episodes-notify.test.mjs`.
- **ВЕТКА, ОСТАВЛЕННАЯ ПОСЛЕ СЛИЯНИЯ, ЛОВИТ ЧУЖИЕ КОММИТЫ — И ЭТО ВИДНО
  ТОЛЬКО СЛУЧАЙНО.** Работа шла в ветке `razmetka-schema`, потому что задание
  просило не трогать мастер. Заказчик тем временем правил пост в админке,
  репозиторий стоял на этой ветке — и его коммит ушёл туда же, мимо мастера.
  Заметили это перебором истории перед выкладкой; не заметь — правка осталась
  бы лежать в ветке, которую не собирает никто, а на сайте её бы не было.
  **Ветка, слитая целиком, удаляется сразу.** И работая в чужой рабочей копии,
  помни: `git status` показывает твою ветку, а руки у неё не только твои.
- **Две сессии в одной папке дерутся за сборку и за список изменений git.** →
  [история](статус/уроки-подробно.md)
- **ЧЕТЫРЕ РОБОТА В ОДНОЙ ПАПКЕ — ТЕ ЖЕ ДВЕ СЕССИИ, ТОЛЬКО ПО РАСПИСАНИЮ.**
  Опросчик постов ходит каждые пять минут и влез ровно в ту секунду, когда
  забирались посты из телеграма: `fatal: Cannot fast-forward to multiple
  branches`. Работа при этом БЫЛА СДЕЛАНА — посты забрались и запушились, —
  а заход объявлен сбойным, и заказчику ушло красное письмо о живом роботе.
  Лечится общим замком (`flock`) на всех, кто лезет в репозиторий: ждём,
  не дождались — уходим молча, следующий заход повторит.
  → [задача-21](статус/задача-21-роботы-на-hetzner.md)
- **ПЕРЕНЕСЁННЫЙ РОБОТ НАДО ВЫКЛЮЧИТЬ НА СТАРОМ МЕСТЕ, А НЕ ПОЛАГАТЬСЯ НА ТО,
  ЧТО ЕГО ТАМ ВЫКЛЮЧИЛИ ЗА НАС.** Воркфлоу GitHub при переезде на Hetzner
  остались включёнными: их гасила пометка «спам», а не мы. Пометку сняли
  молча — и неделю каждую работу делали двое, пока 22 сентября оба не записали
  один файл с разницей в 30 секунд. Замок `flock` от этого не спасает: он общий
  только для жильцов одного сервера. Признак на виду: в журнале Actions снова
  появились походы.
- **Синхронизация «по времени изменения» — это заливка целиком.** Готовая
  `aws s3 sync` сравнивает время, а сборщик переписывает все файлы заново
  и ставит им новое: «синхронизация» залила бы весь сайт при каждой выкладке.
  При бесплатных 10 000 операций записи в месяц и 11 000 файлов это перебор
  с третьей сборки. Сравнивать надо по СОДЕРЖИМОМУ, а `--size-only` пропустит
  правку, не изменившую длину файла.
- **Сравнение, которое не совпадает НИ С ЧЕМ, выглядит как обычная работа.** →
  [история](статус/уроки-подробно.md)
- **Случайность при сборке — это расхождение копий и трата денег.** →
  [история](статус/уроки-подробно.md)
- **Добавляя `routes` воркеру, сначала посмотреть, кто ходит на его
  `workers.dev`-адрес** — деплой его молча отключает. Так чуть не умерла сверка
  названий с Hetzner; `publish-cron` и `baki-cms-auth` спасает явное
  `"workers_dev": true`. **Эта строчка два дня была неправдой наполовину:**
  у `baki-cms-auth` строки не было вовсе, хотя именно на его служебном адресе
  живёт вход в админку. Теперь она есть у обоих, а сторожит её проверка
  `scripts/workers-dev.test.mjs`, а не запись здесь: **запись про защиту
  и сама защита — разные вещи, и первая переживает вторую.**
- **Смена домена ломает не только ссылки.** У воркера входа в админку есть
  список `ALLOWED_DOMAINS`, и без него вход умирает. **С 20 августа 2026 он
  живёт в `cms-auth/wrangler.jsonc`, а не только в панели Cloudflare** — там
  же и `GITHUB_CLIENT_ID`. Правится в репозитории; выкладка ставит их сама.
- **Право нажатия у чужого API спрашивать у API, а не изобретать своё.** →
  [история](статус/уроки-подробно.md)
- **А КОГДА ЧУЖОГО API НЕ СТАЛО, СВОЁ ПРАВО ПРИДЁТСЯ ВСЁ-ТАКИ ЗАВЕСТИ — И ЭТО
  НЕ ОТМЕНА ПРАВИЛА, А СМЕНА ХОЗЯИНА.** Кнопки `/admin/tools/` не заводили
  паролей, потому что право проверял GitHub. Пометка «спам» выключила Actions,
  роботы уехали на свой сервер — а сервер про GitHub не знает и спросить его
  не может. Ключ запуска появился не от лени, и потому у него свои требования:
  слушать только `127.0.0.1` (наружу — через Caddy), сравнивать ключ за
  постоянное время, а запускать **только имена из списка внутри кода** —
  имя службы, взятое из запроса, отдаёт сервер первому любопытному.
  → [задача-21](статус/задача-21-роботы-на-hetzner.md)
- **ПРОВЕРКА СЕКРЕТОВ ПО ОБРАЗЦУ ЛОВИТ ИМЯ ПЕРЕМЕННОЙ ВМЕСТО ЗНАЧЕНИЯ —
  И СИГНАЛ ВСЁ РАВНО ОБЯЗАН ОСТАНОВИТЬ КОММИТ.** Поиск «похожего на ключ» указал
  на строку `line.startsWith('ROBOT_API_SECRET=')` в коде, который этот ключ
  ЧИТАЕТ. Тревога ложная, но разобрались уже ПОСЛЕ коммита, а надо было до.
  **Надёжная проверка — не образец, а сверка с настоящим значением**, взятым
  с сервера: `git grep -F "$KEY"` отвечает точно и не путает имя с содержимым.
- **Файл `_redirects` у Workers не умеет переезд между доменами** («Domain-level
  redirects ❌» в документации). Редирект www → голый домен делается правилом
  в панели Cloudflare, а не файлом в репозитории.
- **«Первый раз висит, второй работает» — это не код, а протокол, который
  сервер обещает, а брандмауэр режет.** → [история](статус/уроки-подробно.md)
- **`git pull` МОЖЕТ НЕ ПРОЙТИ, и тогда правило «pull → build → deploy»
  срабатывает вхолостую.** → [история](статус/уроки-подробно.md)
- **Папка, которую раздаёт веб-сервер, и папка, куда льют файлы по SFTP, —
  одна и та же папка.** → [история](статус/уроки-подробно.md)
- **«В журнале пусто» ничего не значит, если журнал не ведётся.** Caddy
  по умолчанию обращения не пишет вовсе, поэтому на вопрос «скачивал ли
  кто-нибудь этот файл» он отвечает тишиной, неотличимой от «никто».
  Тот же вид граблей, что `curl` без HTTP/3: прежде чем верить ответу,
  убедиться, что инструмент вообще умеет то, о чём его спрашивают.
- **ОЧЕРЕДЬ РАЗВОДИТ РОБОТОВ ВО ВРЕМЕНИ, НО НЕ ДАЁТ ИМ СВЕЖИХ ФАЙЛОВ.** →
  [история](статус/уроки-подробно.md)
- **Очередь у внешней службы подтверждается ТОЛЬКО ПОСЛЕ ЗАПИСИ.** Телеграм
  считает пост выданным в тот миг, когда робот его получил, а не когда файл лёг
  в репозиторий. Свались робот между этими мгновениями — служба считает пост
  доставленным, а на сайте его нет и не будет никогда, и узнать об этом
  неоткуда. Поэтому номер подтверждения хранится у НАС и двигается последним
  действием.
- **Отметок «докуда дошли» бывает две, и вторую забыть легче всего.** Мало
  не подтверждать очередь дальше недоделанного — надо ещё не двигать за него
  отметку «последнее виденное», по которой запасной путь решает, что основной
  что-то пропустил. Сдвинешь — заслон снят молча: очередь честно отдаст пост
  заново, а вот потерянный по сети не поймает уже никто. Спрашивать себя надо
  так: **какие ЕЩЁ счётчики перешагнут через недоделанное.**
- **Очередь непрочитанного у бота одна на всех, и выдаётся оно ровно один раз.**
  Заведи вторая программа привычку читать того же бота — и наш робот начнёт
  молча пропускать посты: не ошибка, не письмо, просто «ничего не найдено».
  А если у той программы постоянное соединение, наш запрос получит прямой отказ
  и не привезёт ничего вообще. **Своя задача — свой бот**, это бесплатно.
- **ВРЕМЯ ПУБЛИКАЦИИ — НЕ ВРЕМЯ ВЫДАЧИ, И «ПРОПУСТИЛ» ЧАЩЕ ЗНАЧИТ «ЕЩЁ
  НЕ ОТДАЛ».** → [история](статус/уроки-подробно.md)
- **ПИСЬМО, НАЗЫВАЮЩЕЕ ЗАКРЫТЫЙ СПИСОК ПРИЧИН, ОТПРАВЛЯЕТ ИСКАТЬ ПОЛОМКУ ТАМ,
  ГДЕ ЕЁ НЕТ.** Робот перечислял две причины пропуска, и обе были не наши:
  настоящей — «телеграм отдал с опозданием» — в списке не было вовсе. Список
  причин обязан кончаться либо той, что случается на самом деле, либо честным
  «бывает и иначе»; а причину, при которой делать ничего не надо, надо назвать
  первой и так и пометить — иначе спокойное письмо читается тревожным.
- **Сторожевые команды: `pgrep -f "[p]ipeline.py"`**, иначе проверка находит
  сама себя. И не путать «процесса нет» с «ssh не достучался» (код 255) —
  сверяться по `state.json` или по строке итога в логе.
- **Долгие прогоны — через `nohup`**, и включать построчный вывод
  (`line_buffering`), иначе лог многочасового прогона остаётся пустым.
- **Скрипт копировать на сервер вместе с зависимостями** (`pipeline.py` без
  папки `providers/` не запускается) — автосинхронизации нет.
- **macOS хранит «й» в именах файлов разложенной** — перед сравнением имён
  `unicodedata.normalize('NFC', …)`.
- **Сопоставления фиксировать файлом, а не считать на лету.** Переименованный
  сценарий молча увёл бы текст к другому выпуску (`essay-map.json`).
- **Роботу дают жильца под задачу, а не ключ хозяина.** →
  [история](статус/уроки-подробно.md)
- **Отпечаток чужого сервера записывать в самом роботе, а не добирать на месте.**
  `ssh-keyscan` при каждом запуске — это «здороваюсь с кем угодно, кто ответит
  по этому адресу»: подменённые данные уехали бы в репозиторий, и заметить это
  было бы некому. Открытый ключ сервера не секрет, его отдаёт сам сервер.
- **Робот, срабатывающий на каждое сохранение, обязан уметь выйти, ничего
  не спросив.** Подгрузка картинок будится КАЖДЫМ коммитом с постами; проверка
  «а помечен ли хоть один пост» стоит миллисекунды, а без неё робот ходил бы
  на сервер за восьмимегабайтным файлом по любому поводу. **И от собственного
  коммита его спасает не запрет, а идемпотентность:** он берётся только
  за помеченное, а последним действием метку снимает.
- **ПРИВЫЧНАЯ ФОРМА ШАГА `if node …; then commit; else fail; fi` ТЕРЯЕТ ВСЁ
  ДОБЫТОЕ У СКРИПТА, КОТОРЫЙ ПИШЕТ ПРИ СБОЕ.** Добор данных о роликах при
  обрыве сети записывает то, что успел узнать, и только потом отвечает
  единицей, — и записанное осталось бы незакоммиченным, а следующий заход
  счёл бы эти ролики разобранными (они же в файле) и в сеть за ними не пошёл бы
  никогда. У трёх соседних шагов того же робота эта форма верна: те скрипты
  при сбое не пишут ничего. **Разница не в стиле, а в поведении скрипта,
  и спрашивать о ней надо каждый раз заново.** Заслон —
  `scripts/video-meta-robot.test.mjs`, подлог возвращает привычную форму.
- **Письмо приходит, только когда НЕ вышло.** Удачную работу видно в админке,
  а письмо «всё хорошо» через неделю перестают читать — и вместе с ним
  перестают читать письма о том, что плохо.
- **Пометка «спам» на аккаунте GitHub гасит не аккаунт, а всё, что ему
  ПРИНАДЛЕЖИТ.** → [история](статус/уроки-подробно.md)
- **Статус блокировки GitHub НЕ ПОКАЗЫВАЕТ НИГДЕ — он виден только снаружи.**
  → [история](статус/уроки-подробно.md)
- **ПОМЕТКА «СПАМ» ГАСИТ И КЛЮЧ РЕПОЗИТОРИЯ (DEPLOY KEY), ПРИЧЁМ ПОСЛЕ
  УСПЕШНОГО ВХОДА.** GitHub принимает ключ (`verified: true`, право записи
  на месте), здоровается в ответ — `Hi eduard1414ed/Baka-page!` — и на любую
  работу отвечает `Repository not found`. С машины владельца в ту же минуту
  работают оба пути. То же, что с квотой API: механизм жив, доступа нет.
  Узкий доступ для сервера при висящей пометке недостижим в принципе —
  остаётся ключ аккаунта, и это решение заказчика, а не умолчание.
  → [задача-21](статус/задача-21-роботы-на-hetzner.md)
- **ПОМЕТКА «СПАМ» УРЕЗАЕТ КВОТУ API У НОВЫХ КЛЮЧЕЙ ДО АНОНИМНОЙ, А КЛЮЧ ПРИ
  ЭТОМ ИСПРАВЕН.** Личный ключ доступа мимо отключённого OAuth-приложения
  не спасает: и fine-grained, и классический получают `graphql: 0` — ни одного
  запроса, — тогда как старый ключ CLI работает на полные 5000. На `/user`
  ключ отвечает 200, поэтому отказ выглядит поломкой админки, а не квотой.
  Спрашивать `limit` у `/rate_limit`, **и обязательно снять эталон тем же
  запросом БЕЗ ключа**: урезанный ответ совпадает с анонимным поле в поле,
  и без эталона читается как «ключ не отправился».
  → [задача-20](статус/задача-20-флаг-github.md)

- **КОПИЯ ЧУЖОГО КОДА СТАРЕЕТ МОЛЧА, И ДЫРУ В НЕЙ ЧИНЯТ БЕЗ НАШЕГО ВЕДОМА.** →
  [история](статус/уроки-подробно.md)
- **НАСТРОЙКА, ЖИВУЩАЯ ТОЛЬКО В ПАНЕЛИ, — МИНА: ВЫКЛАДКА СТАВИТ ТО, ЧТО
  ЗАПИСАНО В КОНФИГЕ.** → [история](статус/уроки-подробно.md)
- **Заученный номер порта — мина, и занят он бывает не нами.** Страничка
  с кнопкой садилась на 4399; у заказчика он оказался занят чужим сервером,
  и 4400 с 4401 тоже — тремя питоновскими `http.server`, к проекту отношения
  не имеющими. Свой порт ищется обходом диапазона, а «свободен» значит
  «соединение отвергнуто», а не «ответил не так». **Чужой сервер, отвечающий
  не тем, — это занято.**
- **`.gitignore`, перечисляющий ИМЕНА, пропускает копию с другим именем.**
  Закрыты были `.env` и `.env.production`; резервная копия `.env.бэкап-…`
  под них не попала, и git предложил закоммитить её с настоящими ключами
  внутри. Копию делают руками и в спешке, и имя у неё всегда новое: закрывать
  надо образцом (`.env*`), а заслон проверять подлогом — создать файл
  и спросить `git status`.
- **Токен, выданный сервисом ПОВТОРНО, — тот же самый, а права у него уже
  другие.** Строка токена Яндекса не изменилась ни на знак после добавления
  права, и сравнение строк сказало бы «ничего не поменялось». Права
  проверяются ЗАПРОСОМ: до правки Вебмастер отвечал 403 «Required scope:
  COMMON», после — 200. Та же семья, что «сообщение „уже работает“ — не свой
  успех»: верить надо ответу на дело, а не признаку.
- **У сервиса спрашивают то, что он умеет, а не то, что кажется.** Google
  Analytics не показывает поисковых запросов ВООБЩЕ — ни одного, никогда,
  такова его конструкция. Запросы живут в Search Console и Яндекс.Вебмастере,
  и только там видны показы без нажатия. Метрика показывает лишь тех, кто
  дошёл до сайта: за месяц 56 заходов и десяток фраз против сотен показов
  у вебмастеров.
- **Свой счёт просмотров и встроенный счёт сервиса СКЛАДЫВАЮТСЯ.** У Google
  включено «отслеживание истории браузера», а наш код шлёт просмотр сам —
  и на сайте без перезагрузок каждый переход считается дважды: 3804 против
  2399 у Метрики за тот же период, +58,6 %. Ловится не рассуждением, а тем,
  что в его отчётах лежат адреса, которых наш код не отправлял (обрывки
  набора в строке поиска).
- **`gh` ОТДАЁТ КЛЮЧ ТОЛЬКО АКТИВНОМУ АККАУНТУ, И ВТОРОЙ ПРОЕКТ ГАСИТ ПЕРВЫЙ.**
  → [история](статус/уроки-подробно.md)
- **ПОРОГ, РАССЧИТАННЫЙ НА ОДНУ МАШИНУ, НА ДРУГОЙ НЕ СРАБАТЫВАЕТ НИКОГДА.**
  «Сказать вслух, если из индекса выпало 40 страниц» — разумное число для
  машины заказчика, где между сборками бывает две недели. На Hetzner сборка
  каждые десять минут, разница между соседними прогонами почти всегда нулевая,
  и сорока перемен там не наберётся: письмо не пришло бы ни разу, а выглядело
  бы это как «всё спокойно». Заводя порог на разницу с прошлым разом, спроси
  не «много ли это», а **«как часто здесь бывает прошлый раз»** — и на каждой
  машине по-своему.

## Куда что писать

- **`CLAUDE.md`** — выводы и правила: то, чему надо следовать всегда. Наступили
  на грабли — **правило сюда одной-двумя строками, историю в
  [уроки-подробно](статус/уроки-подробно.md)**, если она длиннее шести строк.
  Порядок уроков внутри раздела не менять: они ссылаются друг на друга
  («правило ниже», «те же грабли»), и перестановка эти ссылки порвёт.
- **`СТАТУС.md`** — только сводка: что готово по этапам, где что лежит, ключевые
  адреса, открытые хвосты и невылеченные болячки. Держать в районе 300 строк.
  **Это оглавление, а не справочник:** любой список, который растёт от сессии
  к сессии, переезжает в `статус/` отдельным файлом, а в сводке остаётся
  строчка-указатель.
  **И ЧИСЕЛ, КОТОРЫЕ ТЕКУТ, В СВОДКЕ БЫТЬ НЕ ДОЛЖНО.** Посты, тайтлы, файлы
  в сборке, вес `.git`, стоп-лист меняются от каждого сохранения в админке.
  Записанное число устаревает назавтра и начинает врать — в сводке стояло
  «63 опубликованных поста» при 190 настоящих и «`.git` 252 МБ» при 343.
  Число называется замером в ту минуту, когда оно кому-то понадобилось.
  **Исключение — замер-вывод:** тот, на котором стоит принятое решение
  и который от роста данных не меняется (74 % кавычек в постах против 30 %
  в речи). Такой остаётся, потому что без него решение читается произволом.
- **`статус/этап-N.md`** и **`статус/задача-N.md`** — подробности сессии:
  как устроено, что проверено и чем, какие решения приняты и почему. Растёт
  свободно, читается по ссылке из сводки. Новый файл — новая ссылка в сводке.
  **Это журнал, и он не сокращается никогда.**
- **`статус/архив-*.md`** — то, что отработало: закрытые хвосты, подтверждённые
  проверки, снимки цифр. **Из живых документов оно переезжает, а не удаляется.**
  Закрытый хвост уносит с собой свой номер: номера сквозные, перенумерации
  не бывает, на них ссылаются отчёты и старые задания.
- **Разъехавшийся факт чинится в обоих местах сразу.** Сводка живёт дольше
  подробностей и устаревает незаметно: строчка «шрифты лежат, но в CSS
  не подключены» пережила ту часть, где их подключили. Меняете поведение —
  ищите, где о нём написано, а не только где оно написано кодом.
- **УРОК, ОТМЕНЯЮЩИЙ ИНСТРУКЦИЮ, НЕ ОТМЕНЯЕТ ЕЁ — ОНА ПРОДОЛЖАЕТ ВЫПОЛНЯТЬСЯ.**
  11 августа в «Уроки» лёг урок «выкладок две, документы описывали одну»,
  а инструкция наверху этого же файла осталась прежней: «выкладка собирается
  из МЕСТНОЙ копии, коммит, пуш и `npx wrangler deploy`». Читается она первой
  и в каждой сессии, урок — на тысячу строк ниже и не всегда. Два дня файл
  сам себе противоречил, и заметил это разбор документации, а не работа.
  **Выведя урок, спроси: какую строчку в начале файла он только что сделал
  неправдой** — и почини её в ту же сессию. Это та же болезнь, что «правило
  выведено, но по всем местам не пройдено», только место тут одно и оно рядом.
- **ХВОСТ, КОТОРЫЙ ЖДЁТ ГЛАЗ, В СПИСКЕ ДЕЛ ЧИТАЕТСЯ НЕДОДЕЛКОЙ.** Из 76 номеров
  восемь были сделаны целиком и ждали одного — чтобы заказчик посмотрел. Лёжа
  вперемешку с настоящими недоделками, они раздували список втрое и заставляли
  перечитывать себя каждую сессию. **«Ждёт работы» и «ждёт проверки» — разные
  состояния**, и жить им надо в разных файлах: первым в хвостах, вторым
  в [что-смотреть](статус/что-смотреть.md).
- **УРОКИ НЕЛЬЗЯ РАСКЛАДЫВАТЬ ПО ОБЛАСТЯМ: ПРАВИЛО УНИВЕРСАЛЬНО, ЧАСТНА
  ИСТОРИЯ.** Замер 13 августа: классификатор по словам отнёс «пометка „меняете
  тут — поправьте и там“ не удерживает ничего» к вёрстке, «правило, снятое
  в одном месте, обязано быть снято во всех» к картинкам, «догадка не имеет
  права перебивать факт» к данным — и так больше половины. Слова в уроке
  из области, о которой он рассказан; само правило годится везде. Разложи
  по папкам — правила разъедутся по углам и перестанут попадаться на глаза.
  **Резать урок надо не по области, а по шву «правило / история».**
