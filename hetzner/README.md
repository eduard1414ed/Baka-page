# Роботы на Hetzner

Копия того, что реально работает на сервере `167.233.251.252`. Файлы здесь —
не заготовки: они скопированы с работающего сервера, и если он умрёт,
восстанавливать надо отсюда.

**Задача 21**, начата 25 августа 2026. Причина переезда — пометка «спам»
на аккаунте GitHub выключила Actions (см. `статус/задача-20-флаг-github.md`).

## Что уже переехало

| Робот | Было | Стало |
|---|---|---|
| Добор выпусков из RSS | `.github/workflows/sync-episodes.yml` | `baka-episodes.timer` на сервере |

Старый воркфлоу переименован в `sync-episodes.yml.disabled` — GitHub Actions
читает только `.yml` и `.yaml`, поэтому он не запустится, даже если Actions
внезапно оживут. Возврат — переименованием обратно.

## Где что лежит на сервере

```
/root/baka-site/                    клон репозитория (робот работает в нём)
/root/baka-robot/run-episodes.sh    сам робот
/root/baka-robot/notify.sh          отправка в телеграм
/root/baka-logs/                    журналы прогонов, старше 30 дней удаляются
/root/baka-secrets/telegram.env     токен бота и номер чата (права 600)
/root/baki-transcripts/.env         ключ ElevenLabs (права 600)
/etc/systemd/system/baka-episodes.service
/etc/systemd/system/baka-episodes.timer
```

⚠️ **Осторожно с именами:** папка расшифровок называется `baki-transcripts`
через «и», а всё, что заведено задачей 21, — `baka-*` через «а». На этом уже
споткнулись: путь к ключу в юните был написан через «а», файла по нему
не существовало, а `EnvironmentFile=-` (с минусом) означает «нет файла —
не падать». Расшифровка молча не работала бы.

## Секреты в репозиторий не попадают

Ни один ключ здесь не лежит и лежать не должен. Токены живут только на сервере,
файлами с правами 600, и подаются роботу переменными окружения.

## Частые команды

```
systemctl list-timers baka-episodes.timer     когда следующий заход
systemctl start baka-episodes.service         запустить прямо сейчас
systemctl status baka-episodes.service        чем кончился последний
journalctl -u baka-episodes.service -n 50     что писала система
ls -t /root/baka-logs/ | head                 свежие журналы прогонов
systemctl disable --now baka-episodes.timer   выключить робота совсем
```

## Правки

Скрипт правится **здесь**, потом копируется на сервер:

```
scp -i ~/.ssh/hetzner_baki hetzner/run-episodes.sh root@167.233.251.252:/root/baka-robot/
```

**Правя `run-deploy.sh`, прогоняйте `node scripts/deploy-race.test.mjs`
и его же с ключом `--подлог`.** Она вынимает из скрипта блок «нас обогнали»
и гоняет его в песочнице: он держит правило «не класть свою сборку поверх
более свежей выкладки», а само правило оплачено 25 августа 2026 — робот накрыл
свежий сайт сборкой, собранной шестью минутами раньше. В самого робота проверка
НЕ встроена нарочно: она заводит временные git-репозитории, и её поломка
в окружении сервера остановила бы выкладку сайта совсем.

**Правя `run-deploy.sh`, прогоняйте ещё и `node scripts/deploy-idle.test.mjs`
(и с ключом `--подлог`).** Она держит блок «нечего выкладывать»: робот собирает
сайт, только если в коммитах поменялось что-то, что попадает на страницы.
Оплачено 25 августа 2026 — сборка на 336 секунд ради закладки робота телеграма,
которую не читает ни одна страница. Список неэфирного там короткий нарочно:
ошибка в нём стоит невыложенной правки.

**Правя `run-telegram.sh`, прогоняйте `node scripts/telegram-notify.test.mjs`
(и с ключом `--подлог`).** Она держит два правила: письмо о новых постах уходит,
только когда посты есть (иначе приходит зелёное «забрано новых постов: 0»),
и замечания робота доезжают отдельным письмом, даже когда постов нет, — именно
так выглядит «бота выкинули из канала».

Юниты `systemd` после правки требуют `systemctl daemon-reload`.

**Имена переменных в скриптах — только латинские.** Русское имя bash не считает
именем: присваивание падает, а `$ИМЯ` в проверке разбирается как литерал
и никогда не пусто. Робот из-за этого рапортовал о поломке после успешного
захода — поймано на первом же прогоне.
